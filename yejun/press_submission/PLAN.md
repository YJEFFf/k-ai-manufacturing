# 프레스 제출 패키지 실행계획 — 확정 v1

확정일: 2026-09-24. 상태: **계획 확정, 구현 착수 가능**. 사용자의 최종 재검수 요청에 따라 Codex가 Claude 재검수까지 반영했다. 이후에는 아래 순서로 구현·실험·디버깅하며, 같은 계획을 반복 심사하는 단계를 추가하지 않는다.

이 파일이 실행 기준이다. [최초 계획](../analysis/press_plan_review/plan_snapshot.md), [Codex 검토](../analysis/press_plan_review/README.md), [Claude 재검수](../analysis/press_plan_review/claude_response.md)는 판단 이력을 보존한 자료다. 최초 계획의 예상 성능과 미정 사양은 이 문서로 대체한다.

## 현재 단계 제한 — 2026-09-25 사용자 지시

현재는 **구현·실험·디버깅·검수 단계**다. 예준이 결과에 만족할 때까지 보고서 이전 작업을 검수하며, **예준이 보고서 작성 시작을 명시적으로 지시하기 전에는 보고서 작업을 절대 진행하지 않는다.** 초안·장별 근거·제출용 서술·PDF·발표자료와 자동 생성도 포함한다. 이전의 단계 완료·테스트 통과·에이전트 판단은 작성 시작 허가가 아니다.

대회 보고서 초안과 자동 생성 코드는 삭제했다. 검수용 코드·CSV/JSON·분석용 표·그림·검수 기록은 보존한다. W12 보고서 근거 작성과 보고서 전달·최종 제출물 조립은 보류하며, 아래 구현·재현성 검사를 먼저 진행한다. 이 제한은 과거 계획·커밋의 다음 작업보다 우선한다.

## 1. 목적과 역할

공식 과제 ③은 프레스 유압펌프 이상 조기탐지·오경보 분석이다. 출제배경은 펌프 이상이 압력 불안정·가공품 불량·설비 비가동으로 이어지고, 주기점검과 작업자 경험에 의존하면 초기 이상을 놓치거나 정상 운전변화를 이상으로 오인할 수 있다는 문제다. 이 계획의 상위 목표는 **상부·하부 진동과 전류 시계열로 이상을 조기에 탐지하면서 오경보를 줄이고, 미탐지·오경보가 발생하는 조건을 밝혀 점검 판단에 연결하는 것**이다.

| 해결할 과제 | 실행 방법 | 확인할 결과·산출물 |
|---|---|---|
| ① 필요한 역할을 수행하는 AI 모델 개발 | 과거·현재 관측만 사용하는 진동·전류 특징으로 이상을 점수화한다. 단순 기준모델, IF·AE·LSTM과 결합 후보를 같은 조건에서 비교하고, 정상 자료로 경보 문턱을 보정한다. 경보 지속성·진폭 정규화 후보의 효과도 검증한다. | 저장 모델·추론 코드·예측 파일, 이상 탐지/미탐 수·정상 알림 수·첫 경보 지연·판정 가능 비율·F1. 탐지와 지연을 함께 보며 오경보 감소 효과를 판단한다. (§3~5.2, §6~7) |
| ② 미탐지·오경보 발생조건 분석 | 기록구간 내 위치·길이, 진동 수준, 전류 진폭·파형 특성, 경보를 낸 성분별로 성공·실패를 비교한다. 조건별 분모와 진동×파형 상호작용을 확인하고 대표 사례를 시각화한다. | 조건별 FN/FP 표·시계열 사례·모델의 취약 조건, 경보 사유와 확인 항목을 연결한 작업자 판단표. (§5.3, §6) |

발생조건 분석은 출제문이 요구한 **모델의 미탐지·오경보 조건**을 중심으로 한다. 실제 부하·운전상태·고장 원인 라벨이 없으므로 관측한 센서 조건과 진폭 대리 지표로 설명하며, 특정 부품의 물리적 고장 원인을 입증했다고 해석하지 않는다. 조기탐지는 기록 시작 후 첫 경보까지의 지연으로 평가하고, 고장 발생 전 선행시간과 구별한다.

오류 분석에서 드러난 조건은 §6의 지속성·진폭 정규화 후보와 점검 기준의 근거로 연결하고, 개선 효과와 탐지 손실을 함께 보고한다. 설계 변경은 §9의 변경 규칙에 따라 기록한다.

위 목표를 위한 주 모델 후보의 세부 연구 질문은 다음과 같다.

> 정상 학습·보정 절차에서 전류 파형을 추가하면, 진동 단독 대비 어떤 기록구간을 더 탐지하고 정상 알림 부담은 얼마나 달라지는가?

센서 크기와 전류 파형의 서로 다른 탐지 조건을 결합하는 것이 제안 메커니즘이다. 추가 탐지와 업무량의 관계를 가설로 검증하고, 오류가 집중되는 조건을 작업자 점검 판단에 연결한다. 성능 목표값을 이미 달성했다고 전제하지 않는다.

- 예준: `yejun/press_submission/`에 코드·분석용 표·그림·실행 결과를 만들고 검수한다.
- 준용의 보고서 PDF·발표자료 작성 연계는 예준의 명시적인 보고서 착수 지시 이후에 다룬다. 준용의 `claude/`는 읽기 전용으로 참조한다.
- 공식 평가: 진단 15, 모델 40, 영향요인·오류 15, 현장 활용 10, 창의성 10, 재현성 10에 근거를 대응한다. 모델은 베이스라인을 포함해 두 개 이상 비교한다.
- 제출 구성: 보고서 PDF, 코드 ZIP(환경·데이터·README·예측 파일), 발표 PPT와 PDF, 설문 완료 캡처. 구체적 형식은 로컬 공식 양식을 따른다.
- 검증 한계: 정상·이상이 각각 하루이고 상태·파일·날짜가 교락되어 있다. 모든 후속 결과는 이미 본 자료에 대한 탐색적 평가이며 독립 검증·고장 원인의 인과 증거·현장 오경보 보장을 주장하지 않는다.

## 4. 주 점수 변환과 보정

### 4.1 q95 초과분 지수 변환

각 성분별 유한한 정상 학습 점수 집합을 R, 크기를 n이라고 한다. 순수 파형 모델의 미판정 행은 R에 넣지 않는다.

```text
u = quantile(R, 0.95, method="linear")
E = {r-u : r in R, r>u}
beta = mean(E)
g_emp(s) = -log10((1 + count(R >= s)) / (n+1))
g(s) = g_emp(s)                         if s <= u
       g_emp(u) + (s-u)/(beta*ln(10))   if s > u
S_combined(t) = fmax(g_z(z(t)), g_s(sine(t)))
```

서로 다른 초과 점수에 대해서는 증가해야 하며, 같은 입력 점수의 동점은 정상이다. 이 변환은 점수의 척도를 정하는 휴리스틱이다. 확률값 또는 극단값 분포의 검증된 추정치라고 주장하지 않는다. [SciPy GPD 정의](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.genpareto.html)는 형상 0에서 지수분포가 됨을 명시한다.

- 빈 R, 빈 E, beta≤0, 비유한 beta는 해당 성분의 적합 불가 상태다. 임의의 작은 수를 넣어 경보를 증폭시키지 않는다.
- 사인 적합 불가 시 그 분할·변환의 주 모델은 `maxz_only_degenerate`로 명시하여 학습된 max-z 점수를 다시 보정한다. 두 성분 모두 적합 불가면 실행을 실패로 종료한다.
- 정상 학습에서만 n·u·beta·참조 점수를 정하고, 최종 보정 자료는 점수식이나 창을 선택하는 데 사용하지 않는다.
- 사인 점수의 이론적 범위는 [0,1]이다. `g_s(1)`과 최종 문턱을 비교해 파형만으로 경보 가능한지 기록한다. 불가능하다는 관측은 실패 조건 분석으로 남기며, 이상 데이터가 경보를 내도록 문턱을 자동으로 완화하지 않는다.
- 초기 ECDF 포화 방식과 최초 로그 확장식은 절제·이전 결과 대조용이다. 원래의 `21/21·정상 6/4/2`는 이번 지수 변환의 기대 정답이 아니다.

### 4.2 보정과 확률 용어

정상 보정 구간 j의 최대 점수를 M_j라 하고, `p(s)=(1+count(M_j>=s))/(n_cal+1)`로 계산한다. 전체 미판정 구간은 경보하지 않는 상태로 보정·평가 구간 분모에 포함한다. 한 구간의 어느 시점에서든 p≤α이면 첫 알림을 낸다. 구간 단위 보정과 행별 첫 알림이 일치하는지 검증한다.

- `p_value`: 정상 참조에 대한 이탈 p값.
- `anomaly_score=1−p_value`: 정렬용 점수. 고장 사후확률이나 개별 경보의 오경보 확률이라고 쓰지 않는다.
- 이론 경계: `alpha_grid=floor(alpha*(n_cal+1))/(n_cal+1)`. 교환가능한 보정·새 구간과 고정 점수 함수라는 가정 아래의 주변 경계로 표시한다. 동점이 있으면 더 보수적일 수 있다.
- n_cal=120, α=1/3/5%의 alpha_grid는 1/121, 3/121, 6/121이다. α<1/121이면 경보 불가능하다.
- 기존 cutoff는 그 정의와 경험적 보정 예산을 명시하고 conformal과 `criterion` 열로 구별한다. 양쪽 경보 집합의 동일성을 요구하지 않는다.
- 실제 시간 의존성·날짜 차이에 대한 일반화 보장은 없다. [Conformal 참고문헌 §3.2](https://arxiv.org/html/2107.07511v6#S3.SS2)의 주변 보장과 고정 보정셋에 조건부인 변동을 구분한다.

운영점 표는 `모델/분할/전처리/보정 단위/criterion/명목 α/alpha_grid/가정/정상 알림 k/n/독립 가정 단측 95% 상한/이상 탐지/coverage/조건부 지연`을 포함한다. 이항 상한의 n은 **정상 평가** 구간 수이며 보정 구간 수와 혼동하지 않는다.

## 5. 비교·민감도·오류 분석

### 5.1 모델 비교

같은 정상 분할·주 전처리·경보 보정에서 진동 2센서 max-z, 3센서 max-z, 5NN, RMS5, IF, MLP-AE(w=5), 사인 단독, 주 결합을 비교한다. 복잡한 모델도 학습·정상 학습 내부의 조기 종료만 사용한다.

LSTM은 세 결과를 구분한다.

1. 가이드북 프로토콜 재구현: raw→abs→MinMax, seq=20, 64-32-32-64, Adam 1e-3, epochs 최대 800, batch 128, 가이드의 학습률 감소·조기 종료, 마지막 시점 MSE, P=R 문턱. 100시점 라벨 이동과 끝 120행 제외, 검증셋 분리까지 기록한다. 이상 라벨이 문턱에 쓰이는 이 프로토콜은 주 비교와 다른 별도 재현 표다. PyTorch와 원 Keras의 차이는 명시한다.
2. 공통 평가 프로토콜의 LSTM20 단독: 구간 내부 창, 정상 학습 내부 조기 종료, 정상 보정만 사용, 전체 행 분모 유지.
3. 같은 LSTM20에 max-z 결합: 주 모델과 동일한 fmax 결합·꼬리 변환·보정 절차. max-z는 초기 행뿐 아니라 전 행에서 활성화한다. 따라서 준비 구간 정책과 크기 성분의 존재가 비교 가능하다. 창 길이 차이에 따른 지연·coverage는 계속 보고한다.

주 지표는 이상 탐지 구간 수, 정상 알림 수, 판정 가능한 구간·행 수, 첫 경보 지연이다. 혼동행렬·precision·recall·전체 행 F1·판정 가능 행 F1도 제출한다. 창 길이만으로 계산한 순수 창 모델의 판정 가능 행 상한은 w=5:517, w=8:463, w=10:428, w=20:276/600이며 이 원본 구조를 검증한다. 결측·상수 창·적합 불가로 실제 coverage가 더 낮아지면 사유별로 추가 보고한다. 전처리 변경으로 원본 행과 구간을 삭제하지 않는 한 길이에 따른 상한은 유지된다.

### 5.2 강건성과 절제

- raw/matched/coarse에서 학습·보정·평가 전체를 재실행한다. 창 민감도 후보를 생략하지 않는다.
- 양자화 효과는 참조 점수·u·beta·보정 최대/문턱·경보를 함께 기록한다. matched로 적합한 점수 함수·문턱을 동결하고 평가 변환만 바꾼 진단도 두어 입력 변화와 재적합 효과를 구분한다. 이 진단은 주 운영 파이프라인과 별도 조건으로 표시한다.
- 형식 규칙은 파일별 발화율, 두 방향의 구분 가능성, AUROC와 격자 간격·허용오차를 보고한다. 기존 05의 규칙은 간격 1.1920929, 무차원 격자 잔차 허용오차 1e-3이다. 더 엄격한 오차는 별도 민감도다. F1≤0.1을 형식 정보 제거의 단독 증거로 쓰지 않는다.
- 절제: 사인 제거, 크기 성분 제거, 초기 max-z 보완 제거, 지수 꼬리 제거, 구간/행 보정, 양자화. 해당 변경 외의 조건을 고정하고 결과를 매번 계산한다.
- 동일 예산에서 실현 업무량이 같다고 가정하지 않는다. 구간 탐지·부담·지연 곡선으로 비교하고 평가 F1 최대점을 주 모델로 몰래 교체하지 않는다.

### 5.3 진단·오류·불확실성

- 저장 자릿수·전류 격자·중복 타임스탬프·평균·구간 구조는 계산해 보고한다. ‘0.7ms 지터’와 확정적인 수집 경로·DC 오프셋 해석은 사용하지 않는다. 60Hz 앨리어싱은 가설이며 기록구간은 기동·스트로크가 아니다.
- N3 자기상관은 구간 경계를 가로지르지 않는 lag-1로 정의하고 코드화한다. 전체 시계열 연결 상관과 혼동하지 않는다.
- 조건별 FN/FP에는 해당 조건의 전체 행·구간 분모를 함께 표시한다: 위치, 길이, 진폭 대리 지표, 진동 크기, 발화 성분. 상호작용은 진동 수준×파형 특성의 2×2 표로 제시한다.
- 구간 전체 R²는 사후 진단이고 trailing R²는 경보 특징이다. 그림에 어느 값을 쓰는지 명시한다.
- 진폭은 평균 제거 RMS 및 사인 적합 진폭의 적용 조건을 표시한다. 길이 17 미만과 파형 적합이 나쁜 구간은 신뢰 제한으로 표시하며 주 성능 평가에서는 계속 분모에 포함한다.
- 정상 알림의 정확 이항 단측 95% 상한은 독립 가정의 참고치다. 0/n을 0% 확정으로 표현하지 않는다. 시간 민감도는 연속된 기록구간 5·10·20개 블록의 moving-block bootstrap으로 비교하되, 이 길이는 공학적 민감도 선택으로 공개한다. 퇴화 결과는 신뢰구간으로 과장하지 않는다.
- 두 분할을 합산해 표본 수를 늘리지 않으며 하루의 bootstrap을 날짜 간 일반화 구간으로 해석하지 않는다.

## 6. 현장 활용과 상태 규칙

업무량은 첫 알림 구간 수, 경보 run 수, 기록 관측시간 기준 알림률을 각각 제시한다. 기록시간은 각 관측의 0.1초 노출을 합산한 시간으로 정의하고, 첫 시각~마지막 시각의 경과시간도 별도 표기한다. 실제 가동시간과 하루 알림 수는 가정이 있는 시나리오로만 제시한다.

지속성 비교는 (k,n)={(1,1),(2,3),(3,3)}로 고정한다. 같은 구간의 최근 n개 유효 결합 점수가 있을 때 그중 k번째 큰 점수를 정책 점수로 삼고, 보정 구간에서 그 정책 점수의 최댓값을 다시 보정한다. 최초 n−1행·결측·경계에서는 창을 채우지 못한 상태로 표시한다. 각 정책은 자기 문턱·p값·지연을 가지며 미탐 분모를 유지한다. 구간마다 첫 알림 1회와 별도 run 집계를 사용한다.

진폭 정규화 개선 후보는 정상 학습의 trailing 17관측 진폭·진동 특징으로 정의하고, 학습 내부 시간 검증에서 설계한다. 사후 구간 전체 특징을 실시간 점수에 넣지 않는다. 결과가 좋다는 이유로 주 모델을 자동 교체하지 않고 개선 또는 부정 결과로 보고한다.

작업자 판단표는 경보 사유·점수·판정 가능 여부·진폭 신뢰 제한→확인 항목→조치 후보를 연결한다. 진동과 파형의 이상을 특정 부품 고장으로 확정하지 않는다. 실제 업무량 허용치가 없으므로 1·3·5%를 비교 가능한 선택지로 제공하며 단일 최적 현장 운영점이나 절감액을 만들지 않는다.

Python 3.12·CPU를 기준으로 실제 설치·실행한 의존성 조합을 `==`로 고정한다. 원안의 미검증 버전 목록을 그대로 고정하지 않는다. numpy/BLAS·torch·OS·시드를 manifest에 기록한다. 전체 실행시간과 메모리는 측정값으로 채운다.

- `run_all.py --root . --out outputs`: root 아래 데이터 위치를 해석하고 학습·보정·평가·그림·검사·manifest까지 실행한다. 캐시 사용과 전체 재학습 경로를 모두 제공한다.
- `predict.py --model artifacts/... --input new.csv --out predictions.csv`: 모델을 다시 고르거나 학습하지 않고 저장된 전처리·스케일러·창·변환·보정 상태를 불러와 추론한다. 저장 상태에는 protocol_version과 모델·분할·설정이 포함된다.
- 추론 결과: row_id, record_id, timestamp, is_scored/status, 각 성분 점수, combined_score, p_value, anomaly_score, criterion, budget, alarm, alarm_reason, model_id. source/정답은 평가용 메타데이터로 별도 결합한다.
- 원본·센서 원값·행별 예측·모델 바이너리는 Git에서 제외한다. 제출 ZIP에는 필요한 원본 자료와 예측 파일을 포함하며, 정상 학습/보정/평가와 이상 평가 자료의 역할을 명시한다.
- 캐시 키는 입력 해시·코드/프로토콜 버전·전처리·분할·모델 설정·시드·환경을 포함한다. 경로 이름이나 과거 산출물의 존재만으로 재사용하지 않는다.
- 복사한 코드의 출처 경로·커밋·해시와 변경점을 PROVENANCE에 기록한다. 공통 구간 함수 하나를 사용하고 vendor 내부의 별도 함수가 다른 경계를 적용하지 않는지 확인한다.
- `numbers.json`은 실행 결과만 읽어 생성하는 검수용 수치 집계다. 각 숫자에는 모델·분할·전처리·criterion·예산·단위·분모·실행 ID를 연결한다. 보고서 서술이나 장별 문서는 생성하지 않는다.
- 실행기와 검증기는 `validation.py`의 단계별 필수 검사·산출물 계약을 공유한다. 누락된 검사나 결과를 완료로 간주하지 않으며, manifest에 해당 실행 산출물의 해시를 기록한다. `verify.py --steps N`은 실행 범위 내의 명시적인 부분 비교다. 기대값 동결은 검증된 입력·필수 검사·파일 무결성을 먼저 확인한다. run_id에는 코드·설정·입력·환경을 반영한다. verify는 현재 패키지 코드 해시가 manifest와 같은지(실행 후 코드 변경), 주 모델 artifact가 실행 시 해시와 같은지도 대조한다.
- 공식 별도 테스트셋은 확보된 자료에서 확인되지 않았다. 자체 평가 예측 파일이라는 상태와 이상 자료 재사용을 명시한다. W13 문의 초안에 예측 형식·자체 평가셋·p값 출력의 적합성을 포함한다. 메일 발송은 예준의 별도 발송 지시가 있을 때 수행한다.

각 작업에서는 실행 결과와 오류 재현·검수 기록을 갱신한다. 보고서 문장·장별 근거 작성은 보류한다. 사용자·팀원에게 메시지를 보내는 것은 명시적인 발송 지시가 있을 때 수행하고, 일반 인수인계는 저장소 커밋을 사용한다.

## 9. 실행 검사와 변경 원칙

필수 정확성 검사:

1. 원본 해시·구간·분할·스케일러와 참조 자료의 범위·행/구간 분모.
2. 순위 p값과 n+1 보정, 동점·최소 p·비유한 점수·단위·경보 이유. 연속 iid 합성 MC는 새 보정셋과 새 평가점으로 반복해 구현을 확인한다.
3. 구간 경계를 유지하는 순서 변경, 전체 날짜 이동, 불필요한 열 제거에 대한 추론 불변. 미래 관측 추가·수정이 과거 예측을 바꾸지 않는지 확인한다.
4. 손실을 수반하는 재직렬화·재양자화는 변화량을 보고하는 스트레스 검사다. 모든 반올림에서 동일 경보를 강제해 통과시키지 않는다.
5. 저장 모델을 다시 불러온 추론과 원래 추론, 예측 파일에서 재집계한 알림·FN/FP와 분석용 집계표의 일치.
6. 임의 root/out, 캐시 무효화, 캐시 없는 재학습, 깨끗한 환경. 원본 해시 동일성과 부동소수 허용오차를 구분하고 경보 차이도 별도 확인한다. 다른 OS 검증은 추가 완성도 목표이며 실행하지 못하면 확인 범위를 그대로 적는다.
7. 제출물의 참가자 식별 정보와 메타데이터 점검은 보고서 착수 지시 이후의 제출 준비 단계에서 수행한다. 공식 양식이 허용하는 성명·팀명과 필요한 외부 출처 표기는 보존한다.

구현 오류는 발견한 위치에서 수정하고 관련 검사만 다시 실행한다. 성능이 낮다는 이유로 디버깅을 가장해 후보·전처리·보정 단위·예산·분모를 바꾸지 않는다. 의미 있는 방법 변경은 protocol_version·설정·커밋에 이유를 남기고 이전 결과와 비교하며, 추가 계획 재심사를 기본 절차로 만들지 않는다.

결합이 같은 부담 범위에서 추가 탐지를 제공하지 못하거나 수집 조건 변화에 불안정하면, 진동 중심 기준모델을 제출 주 모델로 선택하고 파형 성분은 보조 진단으로 낮출 수 있다. 선택 근거는 두 분할·전체 운영점의 관측 관계와 남은 한계로 설명한다. 실제 운영 비용을 모르면 임의의 비용 점수나 수상 확률로 순위를 만들지 않는다.

**즉시 다음 작업: W1·W6·W11 일부부터 구현한다.** 현재 확정은 실행 절차와 연구 질문에 대한 것이며, 새 지수 변환의 성능·현장 효과·수상을 확정한 것은 아니다.
