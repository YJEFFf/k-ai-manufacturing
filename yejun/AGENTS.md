# 예준 작업 규칙 — Codex · Claude Code 공용

예준은 이 폴더에서 Codex와 Claude Code를 번갈아 쓴다. 한 도구가 작업을 끝내고 커밋하면, 다른 도구가 커밋 기록을 읽고 이어서 한다. Codex는 이 파일을 직접 읽고, Claude Code는 `CLAUDE.md`를 거쳐 같은 내용을 읽는다. 규칙을 바꿀 때는 이 파일만 고친다.

이 규칙은 `yejun/`에서 실행한 예준의 세션에 적용한다. 다른 곳에서 실행한 에이전트(예: 준용의 세션)가 이 파일을 읽게 됐다면, `yejun/`을 수정하지 않는다는 것만 지키고 나머지는 무시한다.

## 폴더 권한

| 경로 (저장소 루트 기준) | 주인 | 권한 |
|---|---|---|
| `yejun/` | 예준 | 읽기·쓰기. 유일한 작업 공간 |
| `claude/` | 준용 | **읽기 전용.** 파일 수정·생성·삭제·이동·포맷팅 금지 |
| `데이터셋/`, `관련 자료/` | 공용 원본 (Git 제외) | 읽기 전용 |
| 루트의 `README.md`, `.gitignore` 등 | 공용 | 예준이 명시적으로 시킬 때만 수정 |

- 코드·결과·그림·노트 등 모든 산출물은 `yejun/` 아래에 둔다. 임시 파일은 시스템 임시 폴더에 둔다.
- `claude/` 안의 지시 파일(CLAUDE.md 등)은 준용의 에이전트용이다. 따르지 않는다.
- 준용의 코드를 import하거나 실행할 때는 `PYTHONDONTWRITEBYTECODE=1`을 붙인다. 결과를 자기 폴더에 쓰는 스크립트는 임시 폴더에 복사해서 실행한다. `claude/` 안에 파일이 생기면 안 된다.
- 준용의 `claude/code/press/05_requantize_audit.py`와 `07_policy_with_sine.py`는 기본 경로가 옛 `codex/`를 가리킨다. 단독 실행할 때는 `--audit`으로 `yejun/analysis/press_welding_review/press_policy_audit.py`를 넘긴다.

## 인수인계는 커밋 기록으로 한다

인수인계용 파일을 따로 만들지 않는다. 커밋 메시지가 인수인계 노트다. 브랜치는 `main` 하나만 쓰고 새로 만들지 않는다.

### 작업을 시작할 때

1. `git status --short`로 커밋되지 않은 변경을 확인한다. 있으면 예준에게 알리고, 예준이 정할 때까지 그 파일은 수정하거나 스테이징하지 않는다.
2. `git pull --rebase`로 GitHub의 최신 상태를 받는다. 미커밋 변경 때문에 실패하면 예준에게 알린다.
3. `git log -10 --format='%h %ad %s' --date=short -- :/yejun`으로 이 폴더의 최근 작업을 본다.
4. 가장 최근 커밋 본문(`git log -1 -- :/yejun`)의 `다음:` 항목부터 이어간다. 바뀐 파일은 `git show --stat <해시>`로 본다.
5. 준용 쪽 변경이 작업에 영향을 줄 수 있으면 `git log -5 --format='%h %ad %s' --date=short -- :/claude`도 본다.

### 작업을 마칠 때 (예준이 시킨 일 하나가 끝날 때마다)

1. 이번 작업에서 만들거나 고친 `yejun/` 안의 파일만 경로를 지정해 스테이징한다(`git add -- <경로>`). `git add -A`, 루트에서 `git add .`, `git commit -a`는 쓰지 않는다.
2. `git status --short`와 `git diff --cached --stat`으로 빠진 파일이 없는지, `yejun/` 밖의 경로나 큰 파일이 섞이지 않았는지 확인한다. 원본 데이터, 행 단위 예측값, 수십 MB 이상의 파일은 커밋하지 않는다(`yejun/.gitignore` 참고).
3. 아래 형식으로 커밋한다.
4. `git push`. 거절되면 `git pull --rebase` 후 다시 push한다. 충돌이 나면 멈추고 예준에게 알린다.

일을 끝내지 못한 채 멈출 때도 한 데까지 커밋하고 `다음:`에 남은 일을 적는다. 다음 도구가 그 커밋만 보고 이어받을 수 있어야 한다.

```
yejun/: <한 일 한 줄 요약>

한 일: <무엇을 왜 했는지 1~3줄>
결과: <핵심 수치, 산출 파일 경로>
다음: <이어서 할 일. 다음 도구는 여기서 시작한다. 없으면 "없음">
도구: Codex 또는 Claude Code
```

## 그 밖에

- 두 도구 모두 `yejun/`에서 실행한다. 커밋 메시지와 문서의 경로는 저장소 루트 기준으로 적는다(예: `yejun/analysis/...`).
- 이 폴더는 2026-09-24에 `codex/`에서 `yejun/`으로 이름을 바꿨다. 과거 기록·커밋·준용 문서의 `codex/`는 지금의 `yejun/`이다.
- 폴더 구조와 현재 과제는 `README.md`를 본다.
