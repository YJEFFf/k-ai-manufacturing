# 통합 계획의 검증 명세

2026-10-02 · [통합 계획](README.md) · **실행 전 계획값**

이 문서는 이후 구현자가 임의의 분할·단위·문턱을 추가하지 않도록 정한 명세다. 아래 숫자는 설계 선택이며 검증된 최적값·현장 허용치가 아니다. 현재 프레스 자료와 기존 파일럿을 본 뒤 만든 계획이므로 기존 자료에 대한 사전 맹검 연구로 부르지 않는다. 아직 읽지 않은 외부 시험 파일에 대해서만 이번 분할 예약과 향후 동결을 구분해 기록한다.

## 1 입력과 기록 단위

| 항목 | 결정 |
|---|---|
| 입력 원본 | 기존 `press_submission/press/data.py`의 SHA-256 두 개와 대조. 원본은 수정하지 않음 |
| 추론 입력 | TimeStamp와 세 센서. 라벨·파일 경로·날짜·행 번호는 특징에서 제외 |
| 라벨 | 평가/확률 보정용 테이블에 별도 보관. 파일별 보정·환산 선택에 사용 금지 |
| 중복 | 같은 시각·같은 세 센서값의 재전송은 첫 관측만 판정. 모든 원행 ID를 대응표로 보존 |
| 경계 | 재전송 처리 뒤 인접 시각 차가 80–120 ms 양 끝 포함 범위 밖이면 새 기록. 정수 나노초로 비교 |
| 시간 이상 | 역행·해석 불가 행은 표시하고 판정 불가. 정렬해서 정상 시계열처럼 만들지 않음 |
| 짧은 기록 | 제외하지 않음. 사용할 수 있는 크기 특징과 낮은 신뢰 표시로 처리 |
| 긴 공백 | 파형을 이어붙이지 않음. 공백을 정상 관측으로 채우지 않음 |
| 원본 대비 변경 | 중복 수, 제외/보류 수, 기록 수, 길이 분포, 원행 대응표를 생성 |

기존 동결 v2의 600개 정상 기록·A/B 분할은 그대로 재현한다. 새 규칙의 기록 번호로 과거 A/B 경계를 다시 해석하지 않는다. 공통 비교 기록 수는 입력 감사에서 확인하며, Claude의 599라는 숫자는 예측되는 참고값이지 수를 맞추기 위한 테스트 정답이 아니다.

원본 SHA-256:

- 정상 `f2d61cb3b3108f49a3305d2966b3a31f26942ac8af8ffc9eb531b432b945b0a7`
- 이상 `9fad8c238e63dba3257d8be32a32362548955c772171a95c0d2af61b0435ed2e`

## 2 관측 시각과 예측 가능 시각

**주 비교는 기록 종료 후 분류다.** 모든 모델에 같은 기록과 이용 가능한 관측 종료점을 준다. 기록 대표 시각은 마지막 행의 기록 시각이다. 물리 취득 시각이 확인됐다는 뜻은 아니다.

끝 표시가 없는 스트림에서는 마지막 행 뒤 0.5초 동안 새 행이 없음을 확인하는 가상 로거 규약을 둔다. 그 전에 경계 범위 밖의 다음 행이 도착하면 그 도착으로 이전 기록을 닫는다. 결정 가능 시각은 이 두 닫힘 사건 중 먼저 관측한 시각이며, 타임아웃만 있는 경우 `마지막 행 시각 + 0.5초`다. 장비의 실제 통신 지연이 아니라 계획상 재생 규약이며, 지연 표에 이를 명시한다. 파일 끝이라고 기다림을 없애지 않는다. 시각을 신뢰할 수 없는 기록은 표본·기록 순서 지연만 낸다.

평가 표는 다음처럼 분리한다.

| 표 | 입력·출력 시점 | 가능한 지표 |
|---|---|---|
| 공통 주 비교 | 완성된 기록, 닫힘 확인 뒤 판정 | 기록 F1·정상 요청 비율·조건별 FN/FP |
| 순차 보조 비교 | 매 행까지의 prefix만 사용 | 행 F1, 관측 후 첫 경보 표본 수·기록 시각 차이 |
| 가이드북 참고 | 실제 가이드북 창·분할·문턱의 정의 | 그 정의에 따른 F1, 학습 epoch·seed 함께 |

기록 끝의 판정을 앞선 행에 복사한 값은 `retrospective_record_label` 같은 사후 열로만 저장할 수 있다. 시점별 `pred_at_time` 또는 행 F1의 예측값으로 쓰지 않는다. 결측 예측·준비 구간·짧은 기록을 F1 분모에서 조용히 빼지 않는다.

## 3 분할과 선택에 쓰는 범위

### 프레스 순방향 평가

시간은 정상 파일 첫 기록 시각부터의 경과 분이다. 경계를 가로지르는 기록은 어느 쪽에도 나누어 넣지 않고 경계 제외표에 남긴다. 분할 사이에서 미래 상태·모델·보정 정보를 공유하지 않는다.

| 이름 | 정상 적합 | 정상 보정 | 정상 평가 | 역할 |
|---|---|---|---|---|
| P0 | 0–10분 | 10–20분 | 20–40분 | 이른 시기 기준의 변화, 개발 비교 |
| P1 | 0–20분 | 20–40분 | 40–60분 | 늦은 시기 변화, 개발 비교 |
| P2 | 0–40분 | 40–60분 | 60분–끝 | 낮은 수준·재가동 구간의 회고 감사 |

P0·P1의 개발 비교로 후보를 좁히고 P2를 한 번 정리한다. 전체 파일을 이미 보았으므로 P2도 독립 시험셋은 아니다. P2 결과를 보고 설정을 바꾸면 변경 전후를 남긴다. 세 평가 구간의 원기록이 중복되지 않는지 확인하며, 공유 학습·같은 날짜 때문에 독립 반복 실험으로 세지 않는다.

모든 후보의 실제 이상 21기록은 **동일한 비맹검 에피소드 확인**으로 별도 보고한다. 탐지기 적합과 정상 문턱에 이상 라벨을 쓰지 않는다. 라벨 확률 헤드 실험은 아래 8절의 별도 분할로 수행하며 그 전체 시스템을 정상 전용 모델이라고 부르지 않는다.

10분 구간·기록 길이 구간·전류 조건 구간별 오류를 공개한다. 과거 A/B, leave-one-block-out, 0–40/40–60/60–끝 파일럿의 결과는 출처와 전처리가 다른 참고 표로 둔다. 블록 제외 학습은 회고 분석이지 순방향 예측이 아니다.

### 새 외부 파일

SKAB의 파일 분할은 [예약 JSON](evidence/skab_split_reservation.json)을 따른다. 같은 CSV의 창·변형·정상 구간과 이상 구간을 서로 다른 split에 나누지 않는다. 한 장치에서 얻은 여러 파일이므로 파일 수를 다른 설비 수로 세지 않는다.

- fit: 정상 라벨 구간만으로 정상 모델 적합. anomaly-free 파일은 이 split에만 배정.
- dev: 후보·증강·정책 비교. 여기서 본 이상 유형과 결과를 기록.
- cal: 실제 정상만으로 최종 점수의 문턱을 정함. 후보 선택에 재사용하지 않음.
- test: 후보·설정·센서·라벨 해석을 동결한 뒤 평가. 실패해도 같은 파일에 맞춰 다시 고른 결과를 독립 검증으로 부르지 않음.

이용 조건·시간·라벨·회차를 먼저 감사한다. 시험 라벨은 평가 모듈에만 노출한다. 원본 설명의 valve 파일 번호와 실제 트리의 번호 차이가 있으므로 파일별 물리 원인은 자동 대응시키지 않는다.

## 4 특징과 조건화

### 기본 전처리

주 입력은 저장된 raw 수치다. 실제 단위 환산은 하지 않는다. 훈련 정상에서만 중앙값·MAD를 적합한다. MAD가 0인 특징은 정상 IQR로 대체하고 이것도 0이면 제외 사유를 기록한다. `log`의 바닥은 해당 훈련 특징 양수 중앙값의 `10^-6`이며 양수가 없으면 해당 특징은 사용 불가다.

양쪽 클래스에 똑같이 적용하는 기존 matched 정밀도(진동 `10^-4`, 전류 `1.1920929`)는 필수 민감도 표다. raw 결과와 matched 결과가 달라지면 약한 신호 손실과 형식 의존을 함께 검토한다. 정밀도를 맞췄다는 이유로 날짜·계측 경로 교란이 해결됐다고 하지 않는다.

진동의 기록 평균 차이도 통제한다. 기본 8설정 모두에 대해 **raw, matched, raw의 두 진동 채널 공통 평균 제거**의 세 입력 조건을 비교한다. 평균 제거는 라벨과 무관하게 `x_ac = x - mean(x_record)`를 적용하고, 특징·모델·보정은 각 조건의 fit/cal 자료로 다시 적합한다. 전류는 이 감사에서 변경하지 않는다. 이 세 조건을 교차 조합하거나 추가 최적화하지 않는다. 따라서 모델 설정은 8개, 기본 입력 감사는 24개 조합이다.

공통 평균 제거는 완결된 기록 평가에서만 전체 기록 평균을 쓸 수 있다. 인과적 행 평가에서는 미래 행 평균을 가져오지 않는다. 한 표본 기록은 평균 제거 후 진동 정보가 없으므로 전류만으로 가능한 판정과 판정 유보를 구분하고 전체 분모에 남긴다. 클래스별 감도 역산은 하지 않는다. raw에서만 얻는 이익이 평균 제거 뒤 사라지면 처리 경로 또는 DC 의존으로 표시하며, 고장 일반화의 증거로 채택하지 않는다. 감소·소실 신호의 실제 손실도 따로 공개한다. 원본 평균은 감사 자료로 보존한다.

### 공통 특징

| 특징 | 정의 | 최소 표본과 처리 |
|---|---|---|
| 진동 크기 | 각 진동 log RMS, log 최대 절댓값 | 1개 이상 |
| 전류 크기 | log RMS, 평균 제거 RMS | 분산·상수 예외 표시 |
| 전류 패턴 | 고정 `0.06 주기/표본`의 사인·코사인·절편 최소제곱, 진폭·R²·잔차 RMS | 20개 이상, rank 부족이면 사용 불가 |
| 진동 관계 | 같은 시각 두 진동의 Pearson 상관 | 20개 이상, 상수 채널이면 사용 불가 |
| 짧은 기록 경로 | 크기 특징만으로 전역 점수 | 주 비교의 모든 모델에 같은 허용 범위 |

`0.06`은 기존 관측에서 정한 탐색적 주파수다. 60 Hz라는 이름으로 학습하지 않는다. `0.04–0.08`의 주파수 탐색이나 특정 진동 톤을 추가하는 것은 기본 후보를 바꾸는 후속 실험이다. 실제 이상에서 보고 고른 대역을 미열람 고장 가정처럼 쓰지 않는다.

### 조건부 기준

- 전류 패턴 R² ≥ 0.95이고 진폭이 훈련 정상의 1–99백분위 안이면 조건화에 사용한다. 이 문턱은 기존 자료를 본 후 정한 설계값이다.
- 각 진동의 `log RMS = β0 + β1 log A [+ β2 (log A)^2]`를 정상으로 적합한다. 설명변수는 훈련 평균·표준편차로 표준화하고 ridge 계수 `10^-3`을 고정한다. 1차·2차만 비교한다.
- 잔차를 훈련 잔차의 중앙값·MAD로 표준화한다. 음의 방향을 포함한 절댓값 점수와 양의 부분 점수를 비교한다.
- 전류 부적합·범위 밖·짧은 기록이면 조건식을 외삽하지 않는다. 전역 진동 크기 점수로 돌아가고 `condition_unavailable`을 남긴다.
- 전류 원 크기와 파형 이탈은 별도 점수로 유지한다. 조건화 과정에서 전류 자체의 변화가 사라지지 않게 한다.
- 격자·소수 자릿수·파일 종류는 조건화 가능 여부를 결정하지 않는다. 품질 감사 표에만 남긴다.

점수 결합도 고정한다. `s_I`는 표준화 전류 log RMS의 절댓값과 표준화 파형 잔차 RMS의 양의 부분 중 큰 값이다. C1은 `max(|r0|, |r1|, s_I)`, C2는 `max(max(r0,0), max(r1,0), s_I)`다. 조건화가 불가능하면 두 모델 모두 `r0/r1` 대신 전역 진동 크기 이탈을 쓴다. 기본 조건부 모델에 전역 진동 점수를 무조건 다시 더해 조건화 효과를 상쇄하지 않는다. 크기 최댓값·관계 특징의 추가는 특징 제거 비교에서 따로 다룬다.

미관측 전류 조건은 펌프 부하 미상으로 해석할 수 있는 단서지만, 전동기 정지라고 자동 분류하지 않는다. 조건부 점수의 개선이 특정 전류 파형에만 의존하는지 전류 제거 비교로 확인한다.

## 5 비교 모델과 탐색 예산

| ID | 모델 | 고정 범위 |
|---|---|---|
| B1 | 전역 크기·파형의 표준화 이탈 최대 | 기본 특징, 한 설정 |
| B2 | 기존 v2 구조 공통 분할 재적합 | 원래 특징·AR(2)·결합을 보존. 공통 기록 끝의 최대 점수로 비교 |
| C1 | 조건부 진동 잔차 양측 + 전류 이탈의 최대 | 회귀 1차·2차 |
| C2 | 조건부 진동 잔차 증가 방향 + 전류 이탈의 최대 | 회귀 1차·2차. 감소·소실 시험 필수 |
| B3 | 공통 특징 kNN 거리 | k=5·10. 정규화·빠진 특징 처리는 동일 |
| O1 | 실제 정상과 합성 이상에 학습한 HistGradientBoostingClassifier | `max_depth=2`, `max_iter=100`, `learning_rate=0.05`, `l2_regularization=1`, `min_samples_leaf=10`, `early_stopping=False`. 튜닝은 후속 |

B2는 과거 동결 파일을 새 평가 구간에 그대로 쓰는 비교가 아니다. 각 fold 정상 적합으로 구조를 다시 맞춘다. 구현 동등성을 기존 A/B에서 확인하는 절차를 별도 둔다. 동결 v2 수치는 역사적 기준으로 유지한다.

B2의 공통 비교 어댑터도 실험 설정의 raw/matched/공통 평균 제거 전처리를 따른다. 원래 v2와의 완전 동등성은 원래 matched 조건에서 확인하고, 다른 입력의 적합판은 동일 구조의 새 변형으로 표기한다. 내부에서 재양자화해 공통 입력 조건이 달라지지 않는지 검사한다.

B3/O1의 정의되지 않는 파형·상관 특징은 훈련 중앙값으로 대체하되 결측·길이를 고장 특징으로 추가하지 않는다. 전처리 선택 자체가 효과인지 크기만 사용한 제거 비교를 남긴다. 증강을 붙이기 전 최소 후보는 총 8설정(B1 1, B2 1, C1 2, C2 2, B3 2)이다. O1은 이 비교 후에만 추가한다.

확률적인 연산의 seed는 `11, 29, 47`을 쓴다. 동일한 원기록과 난수를 후보 간 공유한다. seed는 독립 고장 사례가 아니며 모든 반복을 보고한다.

## 6 정상 보정과 시간 변화

고정 점수 `s`의 기본 순위는 다음과 같다.

`p_normal_tail = (1 + 보정 정상 점수 중 s 이상인 개수) / (n_cal + 1)`

기본 명목 α는 0.05, 민감도는 0.01이다. `n_cal < ceil(1/α)-1`이면 그 운영점은 지원 불가로 표시한다. 이 하한은 수학적 해상도 조건일 뿐 안정성의 충분조건은 아니다. 보정 표본이 작다고 합성 정상을 추가하지 않는다.

기본 점수는 센서군 성분을 결합한 뒤 한 번 보정한다. 상태별로 문턱을 나누지 않고 상태별 오류를 보고한다. 길이별 분포가 다른 경우도 결과에 드러내며 전역 α로 모든 하위 집단의 α를 보장한다고 하지 않는다.

드리프트는 다음 순서로 비교한다.

1. **고정 기준:** 갱신하지 않음. 기본 결과.
2. **느린 변화 점수:** 기록 요약 잔차에 EWMA, `λ=0.2`. 기록 대표 시각 간격이 30초를 넘으면 초기화. 보정 자료도 동일 순서·초기화로 재생하며 전체 경보 정책을 다시 평가.
3. **기준 갱신:** 확인된 정상에 대해서만 가능한 후속 비교. 현재 라벨을 즉시 아는 경우는 oracle 참조선이며 실제 운영 결과가 아니다. 가상 확인 지연 10기록을 명시하고 확인 전 자료는 갱신에 사용하지 않음.

단순히 점수가 낮다는 이유로 정상을 확정하지 않는다. 알려진 정상 피드백이 없으면 갱신을 끈다. EWMA 경보와 EWMA 기준 갱신은 다른 방법이며 동시에 바꿔 효과를 섞지 않는다. 양의 램프·음의 변화가 기준에 흡수되는지 함께 검사한다.

## 7 학습용 증강과 평가용 합성

### 학습 비교군

| 군 | 내용 | 주의점 |
|---|---|---|
| U0 | 실제 학습 자료만 | 필수 기준 |
| U1 | 같은 원기록의 반복 또는 가중치 | 학습 비중·반복량 효과의 대조 |
| U2 | 동일 기록 내부 crop, 동기화된 공통 위상 변형 | 접합 불연속·라벨 보존 검수. 각 채널 위상 독립 변경 금지 |
| U3 | 조건·길이가 비슷한 기록의 다변량 잔차 재표본화 | 세 채널 벡터를 함께 취급, 두 부모 모두 fit에 속함 |
| U4 | 실제 정상 + 개발 합성 이상으로 O1 학습 | 합성 라벨을 제공 라벨과 혼동하지 않음 |
| U5 | 정상 생성 모델 한 종류 | 독립 회차·U2/U3 효용이 확보된 후속 단계 |

U0–U3의 첫 고정 학습기는 B3의 k=5다. 기록 수가 늘어 kNN 밀도가 바뀌는 효과도 U1로 비교한다. 개선이 있으면 선정 후보 하나에만 추가 검증한다. U4는 B1/C 계열과 같은 기본 특징을 사용한다. O1 안에서는 실제 제공 라벨 모델·합성 노출 모델의 라벨 대상이 다름을 명시한다.

실제 기록 대비 증강 수 비율은 0.5·1.0, seed는 3개다. kNN에는 학습 step이 없으므로 원기록 수·복제 수·저장 비용을 맞춰 보고한다. GBM·신경망에는 반복 수·최적화 step을 고정한 대조를 둔다. 증강 후의 이익은 실제 평가에서 판단한다. 합성 시험에서만 좋아지면 학습 증강의 실제 효용은 미확인이다.

### 주입 계열과 크기

모든 크기는 fit 정상의 채널·조건별 RMS 또는 잔차 표준편차에 상대적으로 정의한다. 개발·보류 원기록과 seed를 분리한다. 아래 격자는 생리적·기계적 고장 크기가 아니라 신호 스트레스의 설계값이다.

| 용도 | 관측 변화 | 초기 격자 |
|---|---|---|
| 개발 A | 진동의 대역 제한 잡음 증가 | 추가 RMS / 정상 해당 대역 RMS = 0, 0.1, 0.25, 0.5, 1, 2 |
| 개발 B | 기록 내 감쇠 충격 | 진폭 / 정상 잔차 σ = 0, 0.5, 1, 2, 4, 8. 확률 1%·5% |
| 개발 C | 전류의 불규칙 잔차 추가 | 추가 RMS / 정상 전류 잔차 RMS = 0, 0.25, 0.5, 1, 2 |
| 보류 D | 정상 주성분과 다른 협대역 출현 | 0.10·0.25·0.40 주기/표본 중 정상 톤 ±0.02를 피한 값, 상대 RMS 0.1·0.25·0.5·1 |
| 보류 E | 진동 관계 변화 | 상대 위상 ±π/6·±π/3, 한 채널 변화와 동시 변화 분리 |
| 손실 시험 F | 진동 감소·전류 소실·평탄화 | 배율 0.75·0.5·0.25·0. 즉시 변화와 완만한 변화 분리 |
| 복합 시험 G | 진동 증가와 전류 조건화 불가의 동시 발생 | A 중간 두 크기 + 전류 평탄/파형 훼손 |
| 지속 시험 H | 진동 또는 전류 수준의 램프 | 관측된 시험 구간의 20·60기록에 걸쳐 0→상대 변화 0.25·0.5 |

광대역 주입의 대역은 fit 정상의 강한 선 주파수 주변을 피해 고정하며, 선택 과정·제외 폭을 저장한다. 파형 n이 짧아 주입 대역을 정의할 수 없으면 해당 형태의 시험 미지원으로 표시하고 분모를 함께 낸다. 시험 결과를 보고 주파수를 바꾸지 않는다.

위상·채널 관계 변화와 감소형 변화가 실제 고장인지 무해한 조건 변화인지 확인되지 않은 경우, 이를 실제 고장 재현율로 부르지 않는다. 목적은 탐지기의 사각지대와 확인 요청의 종류를 드러내는 것이다.

대조 스트레스는 수치 표기 변환, 알려진 단위 변환, 알 수 없는 gain/offset, 공백·중복·crop, 기준 변화, 공통 외란이다. 알려진 단위 변환만 역변환 후 점수 불변을 요구한다. gain·필터·시간왜곡에는 무조건 정상 라벨을 붙이지 않는다.

### 탐지 곡선

계열·상태·크기별 검출 비율과 미탐 수를 먼저 낸다. a50/a90은 격자가 해당 비율을 가로지르고 단조 추세가 타당할 때만 보조 적합한다. 격자 밖이면 범위 밖으로 표시하고 임의 경계값으로 우열을 정하지 않는다. 서로 다른 계열의 a50을 평균내지 않는다.

합성 반복은 부모 기록·원 블록으로 묶는다. 불확실성은 원 블록별 결과를 우선 제시하고 부모를 공유하는 seed를 독립 표본으로 세지 않는다. 합성 시작 이후 지연은 주입 정의에 따른 지연이며 실제 고장 선행시간이 아니다.

## 8 확률 출력

| 출력 | 대상 | 허용 해석 |
|---|---|---|
| `p_normal_tail` | 정상 보정 점수의 꼬리 순위 | 정상 기준에서 이례적인 정도 |
| `p_dataset_label` | 제공 라벨의 내부 분할 | 같은 자료 구성에 대한 라벨 확률 추정 |
| `p_synthetic_change` | 명시한 합성 혼합 | 설계한 합성 변화의 라벨 확률 |
| 현장 고장 확률 | 실제 독립 사건·유병률·새 조건 | 현재 검증 불가 |

제공 라벨 확률은 선정 점수의 단조 logistic 헤드로 별도 평가한다. 정규화 강도 C=1, 기울기 비음수, 기록당 동일 가중치를 사용한다. 기준 혼합비 q는 정상 0.9·이상 0.1로 고정하고 가중치를 그 비율에 맞춘다. `p_normal_tail`을 `1-p`로 바꾸어 대신하지 않는다.

이 진단의 정상 기록은 시간순 50% 점수 모델 적합 / 20% 헤드 적합 / 15% 정상 문턱 보정 / 15% 평가로 나눈다. 이상 기록은 시간순 앞 2/3 헤드 적합 / 뒤 1/3 평가로 나눈다. 완전한 기록만 배정하고 정확한 ID를 실행 전에 저장한다. 양성 한 에피소드 내부의 보간 검증이며 독립 고장 일반화는 아니다. 이 추가 실험의 결과를 앞의 정상 전용 탐지 비교와 혼합하지 않는다.

raw 점수와 보정 확률을 함께 저장하고, 확률에는 Brier·log loss와 분모·가중치·기준 혼합비를 병기한다. 적은 양성 기록에서 세밀한 reliability 곡선이나 등위회귀를 강제하지 않는다. 헤드가 완전 분리되거나 추정이 불안정하면 그 상태를 표시하고 현장 백분율을 출력하지 않는다. 예측 CSV가 단일 `p_anomaly` 열을 요구하면 `p_dataset_label`을 대응시키고 의미·q·분할을 같은 파일/명세에 기록한다.

합성 확률 헤드는 필요할 때만 별도로 적합한다. 실제 라벨과 합성 라벨을 한 진짜 고장 클래스로 합치지 않는다. 고장률과 지속시간만으로 현장 PPV를 만드는 수치 주장은 최소 구성에서 제외한다.

## 9 경보와 작업자 부담

모델 비교의 공통 정책은 **기록당 임계 초과 시 확인 요청 1회**다. 이유는 진동 변화·전류 변화·관계 변화·관측 부족으로 표시하며 고장 부위를 확정하지 않는다.

정책 비교는 선정 점수를 고정한 뒤 즉시 요청과 2-of-3을 비교한다. 2-of-3은 기록 순서에서 계산하고 대표 시각 간격 30초 초과 시 초기화한다. 확인 요청을 묶을 때도 원래 임계 초과 기록 수·누락 변화·추가 지연을 보존한다. 정상 두 기록 연속에서 해제하고, 공백 중 상태는 미관측으로 둔다. 3-of-5·10분 지속·3배 물리 한계는 기본 구성에 추가하지 않는다.

계측 점검·판정 유보 때문에 사람이 확인해야 하면 총 요청에 포함한다. 품질 플래그만 저장하고 아무 요청도 하지 않았다면 플래그 수는 별도 보고한다. 이상을 계측 확인으로 보냈을 때는 “이상 신호 확인”과 “기계 이상 탐지”를 별도 지표로 세며 기계 탐지 성공으로 바꾸지 않는다.

프레스 정지 지시나 특정 기계 위치로의 이동은 출력에 넣지 않는다. 조치는 사업장 절차와 정비 담당자의 판단을 연결하는 확인 항목 수준으로 둔다.

## 10 핵심 지표와 분모

| 지표 | 기본 정의 | 해석 제한 |
|---|---|---|
| 정상 요청 기록 비율 | 요청이 1회 이상인 정상 기록 / 모든 평가 정상 기록 | 품질·유보에 의한 요청 포함 |
| 정상 요청 건수 | 정책이 만든 요청 개시 총수 | 기계·전기·계측을 병기하고 합계도 제공 |
| 기록 F1·precision·recall | 완성된 공통 기록 판정 | 이상 21기록은 한 에피소드 |
| 행 F1 | 그 행까지의 정보로 나온 예측만 | 주 비교와 별도 표 |
| 조건별 오류 | 시기·길이·전류 조건·조건화 불가별 FP/FN | 작은 분모도 공개 |
| 합성 민감도 | 계열·크기·조건별 hit/miss | 실제 고장 일반화가 아님 |
| 변화점 지연 | 외부 라벨 시작 이후 첫 요청, 미탐 별도 | 자연 열화 선행시간이 아님 |
| 확률 지표 | 정의한 라벨·분할·가중치의 Brier/log loss | 현장 확률 검증이 아님 |
| 비용 | 학습·추론·메모리·추가 요청 수 | 측정 전에는 추정치 |

**시간당 지표:** 기본은 요청/100기록이다. 추가로 이 기록 정책을 저장된 시각에 재생했을 때의 달력 경과시간당 요청을 낼 수 있지만, 이는 간헐 관측 정책의 요청 빈도다. 공백을 포함한 77분을 연속 센서 감시로 취급하지 않는다. 기록 내부 노출시간 합계와 전체 경과시간을 따로 저장한다. 실제 취득 주기가 미상이라 물리 관측 노출시간을 확정하지 않는다.

상관된 같은 날짜 자료에 이항·Poisson 구간을 자동으로 “정확한 신뢰구간”이라 붙이지 않는다. 독립·동질 발생률을 가정한 참고 계산과 실제 블록별 결과를 구분한다. 무경보 시 `3/T`는 그 발생모형 아래의 근사일 뿐, 이 데이터로 교대당 위험을 실증한 값이 아니다.

## 11 최종 선택 규칙

선택 과정은 실험 전에 파일로 고정한다. 아래 순서는 이번 계획의 우선순위이며 특정 모델에 유리하게 사후 수정하지 않는다.

1. **필수 적격성:** 그룹 분리·미래 정보 차단·보정 분리·전체 분모·출처를 통과한다. 실패 모델은 순위에서 제외한다. 전체 실패면 재설계 필요다.
2. **공통 운영점:** α=0.05의 실제 정상 부담과 계열별 민감도를 비교한다. α=0.01은 해상도가 충분할 때만 보조다. 시험 라벨로 문턱을 맞춰 같은 FPR을 만들지 않는다.
3. **새 복잡성의 최소 이익:** 개발 P0/P1 합계에서 정상 요청이 단순 적격 기준 대비 최소 3기록 줄고 각 10분 구간 악화가 1기록 이내이거나, 정상 요청이 구간당 1기록 넘게 늘지 않으면서 두 개발 변화 계열의 사전 중간 크기 POD가 각각 10%p 이상 좋아져야 한다. 실제 정상 요청 자체가 적으면 감소율을 부풀려 통과시키지 않는다.
4. **탐지 손실 제한:** 개발 계열과 감소·소실·복합 시험의 사전 중간 두 크기에서 POD가 기준보다 5%p 넘게 낮아지면 개선 후보로 채택하지 않는다. 비교 가능 표본이 부족하면 판정 불가다.
5. **동점:** 더 적은 적합 파라미터, 더 적은 전제, 더 낮은 실행 비용 순이다. 단측이 자동으로 우선하거나 GBM이 자동으로 우선하지 않는다.
6. **선택 후 감사:** P2·실제 이상·보류 합성·외부 test의 결과는 채택 근거의 적용 범위를 결정한다. 실패하면 독립적으로 검증된 개선이라고 주장하지 않는다. 사후 수정은 새 버전으로 되돌리고 해당 시험셋을 개발 자료로 전환한다.

3·4번은 실용적인 실험 진행 기준이지 통계적 유의성 검정이나 안전 한계가 아니다. 중간 크기는 짝수 비영점 격자의 가운데 두 값, 홀수이면 중앙값과 바로 다음 값으로 고정한다. seed별 값과 부모 기록별 차이도 공개한다. 보류 계열은 3·4번의 튜닝에 사용하지 않는다.

아무 새로운 모델도 이 기준을 넘지 못하면 적격 기준선을 유지한다. 단순 기준선 자체의 탐지가 부족하면 “완성된 현장 모델”을 선언하지 않고 현재 한계와 필요한 자료를 남긴다.

## 12 SKAB 검증의 구체 범위

첫 센서 조합은 `Accelerometer1RMS`, `Accelerometer2RMS`, `Current`다. 이미 RMS인 센서를 프레스 원시 파형으로 취급하지 않는다. RMS·전류 수준의 조건부 관계를 재학습하고, 프레스의 0.06 사인 성분과 AR(2) 가중치를 그대로 옮기지 않는다. 순수 전이 성능이 아니라 방법의 재적합 검증이다.

외부의 조건 대리값은 과거 창의 `Current` 중앙값이다. 유한·양수이고 fit 정상의 1–99백분위 안인 경우 조건화하며, 프레스의 사인 R² 규칙은 적용하지 않는다. 범위 밖에서는 같은 전역 진동 기준으로 돌아간다. 이렇게 바뀐 특징 대응을 포함해 한 절차로 동결하므로 프레스에서 학습한 동일 모델을 그대로 이식했다고 하지 않는다.

기본 입력은 과거 20표본의 센서 수준 중앙값·산포다. 연속 시간축을 확인한 뒤 각 표본에서 판정한다. 초기 19표본은 준비 구간으로 표시하고 변화가 그 안에 시작되면 미탐/지연 분모에 포함한다. 보정은 cal 파일의 정상 구간에서 비중첩 20표본 블록 최대 점수를 사용한다. 시험에서도 같은 단위의 정상 요청과 전체 타임라인의 최초 경보를 구분한다.

동일 파일의 여러 정상 구간은 같은 회차다. 파일 시작부를 자동 정상으로 쓰지 않는다. dev/cal의 라벨 확인과 test 평가 라벨 접근을 분리한다. `changepoint`만으로 변화 방향을 정하지 않고 anomaly 0→1 전환과의 관계를 검수한다. 설명과 충돌하면 의미를 해결하기 전 지연을 계산하지 않는다.

외부에서는 B1·조건부 기본 모델·kNN과 선택된 증강 변형까지 최대 4개를 비교한다. 외부 자료에 맞는 특징 대응은 test를 열기 전에 동결한다. 파일별 요청·탐지·지연을 그대로 보고하고 valve/other 평균만으로 차이를 숨기지 않는다. 외부에서 이익이 없으면 프레스 관측 조건의 탐색 결과로 결론을 제한한다.

## 13 산출물 계약과 검수

향후 실행 시 필요한 파일은 원행↔기록 대응표, split manifest, 전처리/모델/문턱 설정, 학습 계보, 기록 예측, 인과적 행 예측, 모델 비교표, 합성 계열별 표, 출처 manifest다. 실제 학습에 사용한 입력과 계획 커밋의 해시를 연결한다. 모든 행의 상태를 기록하고 평가 대상과 비대상을 구분한다.

필수 검수는 입력 해시, 경계 양 끝·중복, 미래 행 변경 시 과거 예측 불변, 부모 기록의 split 중복 없음, 0강도 주입=원본, 보정셋 무증강, 짧은 기록 분모, 표와 예측 파일의 TP/FP/FN 일치다. 이는 이후 구현의 검수 명세다. 이번 계획 작업에서 테스트 코드나 모델을 만들거나 실행하지 않았다.
