# 통합 계획의 실행 순서와 완료 기준

2026-10-02 · [통합 계획](README.md) · **이후 실행 지시가 있을 때 사용할 작업 명세**

실행은 작은 범위를 전처리부터 결과표까지 완성한 뒤 넓힌다. 모델 이름·새 UI·대규모 데이터 확보가 첫 완료 조건이 아니다. 기존 패키지를 보존하면서 새 비교가 무엇을 바꾸었는지 추적한다.

## 1 결정 권한과 현재 정지점

- 이번 요청으로 승인된 범위는 계획 비교·통합·근거 확인·계획 문서 저장이다.
- 지금은 코드 구현·모델 학습·추가 원자료 취득·실험을 시작하지 않는다.
- 이후 실행 지시가 오면 이 명세의 첫 단계부터 진행한다. 이름·폴더명 같은 가역적인 선택을 다시 승인받을 필수 사항으로 만들지 않는다.
- 대회 보고서·발표자료는 별도의 작성 지시가 필요하다. 연구 결과표의 명세와 제출용 서술은 구분한다.

향후 구현 위치의 기본안은 `yejun/press_unified/`다. 이번에는 그 폴더나 실행 코드를 만들지 않았다. 원본·기존 모델·Claude 원안은 수정하지 않는 구조다.

## 2 단계별 완결 상태

| 단계 | 구체 작업 | 끝났다고 판단할 조건 | 실패하면 |
|---|---|---|---|
| 1 입력과 기준선 | 원본 해시, 중복·경계·시각 규약, 원행 대응, P0/P1/P2, B1, 지표와 예측 저장 | 한 명령으로 B1의 입력→판정→분모 일치 결과 생성 | 경계·분모를 해결하기 전 모델 확대 중단 |
| 2 주력 비교 | B2 구조 동등성, C1/C2, B3, raw/matched/공통 평균 제거, 짧은 기록·전류 부적합·특징 제거, 확률 헤드 진단 | 8모델 설정 × 3입력 조건의 같은 단위 비교와 탈락 이유, 임시 선정 후보 | 이익이 없으면 기준선 유지. 확률 불안정은 그대로 기록 |
| 3 증강과 사각지대 | U0–U3 고정 학습기 비교, 필요 시 U4, 개발/보류 주입, 복합·감소·지속 변화, 고정 대 EWMA | 실제 효용·합성 민감도·손실을 별도 표로 확인 | 실제 이익 없으면 증강을 학습에서 제외하고 시험 도구로만 유지 |
| 4 외부 검증 | SKAB 고정판 조건 확인, 예약 split, 시간·라벨 감사, 공통 절차 재적합, 선택 후 test 개방 | 파일별 성능과 적용 범위. 실패·불가도 완결 결과 | test에 맞춘 재선택 금지, 독립 검증 미완료로 표시 |
| 5 결과 고정 | 예측과 표 일치, 출처·설정·실패 사례 연결, 요청 정책 비교, 새 환경 재현 | 각 수치를 원본·설정·예측 파일에서 추적 가능 | 원인별 수정 후 영향받은 검수만 다시 수행 |

단계 2의 후보 선정은 개발 비교다. 단계 3의 손실 검사를 통과해야 새 모델 채택을 확정할 수 있다. 외부 결과가 실패하면 외부에서도 검증된 모델이라는 주장을 하지 않는다. 내부 탐색 결과를 보존하는 것과 현장 사용 적합 판정은 별개다.

각 단계 종료 때 결과를 커밋하고 비교 조건을 고정한다. 매 단계가 실행 가능한 상태여야 하며, 필요한 결과만 만들 수 있는 빠른 실행 경로를 둔다. 전체 실행 시간은 첫 측정 후 기록한다. 지금은 “CPU 10분/30분 내 완료” 같은 측정 전 약속을 완료 기준으로 삼지 않는다.

## 3 의존 관계

단계 1이 입력·분할·지표를 고정하면 모델과 외부 **메타데이터 감사**는 별도 진행할 수 있다. 증강 효과는 기준 모델을 고정한 다음 평가한다. 외부 시험 데이터는 선택과 특징 대응이 끝나기 전에 열지 않는다.

두 사람이 작업한다는 가정의 분담이다. 실제 이름·가용 시간은 확정되지 않았다.

| 담당 | 주 업무 | 상대 확인 |
|---|---|---|
| 팀원 1 | 기록·시각·기준선, 조건부 모델, 확률 출력 | 팀원 2가 분모·입력 시점을 검토 |
| 팀원 2 | 증강 계보·주입 명세, SKAB 검수·파일 분할, 조건별 오류 | 팀원 1이 독립 그룹·라벨 의미를 검토 |
| 공동 | 모델 선택, 실패 시 범위 조정, 출처·재현성 확인 | 같은 표와 설정 해시를 기준으로 결정 |

Codex와 Claude를 한 사람이 번갈아 사용할 때 두 사람의 병렬 가용 시간으로 계산하지 않는다. 도구가 바뀌어도 이 계획과 다음 구현 커밋의 설정을 읽고 이어간다. 새 하위 에이전트 사용을 이 문서가 자동 승인하지 않는다.

## 4 공수와 일정 시나리오

아래는 계획상 **집중 작업 인시**다. 계산 대기·접근 오류·새 환경 의존성 해결 시간이 늘 수 있고 실제 측정값이 아니다.

| 작업 묶음 | 예상 인시 |
|---|---:|
| 입력·출처·분할 감사 | 2–3 |
| 기준선부터 결과표까지 연결 | 4–6 |
| 주력 8설정·3입력 감사와 특징 제거 | 5–8 |
| 확률·분모·입력 시점 감사 | 3–5 |
| 증강·합성 사각지대 비교 | 6–10 |
| 외부 자료 한 종류 검수·검증 | 4–8 |
| 느린 변화·요청 정책 비교 | 3–5 |
| 재현성·출처·결과 고정 | 3–5 |
| **합계** | **30–50** |

대규모 생성기, 추가 신경망, 다른 외부 자료, 가이드북 원설정 전체 재학습은 이 합계에 포함하지 않는다. 필요한 경우 별도 선택 작업으로 공수를 다시 계산한다.

| 가용 상황 | 실행 범위와 판단 |
|---|---|
| 2인 각각 하루 6시간, 4일 | 48인시 가정. 전체 계획의 상단 추정에는 여유가 없으므로 메타데이터 감사와 모델 비교를 나누고 선택 작업을 추가하지 않음 |
| 1인 하루 6시간, 4일 | 24인시. 전체 완료를 약속하지 않음. 기준선·조건 모델·축소 증강·내부 검증을 우선 |
| 구현 가용 12–18인시 | 단계 1, B2와 C1/C2 중 기본 1차, U0/U1/U2 일부, 필수 손실 시험과 범위 명시. 외부 검증 미완료 상태로 마감 |
| 연구 기간 충분 | 1–5 전부 후 필요한 추가 질문만 확장. 새로운 후보를 무기한 추가하지 않음 |

2026-10-03에 구현을 시작하는 경우의 예시는 3일 입력·기준선, 4일 주력 비교, 5일 증강·외부 감사, 6일 외부 평가·결과 고정이다. 7–8일은 별도 지시가 있어야 하는 제출물 작업의 시간을 침범하지 않게 남긴다. 이는 착수 약속이나 현재 실행 지시가 아니다. 공식 제출 마감은 [KAMP 공지](https://www.kamp-ai.kr/noticeDetail?NOTICE_SEQ=86)의 10월 8일 23:59다.

## 5 범위를 줄이는 순서

먼저 줄일 항목은 다음 순서다.

1. 생성모델·사전학습 모델·다른 외부 데이터·운영 화면.
2. 기준선 갱신 실험, 특정 톤·스트로크 위상, 복잡한 순차 정책.
3. O1 합성 노출 GBM과 U3. U0·U1·가벼운 U2와 변화 손실 시험은 남긴다.
4. 조건 회귀 2차·k=10 설정. 단순 기준과 조건부 기본 설정은 남긴다.
5. 외부 검증은 명시적으로 미완료 처리한다. 이미 사용한 UCI나 합성 자료로 “새 독립 검증 완료”를 대체하지 않는다.

줄이면 안 되는 것은 입력/라벨 분리, 기록·미래 정보 검수, 실제 정상 보정, 짧은 기록의 분모, 무증강 대조, 감소·전류 부적합에서의 손실 확인, 확률의 의미, 출처·설정 추적이다. 오류를 숨기는 방식으로 모델의 완성도를 높이지 않는다.

## 6 단계별 필요한 결과 파일

아래는 실행 단계의 명세이며 현재 생성한 파일 목록이 아니다.

| 파일 종류 | 내용 |
|---|---|
| data manifest | 원본 URL·버전·해시·이용 조건·행 수 |
| row to record map | 원행 ID, 중복/제외 사유, 공통 기록 ID·대표 시각·판정 가능 시각 |
| split manifest | fit/dev/cal/test와 부모 기록·회차, 경계 제외 목록 |
| model protocol | 입력 특징·설정·보정·확률·정책·계획 버전 |
| augmentation lineage | 부모, 변환, 강도, seed, 합성 라벨, split |
| record predictions | 점수·정상 p·제공 라벨 확률·상태·이유·요청·정답·평가 여부 |
| row predictions | 해당 시점까지의 예측 여부. 사후 기록 판정 열과 명확히 구분 |
| comparison tables | 모델·조건·길이·계열·크기별 분모와 오류, 반복별 결과 |
| source and claim ledger | 주장마다 근거 파일/원문, 적용 범위, 미확인점 |
| run manifest | 코드·설정·입력 해시, 환경, seed, 실행시간, 실패 로그 |

공식 과제가 요구하는 이상 확률은 대상 라벨과 보정 구성을 설명할 수 있어야 한다. 확률 열이 있다는 것만으로 현장 고장 확률의 검증을 충족했다고 쓰지 않는다. 대회 제출에 필요한 파일 구성은 이후 제출물 작성 지시 때 최신 공지와 다시 대조한다.

## 7 현장 확인 항목의 우선순위

추가 자료를 받을 수 있다면 우선순위는 다음과 같다.

1. 원 취득·저장 주기, DAQ·센서 감도·단위·필터·TimeStamp 생성 방식. 정상과 이상 파일의 처리 절차.
2. 다른 날짜의 확인된 정상, 실제 운전/정지·금형 변경·생산 단계 기록.
3. 이상 발생·점검·부품 상태·교체 전후 이력. 하나의 파일을 독립 사건으로 잘못 쪼개지 않도록 사건 ID.
4. 압력·유온·유량·회전/전원 기준 중 현재 혼동 원인을 줄일 변수.
5. 요청 1건의 확인 시간, 미탐 비용, 실제 필요한 대응 시간.

이번에는 연락·인터뷰·자료 요청을 하지 않는다. 센서 추가나 설비 접근을 대회 기간 내 필수 의존성으로 넣지 않는다. 현장 확인 항목은 정비 지시서나 안전 절차가 아니며, 실제 조치는 사업장 절차와 책임자 판단을 따른다.

## 8 계획 완료 조건

현재 통합 계획은 아래 항목을 제공한다.

- 선택한 연구 질문과 선택을 뒤집을 반례.
- 양쪽 안의 채택·수정·보류 근거와 원본 링크.
- 기록·시간·확률·지표의 단위와 공통 분할.
- 비교 모델·설정 범위·증강·손실 시험·선택 규칙.
- 첫 외부 자료의 버전과 센서 원자료를 읽기 전 파일 분할 예약.
- 확인되지 않은 사실의 대체 경로, 단계별 완료 기준·공수·축소 순서.

모델 성능과 증강 효과는 이후 실행의 결과다. 실제 취득 사양이 밝혀지지 않은 것은 과학적 한계이며, 문서의 결정이 빠져 있는 것과 구분한다. 팀 피드백으로 변경할 수 있지만 현재 계획을 사용하기 위해 사용자가 모델 이름·폴더명·모든 파라미터를 다시 정할 필요는 없다.

현재 정지점은 **통합 계획과 비교 근거를 검토 가능한 형태로 저장하는 것**이다.
