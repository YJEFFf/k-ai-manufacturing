## 0. 운영 원칙

1. **세로 절편으로 짓는다** [C05 §0].
   - 각 절편은 `run_all --quick`이 통과하는 상태로 커밋한다.
   - 두 도구가 교대로 일해도 저장소는 언제나 한 명령으로 돈다.
2. **사전 등록 → 구현 → 선택 → 동결** [C05 §0].
   - `config/protocol.yaml`을 정의의 단일 출처로 둔다.
   - 확정 해시를 모든 산출물에 남긴다.
3. **결과를 보고 성공 기준을 바꾸지 않는다** [X README §8].
   - "개선 없음", "판단 불가", "위반(공개)"도 정식 결론이다.
   - 결과를 본 뒤 바꾼 것은 변경 이유와 전·후 결과를 함께 남긴다.
4. **새 폴더에서 시작한다.** 이름은 예준이 정하고, 제안은 `yejun/press_v3/`이다.
   - 기존 `press_guard`는 고치지 않는다.
   - 기존 패키지는 선택 참고 행으로만 실행한다(R2).
5. **샘플 단위와 마지막 행 실시각을 쓴다** [C05 §0].
   - 버스트는 한 번의 스냅샷(원자적 관측)으로 다룬다. 버스트 안 인과 처리나 0.1초 단위 지연 지표는 만들지 않는다 [J1].
   - S1k 해석에만 기대는 것은 조건부로 표시한다.
6. **재현되는 수치만 인용한다** [J2].
   - 설계를 바꾸는 수치는 스크립트나 계약 테스트로 재현될 때만 결과·문서에 쓴다.
   - [C01]의 "검토 재계산" 수치도 같다(R1 참고).
7. **통계는 블록 단위로 말한다** [J1]. 버스트는 서로 독립이 아니다(부하 보정 잔차 lag-1 자기상관 0.26). 유의성·제약·불확실성은 10분 블록 단위로 계산한다.
8. **실행 시간 예산** [C05 §0].
   - `--quick`은 CPU 10분 이내, 전체는 30분 이내로 잡는다.
   - 가이드북 LSTM-AE(B0, C-DL)와 MiniRocket은 캐시를 두고 별도 명령으로 돌린다.
9. **도전자는 시간 상자로 묶는다** [新].
   - C-REL·C-SLOW는 각 0.3, C-REP는 0.4, C-DL은 0.5 도구-일을 넘기면 멈춘다.
   - 그때까지의 결과는 "판단 불가"로 기록한다.

## 2. 절편

노력 단위 "도구-일"은 한 도구가 하루 동안 집중했을 때의 대략적인 양이다. 코덱스 실험 ID(E00–E11) [X03 §8]가 어느 절편에 들어가는지 함께 적는다.

공수는 v2(5–6 도구-일)보다 늘었다. 심사자 2가 v2의 R2(2–3 도구-일)를 낙관적이라고 봤고, 통합과 심사에서 필수 항목이 더해졌기 때문이다 [J2].
