## 1. 한 장 요약

### 1.1 데이터에서 새로 알게 된 것 (01 문서)

1. **탐지는 너무 쉽다.**
   - 한 줄 규칙(\|상부진동\| > 정상 최댓값)이 이상 21 버스트 중 18개를 잡는다.
   - 정상 운전 상태끼리도 분류기 AUC 0.967로 갈린다.
   - 그래서 **F1로는 모델의 우열을 가릴 수 없고**, "분리된다"는 고장 탐지의 증거가 아니다.
2. **두 파일은 처리 경로가 다르다.**
   - 이상 파일은 진동 소수 자릿수가 다르다. 전류는 600개 값 전부가 1.1920929(10⁷/2²³) 격자 위에 있다.
   - 같은 수행기관의 다른 KAMP 데이터셋(용접 예지보전)에도 같은 양상이 있다.
   - 레이블이 날짜·시간대·처리 경로와 완전히 겹친다.
3. **샘플링 주기가 가이드북("초당 10회")과 다를 가능성이 크다.** 세 가지 독립 근거가 "버스트 = 약 8초마다 찍은 50 ms짜리 1 kHz 스냅샷"을 지지한다.
   - 전류 = 정확히 60.0 Hz
   - 진동 톤 ÷ 전류 비가 부하에 따라 바뀌는 폭이 유도전동기 슬립 0.07 → 0.61 %와 맞음
   - 실시각 부하 주기 2.9초 = 1000톤 파인블랭킹 프레스의 실측 사이클
   - 분석은 샘플 단위로 설계해 어느 해석에서도 성립하게 한다.
4. **정상 전류는 깨끗한 60 Hz 파형이고 진폭이 펌프 부하다.**
   - 하부진동은 부하로 거의 결정된다(R² 0.924).
   - 정상 데이터 안에 운전 변화가 이미 있다: 가압·무부하 교대, 12분 장시간 대기, 재가동.
5. **이상 파일의 전류에는 60 Hz 성분이 거의 없다.** 그래서 전류 증거는 "전기 또는 계측" 이중 해석이다.
   - 고장 쪽 가장 강건한 증거는 **부하를 보수적으로 잡아도 남는 상부진동 초과(중앙 4.2배)**와 역위상 흔들림 모드다.
   - 이상 구간 부하가 정상보다 높았을 수 있다는 함정도 있다. 하부진동 증가는 이것으로 설명될 수 있다.
6. **양방향 탐지기는 "평소보다 조용한" 정상 상태에 운다.**
   - 장시간 대기에서 MCD·IForest가 17–18 % 경보했고, 단측 물리 규칙은 2.4 %였다.
   - 가이드북 LSTM-AE의 오경보는 대기 뒤 재가동 구간에 몰린다(7.6 %).

### 1.2 전략 — 네 기둥

1. **오경보 통제를 구조로 한다.**
   - 운전 상태 조건부 단측 건강지표
   - 상태별 conformal 보정
   - 지속성 규칙과 경보 예산(ARL₀)
   - 기계 채널과 전기·계측 채널 분리
   - 수집 건전성 층(계측 점검 알림은 숨기지 않음)
   - ISO 17359 §8.4가 요구하는 "고장 대 운전조건 변화 구별"을 구현한다.
2. **조기탐지를 증거로 만든다.**
   - 물리 동기 합성 고장의 계열별 검출한계(a50/a90, MIL-HDBK-1823A의 모델보조 POD 틀)
   - 램프 성장속도별 검출지연
   - 공개 리그(ZeMA, CC BY 4.0)로 크기를 앵커링한다.
   - 실제 이상 에피소드는 마지막에 한 번만 연다.
3. **정직한 검증을 차별점으로 삼는다.**
   - 사전등록과 선택 규칙 고정
   - 기준선 11종(가이드북 LSTM-AE 원본·교정판·미학습판 포함)
   - 교란 시험 15종: 형식 불변성, 음성 대조, 부하 매칭, 계측 스트레스, 블록 순위 검정
   - 식별 불가 쌍 선언과 주장 장부
4. **점수를 현장 의사결정으로 바꾼다.**
   - 정상 꼬리 p값 + 기저율 시나리오별 사후확률
   - 비용–손실 임계값
   - 3단계 경보 + 계측 점검 + 판정 보류
   - 물리 비교 문장("같은 부하 정상의 2.4배")과 점검 카드
   - 그림자 운전·처리 코드·as-found 기록
   - 센서·수집 로드맵(전압 기준 채널 포함)

## 3. 실행 순서 (05 문서)

- **Tier 1 (필수, 이것만으로 완결):**
  - WP0 사전등록 → WP1 데이터·상태 → WP2 지표·불변성 → WP3 주입 라이브러리
  - WP4 기준선(가이드북 재현 포함) → WP5 PHI-C → WP6 OE-GBM → WP7 MSPC
  - WP8 평가·선택 → WP9 오류·교란 분석 → WP10 현장 산출물 → WP11 재현성
  - 두 도구가 나눠 맡을 수 있게 병렬 경로와 결정 관문 G1–G4를 두었다.
- **Tier 2:** CUSUM ARL₀ 재보정, 램프 검출지연, 계열 맞바꾼 판, 베이즈 필터·Venn–Abers, 1D-CNN AE, 사람 참여 재보정, ZeMA 앵커 스크립트.
- **Tier 3:** 시계열 기초모델, NLN-EMP 수집 흉내, KAMP 자원최적화 정상 변동, 운영 화면 시안.

## 5. 코덱스 계획과 비교할 때 볼 점 (점검표)

1. **데이터 진단의 깊이.** 아래를 다뤘는가.
   - 형식·양자화 차이
   - 샘플링 주기 문제(10 Hz vs 1 kHz)
   - 부하 대리변수의 함정(이상 파일 전류 표준편차)
   - 정상 안의 운전 변화
   - 같은 수행기관 데이터셋의 선례
2. **교란 처리.** 실제 이상을 튜닝에서 완전히 뺐는가. 형식 불변성·음성 대조·계측 스트레스·블록 순위 검정 같은 반증 시험이 있는가.
3. **증강·합성 고장의 설계.**
   - 물리 근거와 출처가 계열마다 있는가
   - 개발·보류 계열 분리와 계열 맞바꾼 판이 있는가
   - 평균 POD를 쓰지 않는가
   - 실제 이상과 닮은 계열을 어떻게 다루는가
   - 정상 변화·계측 스트레스 계열이 있는가
4. **지표.** point-adjust·정확도·시험 기반 임계값을 피하는가. FA/h(Poisson CI), 첫 경보 시간, 계열별 a50/a90을 쓰는가. "검증 가능한 오경보 하한"을 밝히는가.
5. **확률의 의미.** P(고장)을 사전확률과 함께 정의하는가, 아니면 점수를 확률이라고 부르는가.
6. **모델 선정 규칙.** 실험 전에 고정되는가. F1 최대화인가, 제약 + 검출한계인가.
7. **현장 활용의 구체성.** 경보 정의표, 점검 카드, 비용 근거, 도입 절차, 법정 점검과의 관계.
8. **출처 관리.** 등급·확인 방식·라이선스·사용 위험이 출처마다 있는가. 금지 출처 목록이 있는가.
9. **실행 가능성.** 작업 묶음·완료 기준·결정 관문이 있는가. Tier 1만으로 완결되는가.

## 6. 한계와 열린 질문

- **설비 사실관계를 모른다.** 실제 샘플링·DAQ, 펌프 형식, 센서 단위·부착 위치(가이드북은 펌프 상·하단, KAMP 페이지는 모터 상하부), 7/17 에피소드의 실제 상황(고장 진행 단계, 시운전 여부)이 여기에 든다. 이 정보 없이는 H1–H3 가설을 가를 수 없다.
- **현장 오경보 목표(교대·주 단위)는 이 데이터로 실증할 수 없다.** 정상 1.28시간에서 0건이어도 95 % 상한이 2.3건/시간이다.
- **합성 고장 결과는 "설계한 계열에 대한" 검출한계일 뿐이다.** 인공 손상으로 학습한 모델이 실제 손상에서 약했다는 문헌이 있다.
- **리서치 한계.** 세션 웹 검색 한도(200회)가 조사 도중 소진됐다. 일부 출처는 서지·초록 수준으로만 확인됐다(02 문서 확인 열).

## 7. 리서치 방법

- 주제별 리서치 에이전트 9개를 병렬로 띄웠다.
  - R1 도메인 물리, R2 공개 데이터·라이선스, R3 이상탐지 방법·평가, R4 경보·확률보정·소표본
  - R5 합성 고장·증강·POD, R6 저샘플링 신호·표준, R7 국내·대회 자료, R8 설명·오류·교란, R9 현장 관행·아이디어
- 각 에이전트에게 출처마다 아래를 표시하게 했다(`sources/`).
  - 확인 방식(직접 열람 / 서지만 / 검색 요약 / 미확인)
  - 등급(A/B/C)
  - 라이선스와 공개 보고서 사용 위험
- 에이전트가 주장한 데이터 수치 중 계획에 쓴 것은 **모두 제 스크립트로 다시 계산해 확인**했다. 아래 등은 `eda/` 출력에 있다.
  - 형식 차이
  - 1 kHz 가설 근거 3종
  - 부하 매칭
  - 이상 파일 60 Hz 소멸
  - 역위상 진동
- 계획의 핵심 인용 일부(Cauchy 결합, 교차 conformal, jackknife+, scikit-learn 단조 제약)는 Crossref 메타데이터와 공식 문서로 직접 확인했다.
