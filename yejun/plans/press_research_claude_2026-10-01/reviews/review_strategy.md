## 3. P0 — 고치지 않으면 핵심이 무너지는 것

### P0-1. 실제 고장 에피소드가 "판정 보류 + 계측 점검"으로 빠지는 구조

**위치**
- 03 §1 L0: 60 Hz 소실·직류 계단 → 계측 점검
- 03 §2.1 L1: A60, I_T = √(A60² − I₀²), I₀ ≈ 121. 지지 범위 = 정상 [p0.5, p99.5]
- 03 §2.2: M1·M2는 I_T 조건부 잔차
- 03 §2.5 채널 규칙: 정지 검토는 기계 채널 증거가 있어야 함
- 03 §4 경보 표: 판정 보류 = 지지 범위 밖
- 04 §2.2: 지지 범위 밖 이상 버스트는 보류로 따로 셈
- 04 §5.6: 놓쳐도 선택은 뒤집지 않음

**무엇** (원본 재계산, 부록 A-1)
- 실제 이상의 10행 이상 버스트 17개는 A60이 3–101(중앙 42)이다.
  - **17/17이 정상 0–60분 A60의 p0.5(112.6) 아래**다.
  - I₀(121)보다 작으므로 **I_T는 17/17에서 정의되지 않는다.**
- L0의 "60 Hz 소실" 플래그도 사실상 전부 켜진다.
- 그러면 M1·M2(같은 부하 대비 진동 초과)를 계산할 수 없다.
- 경보 표를 그대로 적용하면 에피소드 전체가 "판정 보류 + 계측 점검"이 된다. 기계 경보(점검 권고·정지 검토)는 0건이 될 수 있다.
- 짧은 버스트 4개도 규칙상 보류다.
- 03 §4의 극단값 빠른 경로도 "**부하 보정** 진동이 정상 최대의 3배"라서 같은 문제에 걸린다.
- OE-GBM(D)은 학습 때 한 번도 보지 못한 결측(I_T 없음)을 받아 출력이 임의가 된다.
- 계획은 지지 범위 밖을 "최대 |I| > 271인 7/21"로 생각한 것 같다(01 §3, 04 §2.2, C7). 하지만 정의된 지지 변수(A60)로는 17/17이다.
  - 어느 부하 대리변수로 지지 범위를 판단하는지가 문서 사이에서 다르다.

**왜**
- 심사위원이 가장 먼저 확인하는 것은 "주최 측이 고장이라고 한 구간을 잡았는가"다.
- 이 구간을 "계측 점검/판정 보류"로 내면 다른 모든 장점이 무색해진다.
- 계획 안에서도 모순이다.
  - 01 §6 H1은 "레이블은 주최 측 정답으로 받아들인다"고 한다.
  - 01 §8 결론 4는 실제 에피소드를 "반드시 잡아야 하는 점검 항목"이라고 한다.
  - 그런데 04 §5.6은 "놓쳐도 뒤집지 않는다"고 한다.
- 04 §5.6 때문에 실제 이상을 연 뒤에는 고칠 수도 없다. 그래서 **지금(WP0) 고쳐야 한다.**

**수정안** (WP0에서, 실제 이상을 다시 보기 전에 `protocol.yaml`에 고정)
1. **부하 추정 위계를 둔다.**
   - 전류 SQI가 정상이면 A60·I_T를 쓴다.
   - 전류 채널 이상(60 Hz 소실·직류 계단)이면 **"부하 미상"**으로 둔다.
   - 부하 미상이면 정상 학습 전체의 **최대 포락선(가장 관대한 기준)**으로 진동 초과를 판정한다.
   - 원본 확인(A-3): 상부진동 RMS가 정상 0–40분 최댓값(0.148)을 넘는 이상 버스트는 **14/17**이다(1.5배 초과 13/17). 같은 규칙으로 정상 40–77분 오경보는 **0/251**이다. 실제 이상으로 튜닝하지 않고도 에피소드를 기계 경보로 잡는다.
2. **L0·계측 점검은 덮어쓰기가 아니라 병기 태그로 한다.** 예: "기계 경보 2단계 + 전류 채널 이상 동반 → 전기·계측 점검도 함께".
3. **판정 보류는 좁게 쓴다.**
   - 모르는 부하 값에 따라 판정이 바뀌는 경우에만 보류한다.
   - 재현율에서는 보류를 **미탐으로 세고** 따로 보고한다.
   - 정상 데이터 보류율 상한을 제약에 넣는다. 지금도 짧은 버스트만으로 정상의 11.5 %(69/599)가 보류다.
4. **복합 주입 계열 "진동 고장 + 전류 채널 이상"을 추가한다.**
   - 계열 F1(진동 광대역)과 I3(전류 60 Hz 제거·오프셋)을 함께 넣는다.
   - 이것을 개발 점검 항목(합격/불합격)으로 둔다. 실제 이상을 튜닝에 쓰지 않고도 같은 상황을 설계 요구로 시험할 수 있다.
   - EDA에서 착안했음을 F9와 같은 원칙으로 공개한다.
5. **극단값 빠른 경로도 부하 없이 정의한다.** 예: 최대 |AI0|가 정상 최대(0.352)의 3배 초과. 원본에서 이상 버스트 9/21이 해당한다.
6. **01 §8과 04 §5.6을 하나로 정리한다.**
   - 권고: 1–5로 설계를 고친다.
   - 그리고 "에피소드 단위 기계 경보 여부"를 사전 고정한 최소 합격 조건으로 둔다. 실제 이상을 버스트·임계값 튜닝에는 쓰지 않는다는 점을 공개한다.
   - 예준이 정할 사항으로 README §4에 넣는다.

### P0-2. 항목 2(40점)의 답, 곧 "이상 확률을 내는 최종 모델"이 한 줄로 서 있지 않다

**위치**
- README §1.3·§2
- 03 §3.2 D, §4 확률 행과 경보 표, §5 "예상 최종 구조"
- 04 §4.2 "대회 지표", §5, §8 예측 열

**무엇**
- **(a) 최종 모델 미정.**
  - "A + D 결합 + L5 + L0"라고만 적혀 있다.
  - 결합 방식이 없다. Cauchy 결합인지, D 점수의 상태별 conformal인지, 스태킹인지 모른다.
  - 04 §5 후보 목록에 A+D가 없다.
  - 기준선도 선택 대상인지 불분명하다. 한 줄 규칙(B-one)이 선택되면 "AI 예측모델 개발"의 답이 "규칙"이 된다.
- **(b) 확률이 세 갈래로 흩어졌다.**
  - conformal p값(스스로 "P(고장) 아님"이라고 명시)
  - 기저율 시나리오 사후확률
  - Tier 2의 Venn–Abers·HMM
  - 예측 파일(04 §8)에는 **단일 확률 열과 이진 판정 열이 없다.**
- **(c) 표기 오류와 값 문제.**
  - 03 §4의 "P(고장|x) = POD·π / (POD·π + PFA·(1−π))"는 임계값 규칙의 **P(고장|경보)**(양성 예측도)다.
  - 값(A-5)
    - PFA 1 %, π 10⁻⁴이면 **0.0099**다.
    - 2-of-3 지속(독립 가정 PFA ≈ 3×10⁻⁴)이어도 π 10⁻⁴에서 0.25, π 10⁻³에서 0.77이다.
    - 실제 고장 버스트에도 "이상 확률 1 %" 같은 숫자가 나간다.
  - 3단계 조건 "사후확률 > 0.95가 3 버스트 지속"은 Tier 1(단일 버스트 사후확률)에서 사실상 도달할 수 없다.
    - 그래서 3단계는 물리 한계 경로에만 기대는데, 그 경로가 P0-1 때문에 정의되지 않았다.
  - π "버스트당"이 고장 발생 위험률(hazard)인지 고장 상태 유병률인지 정의가 없다.
- **(d) F1 처리.**
  - 양식 제2장 작성요령은 "베이스라인 포함 2개 이상 모델을 비교하고, **동일한 평가조건에서 어떤 차이가 나타났는지**와 최종모델 선택 이유를 제시"다.
  - 계획은 F1을 "선택 근거 아님" 주석을 단 보조 지표로 둔다.
  - 원본 확인(A-2): 한 줄 규칙의 임계를 정상 0–40분 최댓값(0.352)으로 두고 버스트 판정을 행에 펼친다. 그러면 가이드북 분할 구간에서 **TP 199, FP 0, F1 1.000**이다.
    - 행 단위 근사다. 가이드북은 창 단위(창 20, "+100" 라벨)다.
    - 공식 베이스라인은 0.7476, 파일럿 재현은 0.646이다.
  - 이 사실이 F1 이야기의 가장 강한 출발점인데 계획에 이 수치가 없다.

**왜**
- 위원은 한 화면에서 세 가지를 찾는다. 어떤 모델이 이상 확률을 내는가, 무엇과 비교해 얼마나 나은가, 왜 골랐는가.
- 지금 안은 이 질문에 주로 "검증 장치"로 답한다. "검증은 많고 모델은 안 보인다"는 인상을 줄 위험이 크다.
- 확률 표기 오류는 통계 전공 위원이 바로 잡는다.

**수정안**
1. **최종 모델을 지금 정의하고 이름을 붙인다.**
   - 선택 규칙은 두 가지 역할을 한다. 제안 모델이 비교군보다 나은지 확인하고, 변형·설정을 고른다.
   - 틀 예시(어느 후보가 이기든 같은 틀로 쓴다):

   > **부하 보정 물리지표 이상확률 모델(가칭)**
   > 1. 운전 상태: 전류 60 Hz 진폭으로 펌프 부하를 추정한다. 전류 채널 이상이면 "부하 미상"으로 보고, 정상 최대부하 기준으로 보수 판정한다.
   > 2. 물리 건강지표: 같은 부하의 정상 대비 상·하부 진동 초과, 저주파 흔들림·역위상, 충격성, 펌핑 톤, 전류 파형 왜곡.
   > 3. 이상 확률: 정상 데이터에 물리 근거 고장 신호를 주입해 학습한 그래디언트 부스팅(물리 방향 단조 제약) → 보정된 `p_anomaly`.
   >    - 선택 결과가 A면 "A의 p값 → 공통 확률 헤드"로 바꾼다.
   > 4. 상태별 보정: 운전 상태마다 정상 오경보율을 설계값(버스트당 1 %)에 맞춘다(conformal).
   > 5. 경보: 3단계 + 계측 점검 병기 + 이유 코드 → 점검 카드.
   > - 선정 근거(한 줄): 같은 오경보 예산에서, 학습에 안 쓴 고장 종류까지 더 작은 크기에서 잡는다. 정상 운전 변화·센서 이상에 강건하다. 경보 이유가 물리량으로 나온다.

2. **선택 자격을 좁힌다.**
   - 자격 후보는 {A, D, A+D}다. A+D는 결합식을 정의한 뒤에 넣는다. 권고는 "D 점수를 A와 같은 상태별 conformal로 보정하고, 이유 코드는 A 지표에서" 가져오는 단일 파이프라인이다.
   - 기준선·비교군은 참고 행이다. 기준선이 더 좋으면 그 사실을 그대로 공개한다.
3. **모든 후보에 공통 확률 헤드를 붙인다.**
   - 점수 → 보정 → `p_anomaly`다. 보정은 개발 계열 혼합의 보류 버스트에서 isotonic으로 하고, 기준 유병률 q를 명시한다.
   - 비교 지표
     - Brier·로그손실(보류 계열 혼합)
     - 운영 임계에서의 F1 점수
   - 기저율 환산은 항목 4용 "경보 단계별 적중 확률(자연빈도)"로 옮긴다. 표기는 P(고장|경보)로 고친다.
   - π를 "고장 상태 유병률"로 정의하고 근거(P–F 기간 × 고장률)를 적는다.
4. **3단계에서 사후확률 조건을 정리한다.**
   - Tier 1에서는 사후확률 조건을 뺀다.
   - 넣고 싶으면 버스트 간 누적(간단한 2상태 전진 재귀, Tier 2의 G 축소판, 노력 S)으로 바꾼다.
5. **주 비교표를 하나로 만든다.** 6행 × 같은 평가조건이다.
   - 행: 공식 LSTM-AE(B0), 한 줄 규칙, IF(또는 kNN), 상태별 PCA, A, D(또는 최종).
   - 열
     - ① 공식 분할 행 단위 F1/정밀도/재현율
     - ② 실제 에피소드 탐지·첫 경보(버스트 수)
     - ③ 상태 보류(장시간 대기·재가동) FPR·FA/h
     - ④ 정상 변화·계측 스트레스 FPR
     - ⑤ 개발 계열 a50
     - ⑥ 보류 계열 POD(고정 크기) 또는 합성 혼합 F1 점수
     - ⑦ Brier
   - 표 머리 문장: "실제 고장은 단순 규칙도 모두 잡는다(①②). 모델의 차이는 ③–⑦에서 난다."
   - 이렇게 하면 F1을 버린 것이 아니다. F1이 포화했음을 보여 주고, 그래서 평가조건을 넓혔다는 근거가 된다.
6. **지도학습 대조(H)를 표 아래 한 줄로 둔다.** "실제 레이블로 학습한 모델은 ①②에서 만점이지만 ⑤⑥에서 무너진다." 위원이 직관적으로 이해하는 "왜 지도학습이 아닌가"의 답이다.

### P0-3. Tier 1이 두 도구의 교대 운용에 비해 너무 크고, 통합이 맨 끝에 있다

**위치:** 05 §2(WP0–WP11, 순서와 병렬화, 결정 관문), README §3.

**무엇**

- 05의 병렬 경로는 "두 도구가 동시에" 일한다는 전제다.
  - 실제 운용은 커밋으로 넘기는 **교대**다. 병렬 이득이 0이고 임계 경로가 전체 합이다.

**왜**
- 가장 흔한 실패는 미완성이다.
- 항목 6(재현, 10점)과 항목 2의 선정 근거가 끝에 몰려 있어 함께 무너진다.

**수정안**
- **세로 절편(R1 얇게 끝까지 → R2 넓히기 → R3 마감)으로 재배열한다.**
  - 각 절편은 `run_all --quick`이 통과하는 상태로 커밋한다.
  - 세션이 끊겨도 저장소가 항상 실행 가능하다.
- 6.4절 순서로 자른다.
- 상세는 6절.

## 4. P1 — 점수나 실행에 큰 영향

### P1-1. "조기탐지"의 직접 증거가 Tier 2로 밀려 있다

- **위치**
  - 05 §3 T2-1(CUSUM), T2-2(램프 지연)
  - 04 §3.1 계열 F10, §5(선택에 지연 미사용), §4.1(첫 경보 시간)
- **무엇**
  - 과제 제목이 "이상 **조기**탐지"다. 그런데 Tier 1에서 "조기"의 근거는 a50(더 작은 고장)이라는 간접 증거뿐이다.
  - 실제 에피소드에서는 한 줄 규칙이 이상 파일 둘째 행에서 울린다(01 §6).
    - 2-of-3 지속을 쓰는 최종 모델은 첫 경보가 약 1 버스트(약 8초) **늦을** 수 있다.
  - 04 §3.1은 개발 계열에 "그 램프"를 넣는다. 하지만 선택 규칙은 지연을 쓰지 않고, 램프 평가는 Tier 2다. 서로 맞지 않는다.

- **수정**
  - Tier 1에 최소 램프 실험을 넣는다.
    - 계열 F1 하나, 기간 2개(예: 30·120분)
    - 정상 블록 부트스트랩 스트림 1–2시간
    - 비교 3개: 한 줄 규칙·IF·최종
    - 지표: 첫 경보 시점의 고장 크기, 단순 임계 대비 선행시간, 경보 전 오경보 수
  - CUSUM 재설계는 Tier 2에 둔다.
  - 실제 에피소드 첫 경보는 "단순 규칙과 동률(1–2 버스트)"이라고 정직하게 쓴다. 극단값 빠른 경로가 첫 버스트에서 울리는지 확인한다.

### P1-2. 창의성(항목 5)이 결과와 연결되어 있지 않다

- **위치:** 03 §5 루브릭 5, 03 §7, README §2
- **무엇**
  - 공식 양식 제5장 작성요령은 이렇다. "단순히 새로운 알고리즘을 사용했다는 설명보다, 제안한 방법이 성능·오류 감소·현장 활용에 어떤 기여를 했는지를 제2장과 제3장의 결과에 연결".
  - 계획에는 구성요소별 기여를 재는 표가 없다.
  - 차별점 8개 중 세 개는 방법이 아니라 진단(항목 1)이다. 1번 S1k, 4번 부하 대리변수 함정, 8번 출처 진단이 그렇다.
  - "앙상블: Cauchy 결합"은 앙상블로 보기 어렵다.
- **수정: ablation 사다리 표 하나.** 같은 분할, 같은 경보 예산에서 한 단계씩 더한다.
  - 단계
    1. 한 줄 규칙
    2. 다변량 양측(IF·MCD)
    3. 단측 규칙
    4. 부하 정규화
    5. 상태별 conformal
    6. 지속성
    7. 합성 노출 GBM(단조 제약)
  - 열
    - 장시간 대기·재가동 FPR(실데이터)
    - N2·N3·I2 스트레스 FPR
    - 개발 계열 a50
    - 보류 계열 POD
  - 파일럿에 이미 근거가 있다. 장시간 대기 경보율이 MCD 18.1 %에서 물리 규칙 2.4 %로 줄었다.
  - "앙상블"은 A+D 결합을 실제로 만들 때만 주장한다.

### P1-3. 슬립 ŝ와 물리 일관성 잔차 E2는 버스트 하나로는 잡음에 가깝다

- **위치:** 03 §2.1 ŝ, §2.3 E2, §7 차별점 2; 05 WP1·WP2·G1
- **무엇** (원본 재계산, A-4)
  - 부하 버스트 136개(대부분 50행, 톤 적합 R² 중앙 0.92)를 봤다.
  - 부하 4분위의 비 중앙값은 2.9938에서 2.9809로 약 0.013 움직인다.
  - 그런데 **분위 안 표준편차가 0.007–0.023**이다.
  - 이론 하한(Cramér–Rao, N = 50, R² 0.92)도 비의 표준편차 약 0.008이다. N = 37이면 0.012다.
  - Spearman −0.40으로 계획 값(−0.41)과 같다.
  - 집단 수준 경향은 확실하다. 하지만 버스트 단위 부하 추정과 E2 잔차로는 신호보다 잡음이 크다.
- **수정**
  - ŝ·E2를 Tier 1 핵심과 차별점에서 내린다. S1k 가설의 집단 수준 근거로만 쓴다.
  - 필요하면 Tier 2에서 여러 버스트 평균 ŝ(느린 지표)로 다시 본다.
  - G1의 "슬립 추정 안정성"은 수치로 고정한다. 예: 분위 안 SD < 분위 간 차이의 1/3. 실패하면 바로 삭제하고 되돌아가지 않는다.

### P1-4. 전류 채널 고장, 채널 규칙, 제약 3, F8 사이의 비대칭과 식별 불가

- **위치:** 03 §2.5; 04 §3.1(F5 개발, F6 보류, F8), §3.3 I2, §3.4, §5 제약 3
- **무엇**
  - **전류 채널 고장의 탐지 정의가 없다.**
    - F5(토크 맥동 → 전류 변조)와 F6(마찰 → 전류만)은 경보가 나야 맞는 고장이다.
    - 그런데 채널 규칙은 전기·계측 채널만의 경보를 "계측 점검" 카드로 보낸다. POD를 셀 때 이 카드가 탐지인지 정의가 없다.
    - 제약 3은 **기계** 채널 경보만 센다. 그래서 전기 채널 경보는 오경보 비용이 0이다.
    - 전기 채널 경보를 탐지로 세면 이득만 있다. 선택이 전류 민감 탐지기 쪽으로 기운다. 계획이 가장 경계한 계측 민감 특징 쪽이다.
  - **구별할 수 없는 쌍을 서로 다른 결과로 요구한다.**
    - F8 "한 채널 이득 ×1.5"는 계측 점검으로 가야 한다고 한다.
    - 계열 F1(진동 광대역, 한 채널, g = 1.5)은 고장 경보가 나야 한다고 한다.
    - 참조 채널이 없으면 둘은 구별할 수 없다. I2(진동 이득 ±10 %)와 F1(g = 1.1)도 마찬가지다.
    - §3.4 식별 불가 쌍 표에 이 쌍이 없다.
  - **제약 3이 목적과 충돌한다.**
    - 제약 3(I2 ±10 %에서 기계 경보율 ≤ 2α)은 사실상 "진동 10–20 % 변화는 잡지 않는다"를 강제한다.
    - 이것은 목적(계열 F1의 a50 최소화)과 정면으로 부딪힌다.
- **수정**
  - 채널별로 POD와 경보 예산을 따로 정의한다(기계 경보 POD/FA, 전기 점검 POD/FA).
  - F8에서 이득 변화를 뺀다. 구별 가능한 것만 남긴다(평탄·포화·결측·오프셋 계단·위상 반전).
  - 이득 변화는 식별 불가 쌍으로 옮긴다(I2·이득 ↔ 계열 F1).
  - 제약 3이 a50의 하한을 만든다는 점을 설계 선택으로 명시한다.
    - 현장 의미: "기준 채널 없이는 10 % 진동 변화를 센서 드리프트와 구분할 수 없다 → 기준 채널·정기 교정이 필요하다(센서 로드맵)."
    - 항목 3·4의 좋은 소재다.

### P1-5. 선택 규칙의 공백

- **위치:** 04 §2.1, §2.3, §5; 03 §3.2 D, §5; 05 G2
- **후보 집합**
  - 문제: 열거되어 있지 않다. A+D 정의가 없고, 기준선의 자격도 불명이다.
  - 수정: `protocol.yaml`에 자격 후보와 참고 행을 나눠 적는다.
- **a50을 재는 분할**
  - 문제: 지정되지 않았다. §2.3은 "주입은 각 분할의 시험 정상 버스트에만"이라고 한다.

- **D의 확률 보정 데이터**
  - 문제: "보류 합성 혼합"이 보류 계열(F2·F3·F6·F7)인지, 개발 계열의 보류 버스트인지 모호하다.

- **제약 1의 "블록별 최댓값 ≤ 3α"**
  - 문제: 완벽히 보정된 탐지기도 우연히 떨어진다.
    - 블록당 약 68 버스트, α 1 %면 한 블록에서 FP ≥ 3일 확률이 약 3 %다.

    - 모든 후보가 탈락할 때의 대체 규칙도 없다.
  - 수정
    - 블록 최댓값은 보고 지표로 돌린다.
    - 제약은 합동 이항 검정으로 한다. 예: 95 % 상한 ≤ 2α.
    - "아무도 통과하지 못하면 위반이 가장 작은 후보를 고르고 공개한다"를 추가한다.

- **a50 추정 실패**

  - 수정: "< 최소 격자" 또는 "> 최대 격자"로 표기하고, 순위 계산 규칙을 정한다.

### P1-6. 경보 예산의 숫자와 경보 단계 이름이 문서마다 다르다

- **위치**
  - README §4: 주의 ≤ 1/일, 경고 ≤ 1/주
  - 03 §3.2 B: 교대당 1회 ≈ 3,700 버스트
  - 03 §4 경보 표: 관찰 / 점검 권고 / 정지 검토. 1단계 = 단일 버스트 p < α₁
  - 03 §4 추가 문단: 경고 / 위험
  - 04 §5 제약 1: α_op 1 %/버스트
  - 05 §5: 주의 / 경고 / 위험
- **무엇**
  - α_op 1 %/버스트는 지속성 규칙 전에 시간당 약 4.5회, **하루 약 109회**다.
  - 1단계 "관찰"이 단일 버스트 p < α₁이고 α₁ = 1 %면, 하루 100회 넘게 알림이 나간다.
  - 2-of-3 지속(독립 가정)은 하루 약 3회다.
  - README 목표(주의 ≤ 1/일)와 두 자릿수가 차이 나는데, 둘을 잇는 산술이 없다.
- **수정**
  - "경보 예산 사슬" 표를 하나 만든다. 왼쪽부터 차례로 이어진다.
    1. 버스트 α: 이 데이터로 검증 가능(≈ 1 %)
    2. 지속성 규칙
    3. 설계 FA/h: 외삽이며 검증 불가
    4. 교대·일 기대값: 설계값
    5. 그림자 운전 실증 기간
  - 단계 이름을 하나로 통일한다. 예: 1 주의(관찰) / 2 경고(점검 권고) / 3 위험(정지 검토), 그리고 계측 점검과 판정 보류.
  - 1단계도 지속성이나 낮은 α₁로 하루 예산에 맞춘다.

## 9. README — 한 장 입구로서의 평가와 개선안

**평가**
- 약 180줄이다. 첫 화면이 과정 메타("예준의 요청을 이렇게 이해했다", "독립성 공개")다.
- 팀 리더가 30초 안에 알아야 할 것이 바로 보이지 않는다. 최종 모델, 핵심 주장, 최소 범위, 결정할 것이 여기에 든다.
- 정의 없이 쓰는 약어가 많다. S1k, PHI-C, OE-GBM, a50, FA/h, T_real/T_syn이 그렇다.

**개선 순서**
1. 결론 3줄
   - 최종 모델 한 줄
   - 주장 3개: 오경보 통제, 작은 고장 검출한계, 현장 경보·카드
   - 가장 큰 위험 1개
2. 최소 완결판(R1–R3)과 컷 라인
3. 루브릭 대응 표(지금 것 유지, 위 수정 반영)
4. 예준이 정할 것. 다음을 추가한다.
   - 자격 후보와 모델 이름
   - 부하 미상 규칙과 에피소드 합격 조건
   - 컷 라인
   - 외부 데이터는 "Tier 1 안 씀" 권고
5. 위험·한계
6. 용어표 6줄
7. 독립성·리서치 방법(맨 끝)

## 부록 B. 공식 문서에서 확인한 요구 (과제공개·보고서 양식 hwpx)

**과제 ③의 요구**
- "유압펌프 모터의 상부·하부 진동 및 전류 시계열 데이터를 활용하여 설비이상을 조기에 탐지하는 AI 모델을 개발"
- "이상을 많이 탐지하는 것뿐만 아니라 정상적인 운전변화를 이상으로 판단하는 오경보를 줄이고, 모델의 미탐지·오경보 발생조건을 분석"

**평가 항목 2와 양식 제2장 작성요령**

- 제2장 작성요령: "베이스라인을 포함하여 2개 이상의 모델을 비교하고, 동일한 평가조건에서 어떤 차이가 나타났는지와 최종모델을 선택한 이유를 제시"

**제3장 작성요령**
- "전체 평균 성능만 제시하지 않고, 모델이 잘 작동하는 조건과 실패하는 조건을 구분"

**제4장 작성요령**
- "모델의 출력값이 실제로 어떤 현장 판단과 조치로 이어지는지"

**제5장 작성요령**
- "단순히 새로운 알고리즘을 사용했다는 설명보다, 제안한 방법이 성능·오류 감소·현장 활용에 어떤 기여를 했는지를 제2장과 제3장의 결과에 연결"
