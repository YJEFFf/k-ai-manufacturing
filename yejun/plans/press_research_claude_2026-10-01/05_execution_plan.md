## 0. 운영 원칙

1. **[v2] 세로 절편으로 짓는다.** 얇게 끝까지(R1) → 넓히기(R2) → 마감(R3) 순서다.
   - 각 절편은 `run_all --quick`이 통과하는 상태로 커밋한다.
   - 두 도구가 교대로 일하고 세션이 끊길 수 있으므로, **저장소는 언제나 한 명령으로 도는 완결 상태**여야 한다.
2. **사전 등록 → 구현 → 선택 → 동결.** `protocol.yaml`(정의·임계·계열·선택 규칙)을 단일 출처로 둔다. 확정 해시를 산출물에 기록한다.
3. **규칙에 곁가지 규칙을 덧대지 않는다.** 결함은 해당 층의 정의를 바꿔 고친다. 이전 판과 같은 시험을 함께 다시 돌린다.
4. **새 폴더에서 시작한다(이름은 예준이 정함, 제안 `yejun/press_v3/`).** 기존 패키지는 전제가 아니다. 함수 단위 재사용만 허용하고, 그것도 이 계획의 테스트를 통과할 때만 한다.
5. **샘플 단위·마지막 행 실시각.** S1k 해석에만 기대는 것(스트로크 위상, 톤 Hz 해석)은 조건부로 표시한다.
6. **실행 시간 예산.** `--quick`(격자 축소, 부트스트랩 200회)은 CPU 10분 이내, 전체는 30분 이내를 목표로 한다. 가이드북 LSTM-AE(B0)는 원설정 시드당 약 50분으로 추정되므로 **기본 실행에서 빼고 캐시 결과 + 별도 명령**으로 둔다.

```
yejun/press_v3/

  DATA_SOURCES.md            # 데이터 출처·라이선스·해시
  requirements.txt           # 버전 고정, CPU만 (numpy, pandas, scipy, scikit-learn, statsmodels, matplotlib, PyYAML)
  requirements-b0.txt        # 가이드북 재현 전용(TensorFlow) — 선택 실행
  config/protocol.yaml       # 04 문서의 정의·분할·지표·선택 규칙(단일 출처)
  config/injection_grid.yaml # 주입 계열 격자(해시 기록)
  run_all.ipynb              # 공식 개발환경(Jupyter)용 진입점 — run_all.py를 그대로 호출
  src/press_v3/
    data.py       # L0 SQI(LSB 지문 포함), 버스트·마지막 행 실시각, L1 상태·부하·부하 미상·정지
    signal.py     # 60 Hz·고조파·톤 적합, M/E 지표, 금지 특징 목록
    inject.py     # 계열 주입(슬립 일관 처리), 정상 블록 부트스트랩 스트림
    models.py     # 한 줄 규칙, IF/kNN, 상태별 PCA, PHI-Prob(A·D 헤드), 지도 대조
    calibrate.py  # 교차 conformal, 기준선 갱신(EWMA), 공통 확률 헤드, PPV 시나리오
    alarm.py      # 경보 단계·지속성·해제·빠른 경로·병기 태그·이유 코드
    evaluate.py   # 분할 3종, 지표, POD GLM, 선택 규칙, 교란 시험, 그림
    run_all.py    # 전처리 → 학습 → 보정 → 추론 → 평가 → 산출물 (--quick/--full)
  tests/          # 계약 테스트(정의·불변성·누수·주입 0강도=원본·conformal 타당성)
  outputs/        # predictions_rows.csv(전 20,600행), predictions_bursts.csv, metrics/, tables/, figures/, run_manifest.json
```

- `--root` 기본값은 동봉 데이터의 상대 경로로 두고, 입력 해시를 검사한다.
- 행 단위 예측 파일은 `yejun/.gitignore` 규칙에 따라 Git에는 올리지 않는다.

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| 실제 이상이 판정 보류·계측 점검으로 빠짐 | 부하 미상·정지 규칙을 WP0에 고정(이상 14/17, 정상 0/251). F-COMBO 합격 시험. 보류는 미탐으로 집계 |
| 시간 부족 | 세로 절편과 컷 목록. 매 절편 `run_all --quick` 통과 커밋 |
| 아무 후보도 제약을 통과하지 못함 | 위반이 가장 작은 후보를 고르고 공개(04 §5-7) |
| 두 도구 간 정의 표류 | `protocol.yaml` 단일 출처, 계약 테스트, 용어표 |
| 드리프트로 시험 FPR이 시험창 위치에 좌우됨 | 기준선 갱신, SP-block 헤드라인, 드리프트 곡선 |
| 합성 고장이 비현실적이라는 비판 | 계열마다 주입 카드(메커니즘·출처·운용 한계), 학습에 안 쓴 계열 결과 우선, 식별 불가 쌍 공개, 하룻밤 조건의 낙관적 하한임을 명시 |
| S1k 해석 비판 | 가설로 제시하고 근거 ①–③과 스크립트를 공개. 결론은 샘플 단위 설계라 해석에 의존하지 않음 |
| "이상 확률" 의미 논란 | `p_anomaly`(기준 유병률 명시)와 경보 PPV(π = λ × D 시나리오)를 구분하고 우도비 상한을 표기 |
| 실행 시간 폭증 | 특징 캐시, `--quick`, B0 캐시 |
| 문구 역효과(가이드북·공식 베이스라인·레이블 타당성) | 화해형 표현 사용(검토 전략 8절 표). 같은 수행기관 데이터셋 이야기는 쓰지 않음 |
