# 05. 실행 계획 — 작업 묶음, 완료 기준, 순서, 현장 활용

[근거 표기] `[D§]` 01 문서, `[A§]` 03 문서, `[P§]` 04 문서, `[R#]` 02 문서.

## 0. 운영 원칙

1. **Tier 1만 끝나도 완결된 결과 묶음이 되게 한다.** Tier 2·3은 Tier 1 산출물을 바꾸지 않고 더하는 방식으로만 붙인다.
2. **사전 등록 → 구현 → 선택 → 동결 순서를 지킨다.**
   - 04 문서와 주입 격자 YAML을 확정하고 커밋한 뒤에 비교 실험을 돌린다.
   - 선택이 끝나면 모델·임계값·보정을 동결한다.
   - 동결 뒤 바꾸면 변경 기록과 바꾸기 전·후 수치를 함께 남긴다.
3. **규칙에 곁가지 규칙을 덧대지 않는다.** 결함이 나오면 해당 층(L0–L6)의 정의를 바꾸고, 이전 판과 같은 시험을 함께 다시 돌린다.
4. **새 폴더에서 시작한다.** 이름은 예준이 정한다. 제안: `yejun/press_v3/`.
   - 기존 `press_submission/`, `press_guard/`는 이 계획의 전제가 아니다.
   - 재사용은 함수 단위로만, 이 계획의 테스트를 통과할 때만 한다.
5. **샘플 단위로 구현한다.** 주파수는 주기/샘플, 시간은 실시각 버스트 시각이다. 샘플링 해석(S10/S1k)이 바뀌어도 코드가 바뀌지 않는다 [D2-2].

## 1. 코드 구조 (제안)

```
yejun/press_v3/
  README.md                 # 한 명령 실행법, 산출물 설명, 라이선스 표
  DATA_SOURCES.md           # 데이터셋별 출처·라이선스·변경사항·해시
  requirements.txt          # 버전 고정(CPU만)
  config/protocol.yaml      # 04 문서의 분할·지표·선택 규칙
  config/injection_grid.yaml# F·N·I 계열 격자(해시를 manifest에 기록)
  src/press_v3/
    data.py        # L0 수집 건전성(SQI), 버스트 분리, 중복 처리, L1 상태(A60, I_T, ŝ, 지지 범위)
    signal.py      # 벡터화 사인·고조파 적합, 톤 적합(0.179·0.355), 슬립, M/E/S 지표, 금지 특징 목록
    inject.py      # F1–F10, N1–N9, I1–I3 (반송파 재합성 포함), 정상 블록 부트스트랩 스트림
    models/        # baselines.py(B-const…B-shew), b0_lstm_ae.py(B0·B0′·B0-rnd), phi_c.py(A), mspc.py(B), oneclass.py(C), oe_gbm.py(D), seq_ae.py(E), supervised.py(H)
    calibrate.py   # Mondrian·교차 conformal, Cauchy 결합, 기저율 시나리오 확률, (Tier 2) Venn–Abers, HMM 필터
    alarm.py       # 3단계 경보 + 계측 점검 + 판정 보류, 지속성(on/off-delay), 극단값 빠른 경로, 이유 코드
    evaluate.py    # 분할 A/A′/B/C, 지표(4절), POD GLM(a50/a90), 부트스트랩, 선택 규칙, C 시험
    explain.py     # 물리 비교 문장, 반사실, RBC, TreeSHAP, ALE, H 통계량(귀무분포)
    run_all.py     # 전처리 → 학습 → 보정 → 추론 → 평가 → 산출물
  tests/           # 불변성(N8)·누수·재현성·conformal 타당성·금지 특징·주입 0강도=원본
  outputs/         # predictions_rows.csv, predictions_bursts.csv, metrics/, tables/, figures/, run_manifest.json
```

**의존성 원칙**
- Tier 1은 numpy, pandas, scipy, scikit-learn, statsmodels, matplotlib, PyYAML로 끝낸다.
- 딥러닝(B0′, E)은 PyTorch CPU 하나만 쓴다.
- 가이드북을 원본 그대로 재현하는 B0는 TensorFlow가 필요하다. 별도 requirements로 격리한다(선택 실행).
- shap(MIT)은 Tier 2 설명에서만 쓴다.
- 금지(라이선스) [R3][R8]:
  - GPL·AGPL·비상업: catch22, hctsa, saxpy, 옛 NAB 복사본, Moirai·TimesFM 3.0 가중치
  - BSL: alibi-detect, Alibi Explain
  - 라이선스 없는 저장소의 코드

## 5. 현장 활용 설계 (WP10 상세)

| 항목 | 내용 | 근거 |
|---|---|---|
| 위치 정의 | AI 경보는 법정 점검·방호장치를 **대체하지 않는 정비 의사결정 보조**다. 프레스 작업 시작 전 점검(산업안전보건기준에 관한 규칙 제35조·별표 3)에는 유압펌프 항목이 없다. 그래서 그 빈자리를 채우는 상태감시로 위치시킨다 | R7 |
| 경보 체계 | 주의 = 비가청 알림(정비 일일 보고) / 경고 = 정비 책임자·운전원 / 위험 = 즉시 대응. 계측 점검과 판정 보류는 별도 범주다. NAMUR NE 107(F/C/S/M), ISO 20816-1 ALARM/TRIP, ISO 17359의 기준선 대비 변화와 대응시킨다. 우선순위 분포는 약 80/15/5를 목표로 한다 | R4, R9 |
| 경보 정의표 | 단계마다 결과, 대응시간, 조치, 근거 데이터, 기대 오경보 수(설계값), 억제·보류 규칙을 적는다(ISA-18.2 rationalization 형식) | R4, R9 |
| 이유 코드 → 점검 카드 | 순서는 ① 계측 확인(센서 체결·케이블·SQI) → ② 공정 확인 → ③ 판단이다. 기계 채널 코드별 공정 확인 항목: | R1, R9 |
| | 광대역·충격(M3·M4): 유면·흡입 스트레이너·흡입 이음부 공기 누설, 유온, 베어링 | |
| | 펌핑 톤·부하 체류(M6·S1): 펌프 유량-압력 시험, 케이스 드레인 유량, 유온 추세 | |
| | 흔들림 모드(M5): 고정 볼트·마운트·커플링 정렬 | |
| | 전기·계측 채널(E1–E3): 상전류·상전압 3상 측정, 센서·결선. 전압 기준 채널이 있으면 계측 대 전기를 바로 판별 | |
| 물리 비교 표시 | 경보 카드에 "하부진동이 같은 부하 정상의 2.4배, 상위 1 % 밖"처럼 쓴다. 같은 부하 정상 분포 띠(5–95 %) 위에 해당 버스트 원신호를 겹친다(가능도 경보 + 교차확인) | R9 |
| 확률 표시 | 기저율 시나리오별 사후확률을 자연빈도로 표기: "이 등급 경보 100건 중 약 N건이 실제 이상(가정: 고장률 X)" | R9 |
| 비용 기반 임계 | p* = C_I / (C_U − C_P). 비용비 10/50/100/300 × π 10⁻³/10⁻⁴ × 예산(1/일, 1/주) 격자로 결정 민감도를 보인다. 가이드북의 "펌프 고장 시 최대 2–3일 정지"는 C_U의 정성 근거로만 쓴다 | R4, R9 |
| 점검 우선순위 | 교대 안 경보를 (단계, 사후확률, 지속 시간, SQI) 순으로 정렬한 목록 | R9 |
| 도입 절차 | ① 그림자 운전(기록만, 정비일지 대조). 교대 예산 실증에 ≥ 24 h, 일 예산 ≥ 72 h, 주 예산 ≥ 3주 → ② 상태별 재보정(상태당 ≥ 100 버스트) → ③ 경고 단계 가동 → ④ 위험 단계 가동. 임계 변경은 변경관리로 기록 | R4, R9 |
| 피드백 | 경보마다 처리 코드 (a)–(e). 조치 전 상태를 남기는 **as-found 기록**(측정값·사진·소견)으로 예측 진위를 사후 판정한다(정비 후에는 반사실이 사라짐). 갱신은 확인된 정상 구간에서만 한다 | R4, R9 |
| 운전 변경 기록 | 금형 교체·정지·시운전·오일 온도를 기록해 N1–N4 오경보를 억제(상태 기반 억제, ISA §11.9 범주) | R4, R5 |
| 센서·수집 로드맵 | 진동 샘플링 사양 명시 + 앨리어싱 방지 필터, 연속 기록, 토출압·유온·필터 차압·유중 입자, **같은 DAQ의 전원 전압 기준 채널**, PLC 운전모드·스트로크 신호, 정비 이력. 항목마다 01 문서의 어느 한계를 푸는지 연결. 데이터 표준(KAMP 참조모델의 유압식 프레스 AAS 속성명 등)과 맞춘 출력 필드 | R1, R7, R9 |
