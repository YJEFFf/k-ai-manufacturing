# 구현 순서와 완료 기준

이 문서는 기능별 구현 계약이다. 프레스 핵심 데이터 계약·모델 비교·개발 주입·손실·후반 감사는 [검증 패키지](../../analysis/press_master_validation_2026-10-03/README.md)에서 실행했고, 전체 채택 기준을 통과한 새 후보는 없다. 현재 작업 순서는 [실험 후 수정 계획](07_validation_revision.md)을 따른다. 대회 보고서·발표자료 작성은 [작업 규칙](../../AGENTS.md)에 따라 별도 착수 지시가 필요하다. 실험 완료를 그 지시로 해석하지 않는다.

## 이번에 실행한 감사의 재현

아래는 데이터·계획 감사의 재현이다. 모델 실험의 새 적합·집계 대조 명령은 [핵심 검증 재현](../../analysis/press_master_validation_2026-10-03/README.md)에 따로 있다. Python 3.12의 분리된 환경에서 저장소 루트 기준으로 실행한다. 전체 의존성 고정본은 [audit lock](requirements-audit-lock.txt), 직접 의존성 목록은 [requirements](requirements-audit.txt)다. 제공 프레스 CSV는 공유 원본 경로에 이미 있어야 한다.

```sh
python3.12 -m venv /tmp/press-master-audit
/tmp/press-master-audit/bin/python -m pip install -r yejun/plans/press_master_2026-10-03/requirements-audit-lock.txt
/tmp/press-master-audit/bin/python yejun/plans/press_master_2026-10-03/scripts/reproduce_audits.py --acquire
```

취득 파일이 준비돼 있으면 `--acquire`를 빼도 된다. 취득 옵션은 네 데이터셋과 NLN 문서 두 개만 대상으로 하며 NLN 센서 전체를 받지 않는다. 감사는 프레스 재계산 → 외부 최초 구조 감사 재현 → SKAB 수집 그룹·충돌 마스크 정정 → ESPset ID 예약 → 패키지·원파일 검증 순이다. 기존 계산 helper를 import할 때도 `PYTHONDONTWRITEBYTECODE=1`을 적용한다. 세부 로그는 Git 제외 `cache/reproduction/`에 남긴다.

원출처 웹페이지의 이번 수신 사본도 로컬에 있으면 `--with-source-caches`로 해시를 추가 검증한다. 이 사본들은 Git에 없으므로 새 clone의 기본 필수 조건이 아니다. 새 출처 접근은 `scripts/check_sources.py`로 따로 실행하며, 현재 웹 응답이 과거 사본과 바이트까지 같다고 요구하지 않는다. 접근 수·버전·내용이 바뀌면 이번 날짜의 문구와 구분해 검토한다.

[실행 기록](evidence/audit_run.json)은 실제 환경·실행한 단계·반환값을, [검증 기록](evidence/verification.json)은 문서 링크·설정·분할·수치·해시 검사를 보관한다. [입력 계보](evidence/provenance.json)는 비교한 문서와 재계산 의존 파일의 기준 커밋·SHA-256을 고정한다. 이 검사를 모두 통과해도 새 탐지 모델의 성능 검증을 통과했다는 뜻은 아니다.

## 구현 위치와 계약

새 구현 위치는 `yejun/press_v3/`로 정한다. 기존 `press_guard`·`press_submission`의 결과와 인터페이스를 보존하고 비교 어댑터로 재사용한다. 공용 원본과 `claude/`는 읽기 전용이다. 설정은 이번 [protocol.json](protocol.json)을 복사해 버전·해시를 연결한다. 이후 변경은 변경 이유·결과 열람 여부·시험의 개발 전환 여부를 기록한다.

| 모듈 | 책임 | 핵심 산출물 |
|---|---|---|
| data | 해시, 원행 대응, 중복, 기록 경계, 시각·품질 상태 | input_manifest, record_map, exclusions |
| features | AC 특징, 조건 대리값, 미정의·길이 처리 | feature_schema, fitted_preprocessing |
| models | B1/B2/B3/C1/C2/O1, 고정 시드 | fitted_model, model_card_facts |
| calibration | 실제 정상 순위, 별도 라벨/합성 확률 | calibration_ids, score_reference, probability_definition |
| augment | 부모 계보, crop·잔차·주입 | augmentation_manifest, rejected_generations |
| policy | 즉시 요청, 지속성, 공백·해제·유보 | request_log, policy_definition |
| external | SKAB 그룹, Beihang 시간축, ESPset ID, UCI 회귀 | source_use_manifest, external_splits |
| evaluate | 같은 시점의 지표, 조건별 오류, 선택 규칙 | model_comparison, family_curves, selection_record |
| reproduce | 환경·버전·실행·검증 연결 | run_manifest, reproduction_summary |

제품 전체의 `run_all.py`와 노트북은 아직 없다. 검증용 `reproduce.py`는 현재 구현 범위의 전처리→적합→보정→추론→집계를 새로 실행해 저장 결과와 대조한다. 외부·확률·운영 모듈을 제품에 연결한 후 CLI 하나로 확장한다. Jupyter는 같은 CLI를 호출하는 편의 경로다. 위 `reproduce_audits.py`는 데이터·계획 감사만 재현한다.

## 기능별 완료 조건

### 데이터와 평가 계약

현재 확보한 해시와 구조 감사 결과를 구현 입력으로 가져온다. 프레스 599/21 기록을 무조건 맞추는 하드코딩 대신 경계·중복 규칙과 원본 해시를 함께 검증한다. SKAB의 예전 파일 분할을 사용하지 않는다. 주석 충돌 마스크와 동일 수집 그룹은 정상 적합·보정·평가를 관통한다.

완료 조건은 모델을 넣지 않아도 모든 원행의 상태와 소속, 기록 판정 가능 시각, 중복 그룹, 외부 채널 시간축을 설명할 수 있는 것이다. 단순 B1까지 한 번 연결해 분모·상태·집계가 끝까지 만들어져야 한다. 데이터 의미가 미해결이면 해당 채널·주장을 보류하며 예측을 강제로 만들어 채우지 않는다.

### 같은 조건의 모델 비교

공통 입력·분할의 B1/B3/C1/C2 7설정과 후속 개선안 6개는 실행했다. 조건화·단측·길이 추정·결합 방식의 이익과 손실을 구분한 결과를 승계한다. B2 공통 재적합과 과거 동결 결과 재현은 비교 질문이 명확할 때의 별도 참고 항목이며 현재 필수 경로에 넣지 않는다. 추가 변환 감사는 AC, raw, 공통 matched 각각에서 적합·보정까지 다시 수행해야 하며 클래스별 배율 교정은 주 추론에서 금지한다.

가이드북 원설정 LSTM-AE 완전 재현을 추가할 때는 3시드 별도 계산으로 실행한다. 현재 미실행 결과를 예측해 표에 넣지 않는다. 공정한 LSTM-AE 변형은 버스트 안 창·정상 보정으로 따로 적합해야 한다. 과거 결과 보존과 모든 과거 학습의 반복 실행은 구분한다.

실제 라벨 확률 진단은 정상 전용 탐지 트랙과 별도로 실행한다. 이 단계 완료 시 각 모델의 실제 라벨 사용 여부·예측 시점·학습 정보·보정 분모가 표에 있어야 한다. 최종 모델 후보가 좋아 보인다는 이유로 이 표 없이 증강·UI로 넘어가지 않는다.

### 증강과 오류 분석

현재 수행한 주입은 평가용 스트레스다. 정상 학습 증강은 A0/A1 반복 계약과 A2 crop부터 실행한다. A3 잔차와 O1 합성 노출은 추가 근거가 있을 때의 확대 항목이다. 개발 결과를 보고 성공 조건을 바꾸지 않는다. 각 실험은 실제 정상 요청·개발 POD·손실 셀·실행비용을 함께 남긴다. 보류 계열은 선택 후 열어 감사한다.

필수 오류 표는 시간 구간×전류 조건, 길이×조건화 가능 여부, 진동 방향×전류 변화, 품질 요청×기계 근거 요청이다. 전류 조건과 진동의 상호작용은 조건부 잔차와 전역 잔차의 차이로 먼저 설명한다. GBM이 채택되면 지원 범위 안의 2원 반응을 보조로 제시하되 서로 상관된 조건의 불가능한 조합을 인과 효과처럼 해석하지 않는다.

느린 변화 경로는 모델 선택 뒤 별도 정책 실험으로 진행한다. 지속성으로 오경보가 줄어도 추가 지연·미탐 증가를 함께 보고한다. 미상 게인을 정상으로 학습하거나 감쇠를 정상으로 지워 버리면 실패다.

### 외부 실험

외부 주 검증은 SKAB의 수정 그룹 분할이다. fit/dev/cal 어댑터와 두 구조 대조를 다음 필수 작업으로 앞당겼다. 새 회차 검증이 데이터 부족을 보완하는 핵심이기 때문이다. 후보·특징 대응·정책은 dev에서 정하고, 실제 정상 cal로 보정한 뒤 test를 한 번 공개한다. 프레스에서 아직 최종 후보가 채택되지 않았다는 사실을 유지한다.

다음 순서는 Beihang의 진동·속도 조건 실험, ESPset의 펌프 ID 보조 검증이다. 서로 다른 표현에서 같은 가중치를 썼다고 하지 않는다. 외부 데이터별 구조에 맞춘 재적합 절차의 비교다. 모델 하나의 모든 분야 우승을 요구하지 않고 어느 조건에서 실패하는지 보존한다.

기존 UCI는 누설·냉각 조건 실패를 재현하는 회귀 분석이다. 새 외부 실험이 실패했다고 UCI로 이름만 바꿔 성공 외부 시험으로 대체하지 않는다. 접근·주석·이용 조건 때문에 외부 실행이 막히면 그 데이터의 질문만 미완료로 표시하고 다른 자료의 완료 상태를 분리한다.

### 운영 연결과 재현

점검 화면은 센서 변화, 같은 관측 조건의 정상 대비 차이, 조건화 가능 여부, 기록 길이, 미관측, 요청 이유와 처리 결과를 보여준다. p값을 고장 확률처럼 색칠하지 않는다. 소수 데이터의 극단 확률은 제한과 기준 혼합비를 함께 표시한다.

요청 종류는 진동 확인, 전류 확인, 계측 확인, 관측 부족의 네 가지로 시작한다. 원인 부위·정지 상태를 자동 확정하지 않는다. 처리 기록에는 생성 시각·담당·확인 수준·정상 승인·정비 연결을 남기며, 확인되지 않은 낮은 점수 데이터를 자동 정상 재학습에 쓰지 않는다. 장비 조작 지시는 사업장 승인 절차와 정비 담당자에게 연결한다.

의사결정 효용은 점검 수·확인 시간·미탐 비용의 변수로 비교한다. 실제 비용이 없으면 연간 절감액을 실측 성과로 쓰지 않는다. 알림 억제로 줄어든 개수와 놓친 변화·늦어진 확인을 동시에 기록한다.

기본 재현은 새 Python 환경에서 1회, 다른 OS 검증은 변경한 코드의 이식성이 불확실할 때 추가한다. 실제 실행 시간·메모리를 측정하기 전 10분/30분을 보장하지 않는다. 캐시는 입력·코드·설정·환경·seed 해시가 모두 맞을 때만 사용하고, 완전 재학습 모드와 캐시 검증 모드를 구분한다.

관측 결과가 α에 가깝다는 것을 단위 테스트 정답으로 강제하지 않는다. FPR·a50·Brier가 나쁘게 나오는 것은 연구 결과일 수 있다. 테스트는 규약·계산·누수를 검사하고 성능 실패를 숨기는 데 쓰지 않는다.

## 일정과 축소 규칙

10월 8일 마감까지 남은 작업은 [수정 우선순위](07_validation_revision.md)로 관리한다. 핵심 비교를 이미 실행했으므로 과거 날짜별 가정 대신 각 완료 조건과 외부 첫 실행 비용으로 일정을 갱신한다. 마지막 날 새 후보를 추가하거나 시험 결과를 보고 구조를 바꾸지 않는다. 보고서 착수는 별도 지시가 필요한 현재 상태를 유지한다.

축소 순서는 생성 모델·기초모델 → MiniRocket·추가 신경망 → 기준 자동 갱신 → 추가 UI 장식 → 추가 외부 세부 채널 → ESPset 보조 확장 → Beihang 보조 확장이다. 남길 것은 공정한 기준 비교, 확률 정의, 실제 정상 평가, 감소·전류 무효 손실 시험, 하나 이상의 보류 변화, SKAB 수집 그룹 검증, 출처·한 명령 재현이다. 필수 항목을 못 끝내면 미완료를 명시하고 검증된 최소 범위만 동결한다.

후보를 계속 늘리는 대신, 새 실험이 최종 선택이나 주장 범위를 바꿀 수 있는지로 추가 작업을 판단한다. 성능이 나쁜 실험의 재실행은 구현 오류·새 가설·누수 발견처럼 이유가 있을 때만 한다.
