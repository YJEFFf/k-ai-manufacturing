# 두 통합안의 비교와 오류 정정

비교 대상은 Codex의 `press_unified_2026-10-02`와 Claude의 `press_plan_merged_2026-10-02`다. 원안 두 개, 기존 평가 기록, 관련 재계산 코드도 추적했다. 이번 검토는 한 작성자가 방법론·데이터·실행 관점을 번갈아 적용한 것이며 새 독립 심사자들의 합의로 표현하지 않는다. 과거 AI 심사 점수는 공식 점수나 수상 확률로 사용하지 않았다.

## 설계별 최종 선택

| 쟁점 | Claude 통합안 | Codex 통합안 | 최종 결정 |
|---|---|---|---|
| 연구 중심 | 조건부 물리지표와 단측 판정 | 조건부 정상 기준을 우선 가설로 | 조건부 정상 기준. 물리 의미·최종 승자는 검증 전 확정하지 않음 |
| 기존 v2 | 선택 참고로 축소 | 동결 결과와 공통 분할 재적합 필수 | 둘 다 필수. 개선을 주장하려면 기존 방식과 직접 비교 |
| 진동 평균 | 기본 제거 | raw·matched·공통 평균 제거 감사 | 라벨 무관 공통 평균 제거를 주 입력으로, raw/matched는 교란 감사 |
| 전류 무효 | 부하 미상·정지 경로 | 전역 진동 경로 | 전역 진동과 전류 점검 병기. 물리적 정지는 확정하지 않음 |
| 보정 | 합동 교차 보정 | 합동 분리 보정 | 모델 적합과 분리한 실제 정상의 순위 보정. 교차 보정은 후속 연구 |
| 짧은 기록 | 주요 특징은 10표본 이상 | 전체 분모와 축소 특징 | 1표본부터 상태 기록. 단일 진동 표본은 AC 정보 없음 |
| 후보 선택 | 일부 도전자에 보류 a50 채택 기준 | 개발 선택 후 보류 감사 | 보류 결과는 선택·튜닝 금지. 실패하면 주장 축소 또는 다음 버전 |
| 증강 | 평가 주입·OE 중심 | U0부터 U5까지 효용 대조 | 제한 변환·잔차·OE 순서. 같은 모델·학습량·부모 가중치 비교 |
| 외부 자료 | 기존 UCI 선택 단계 | SKAB 우선·파일 예약 | UCI 회귀 분석 + SKAB 중복 그룹 검증 + Beihang 조건 실험 + ESPset 개체 보조 |
| 확률 | 합성 혼합 확률이 주 출력 | 제공 라벨 확률이 별도 출력 | 제공 라벨 확률 진단을 대회 대응에 사용. 합성 확률은 별도 열 |
| 순차 감시 | 여러 경보 경로·기준 갱신 | 즉시 요청 뒤 지속성 비교 | 한 점수의 즉시 요청부터. 느린 점수와 기준 갱신은 별도 실험 |
| 운영 문구 | 고장 부위·비가동 경로 | 원인 미확정 확인 요청 | 센서·신호 근거와 확인 순서. 관측만으로 원인을 강제하지 않음 |
| 구현 순서 | 단계마다 끝까지 실행 | 공통 기준부터 비교 | Claude의 완결 단계에 Codex의 실험 대조·중단 기준 결합 |

## 재검수에서 수정한 주장

아래는 동일한 비중의 취향 차이가 아니다. 누수·오류, 근거 부족, 전략 선택을 구분한다.

| 번호 | 문제 | 판정과 근거 | 최소 수정 |
|---|---|---|---|
| R01 | SKAB 파일 분할이 수집 분리라고 가정 | **실제 중복 확인.** 학습 `other/11`과 시험 `other/10`에 동일 21행. 다른 4쌍도 겹침 | [그룹 예약](evidence/skab_group_reservation.json) 사용, 그룹 내 중복 한 번 집계 |
| R02 | Beihang의 채널이 CSV 행으로 동기화돼 있다고 읽을 여지 | **실제 구조 불일치.** 22열은 11개의 시간·신호 쌍 | 채널별 파싱 후 공통 시간창의 통계량으로 결합 |
| R03 | Beihang 출력 압력 1 kHz | **문헌과 파일 불일치.** 정상 1번 저장 간격은 약 1/3000초 | 이 채널은 보류. 파일별 시간 감사 후 보조 실험 |
| R04 | 전체 기록 판정을 예제 20행 창에 복사한 F1을 창 모델과 비교 | **판정 정보 차이.** 재계산 1.000 대 0.819672 | 동일 관측 종료점의 표만 우열 비교. 소급 판정은 사후 표 |
| R05 | ADC 격자가 센서 감도·g/A·1 kHz·정지를 입증 | **식별 불가.** 특정 ADC·감도를 가정한 격자 적합은 동일 관측의 유일한 생성 과정이 아님 | 표본 단위와 raw 단위. S1k·감도·비가동은 가설 |
| R06 | 정상 진동의 기록 평균이 작으므로 평균 제거를 확정 | **과정 미확인.** 평균 차이는 확인했지만 수집 경로 이력은 없음 | 공통 평균 제거는 교란 통제 선택으로 정당화 |
| R07 | 공통 평균 제거 뒤 스펙트럼 처리 교란이 해소 | **불충분.** 필터·정규화·센서 부착·단위 이력은 여전히 미상 | AC 감사 통과만으로 물리 파형 비교의 타당성 확정 금지 |
| R08 | 교차 conformal에 일괄 1−2α 보장 | **방법·가정 연결 누락.** 특정 이론을 임의 OOF 점수 풀링에 이식 불가 | split rank 보정으로 단순화. 의존·드리프트에서 명목 α와 실측을 분리 |
| R09 | 6블록 증가 순서의 1/720을 실제 드리프트의 정확 p값으로 확정 | **계산과 귀무 가정 구분 필요.** 6! 중 한 순서라는 계산은 맞지만 블록 교환가능성이 입증되지 않음 | 효과 크기·블록별 값 제시. 유의성 확정 표현 제거 |
| R10 | 블록 부트스트랩을 쓰면 정상 77분이 충분한 운영 인수 자료가 됨 | **독립 정보 불증가.** 블록도 시간 변화·표본 부족 영향 | 민감도 탐색만. 미래 교대 오경보 보장·확정 OC 상한 금지 |
| R11 | 센서 이득 ×10⁴에도 점수 불변이면서 실제 전류 크기 변화는 탐지 | **동일 관측의 식별 충돌.** y=gx만으로 g와 x 변화를 분리할 수 없음 | 알려진 단위 변환만 역변환. 미상 이득은 계측 확인, 무조건 정상 학습 금지 |
| R12 | 단측 규칙을 자르면 안 되는 최종 요구로 고정 | **전략 과잉 고정.** 진동 감소·소실 사각지대 가능 | 양측과 공정 비교하고 손실 허용 기준을 통과할 때만 채택 |
| R13 | C-REP·C-DL을 보류 계열 a50으로 채택 | **시험 누수 규칙 충돌** | 개발 계열 안에서 선택. 보류는 감사 전용 |
| R14 | U0·U1·U4의 서로 다른 모델/실제 라벨 사용을 증강 효과로 비교 | **효과 분리 실패** | 정상 증강 안에서 같은 kNN, OE 안에서 같은 GBM을 고정. 지도 라벨 모델은 별도 |
| R15 | 120분 램프를 77분 원자료로 실제 스트림처럼 시험 | **관측 길이 부족** | 실존 평가 구간 내 20·60기록 램프. 긴 재조합은 별도 시뮬레이션 |
| R16 | 중앙 8초 간격으로 8–16초·16–24초를 보장 지연 하한처럼 제시 | **간격 가변·미탐·타임아웃 누락** | 실제 기록 시각으로 지연 계산. 중앙 간격 수치는 설명용 예시 |
| R17 | S1k에서 실제 자료 전체 커버리지 약 0.6% | **근사 범위 수정.** 50표본 최대 길이를 모든 기록에 적용 | 전체 정상 행 기준 약 0.433%. 취득률 미확인 표기 |
| R18 | 이상/고장/정상 꼬리 확률을 같은 의미로 사용 | **대상 라벨·혼합 불일치** | 점수, 정상 순위, 제공 라벨 확률, 합성 확률 분리 |
| R19 | p값 해상도로 일반적인 고장 우도비 상한을 결정 | **수학적 근거 없음.** 경험 순위의 격자와 밀도비는 다른 양 | 해당 상한 삭제. PPV는 직접 가정한 TPR/FPR/π의 시나리오만 |
| R20 | GPL/AGPL을 대회가 금지한 것으로 취급 | **공식 요구와 팀 선호 혼동** | 선택 배포판 조건을 기록. 공개·재배포 조건별 판단, 일괄 금지로 표현하지 않음 |
| R21 | 개발환경 문구에서 Jupyter Notebook 의무를 도출 | **공식 문구보다 강한 해석** | Python CLI 재현 필수, 노트북은 편의 진입점 |
| R22 | 과거 AI 심사 점수·인용 수로 수상 가능성 확정 | **관측 근거 없음** | 공식 6항목에 실제 산출물을 대응하고 점수 예언은 제거 |

R05~R10의 근거는 [출처 검토](03_data_sources.md)와 [원자료 감사](evidence/press_audit.json)에 연결했다. 재계산 스크립트가 과거 해석을 출력하더라도 그 해석까지 승인한 것은 아니다. 예를 들어 `legacy_recalculation.txt`의 g 표기는 과거 코드의 가정을 보존한 출력이다. 새 계획에서는 raw 단위라고 쓴다.

## 비교 후 남긴 네 가지 후보 방향

| 후보 | 가장 좋은 설명 | 가장 강한 반론 | 최종 위치 |
|---|---|---|---|
| 조건부 잔차 | 관측 조건에 따른 정상 변동을 점수 전에 설명 | 전류도 고장에 영향받아 과도한 정상화 가능 | 주력 가설, 실패하면 교체 |
| 전역·단순 기준 | 가정이 적고 희소 자료에서 안정적 | 정상 상태 변화에 민감 | 항상 남기는 최종 후보 |
| 증강·표현 학습 중심 | 알려진 형태를 넘어 약한 변화를 학습할 여지 | 한 에피소드와 생성기를 외워 성능 착시 | 대조 실험을 거쳐 조건부 추가 |
| 외부 원자료 대량 결합 | 회차와 센서 다양성이 커짐 | 다른 설비의 센서값·라벨 의미 불일치 | 원시 결합 기각, 절차 재적합·개체별 검증으로 대체 |

최종 권고는 첫 방향에 둘째 방향의 교체 가능성을 남기고, 셋째 방향을 검증된 보강으로만 사용하며, 넷째 방향의 데이터 다양성을 독립된 외부 질문으로 활용하는 것이다. 이 결합은 동일한 의사결정인 **언제 어떤 근거로 확인 요청을 보낼 것인가**를 강화한다.
