# 프레스 재설계 검증·실행 계획

2026-10-01 · [전체 계획](README.md) · [출처·데이터](01_sources_and_data.md) · [접근법](02_research_options.md) · [증강 계획](04_augmentation_plan.md)

**모든 실험·구현·수집은 이후 실행 지시가 있을 때의 계획이다.** 이번 작업에서 이 문서의 절차를 실행하지 않았다. 제시한 수치 목표·파라미터·공수는 계획값이며 새 실험 결과가 아니다.

## 1. 검증으로 답할 질문을 먼저 고정한다

| 질문 | 주 비교 | 필요한 근거 | 현재 프레스만으로 가능한 수준 |
|---|---|---|---|
| Q1. 정상 조건화가 오경보를 줄이는가? | 전역 대 상태/잔차 모델 | 조건별 정상·이상, 동일 정책 | 신호 대용 상태의 탐색 비교 |
| Q2. 지속 변화에서 이익이 있는가? | 빠른 대 느린 대 결합 | 변화 시작 라벨 또는 별도 합성 시험 | 합성 민감도, 기존 이상에 대한 사후 분석 |
| Q3. 센서 관계가 추가 정보를 주는가? | 단일 채널/크기 대 관계 추가 | 같은 입력 시점과 특징 제거 비교 | 가능하나 날짜 교락 남음 |
| Q4. 목표 정상 참조가 도움이 되는가? | 무적응 대 기준/문턱 적응 | 새 개체·날짜의 확인된 정상 | 같은 프레스의 새 날짜 자료 없어서 미검증 |
| Q5. 증강이 실제 효용을 높이는가? | 무증강 대 가중치 대 증강 | 실제 자료 시험, 생성 계보 분리 | 탐색 비교; 독립 사건 일반화는 미검증 |
| Q6. 새 표현이 이익을 주는가? | 같은 분류기·다른 표현 | 동일 분할·학습/관측 예산 | 짧은 입력 적합성 확인이 선행 |
| Q7. 경보 정책이 부담을 줄이는가? | 고정 정책 대 대안 정책 | raw 점수·묶인 알림·지연 | 기록 범위 안에서 가능, 하루 실증 불가 |

시작 시 주 질문 하나와 보조 질문 두 개를 선택한다. 기본 제안은 Q1을 주 질문, Q3/Q5를 보조로 두고 Q2를 경쟁 주력으로 비교하는 것이다. 다른 방향이 유리하다는 근거가 나오면 정해진 판정 회의에서 바꾸고 변경 이유를 기록한다.

## 2. 데이터 사용 계약

### 2.1 실험 단위

| 단위 | 정의 | 사용 목적 |
|---|---|---|
| 행 | 한 타임스탬프의 센서 벡터 | 행 F1/AP와 점수 흐름 |
| 창 | 같은 연속 기록 안의 과거 관측 묶음 | 특징/모델 입력 |
| 기록 | 시간 공백 규칙으로 구분한 수집 묶음 | 기록별 경보·관측 길이 분석 |
| 실험 회차·개체·날짜 | 실제 수집 설계의 그룹 | 누수 없는 분할·불확실성 평가 |
| 고장 사건 | 별도 발생·점검으로 확인된 사건 | 실제 사건 재현율·시작 지연 |
| 작업자 알림 | 정책이 출력한 확인 요청 | 운영 부담 |

21개 이상 기록을 21개의 고장 사건으로 대체하지 않는다. 기존의 약 3분짜리 이상 파일은 한 수집 에피소드이며, 실제 독립 고장 발생 횟수는 확인되지 않았다.

### 2.2 입력 허용 범위

모델 입력은 예측 시점까지 이용 가능한 센서와 관측 품질 정보다. 타임스탬프는 경계·실제 경과시간 처리에 쓰되 날짜를 고장 예측 특징으로 쓰지 않는다. `Equipment_state`, 파일명, 경로, 정상/이상별 포맷 표식은 입력에서 제외한다.

단위 미확인 센서에는 임의의 A·g·mm/s 단위를 붙이지 않는다. 원시값의 RMS와 계측 장치가 출력한 RMS를 구분한다. 10 Hz 저장 간격은 원 ADC 취득 속도의 증거가 아니다.

공백을 가로지르는 창, 양방향 보간, 중심 이동평균, 전체 기록을 이용한 위상 정렬은 실시간 비교에서 제외한다. 사용할 경우 계산 완료 시점을 지연에 포함하거나 오프라인 분석으로 구분한다.

### 2.3 출처·도입 판정

외부 데이터는 [출처 문서](01_sources_and_data.md)의 확인 조건을 먼저 통과한다. 원출처·수집 설명·라벨 의미·버전·이용 조건이 확인되지 않으면 실제 도입을 보류한다. 일부 파일만 사용하면 선택 기준을 결과를 보기 전에 정한다.

대회 외부 데이터 허용 범위는 최신 주최 공지를 확인한다. 허용이 불명확하면 계획의 외부 검증은 연구 참고로 유지하고 대회 입력·제출물에 편입하지 않는다. 현재의 자료 조사 자체가 원자료 배포 권한을 뜻하지 않는다.

## 3. 분할과 평가 자료의 상태

### 3.1 기존 프레스: 재현 가능한 탐색 비교

기존 A/B 분할·동결 v1/v2를 유지해 비교 기준을 보존한다. 새 정상 시간순 분할을 보조로 만들 수 있지만 이미 전체 자료를 본 상태라는 사실을 바꾸지 않는다. 같은 A/B의 이상 결과를 독립 반복처럼 평균내어 표본 수를 늘리지 않는다.

모델·문턱 선택은 지정한 개발 부분에서만 한다. 현재 이상 파일을 모델 선택에 사용했으면 그 사실을 기록한다. 지도 모델의 이상 21기록 leave-one-record-out 결과는 같은 파일 내부의 보간 성능으로 다루고 새 고장 일반화라고 하지 않는다.

### 3.2 외부: 회차·개체를 먼저 분리

| 데이터 | 계획한 분할 | 중요한 누수 점검 |
|---|---|---|
| UCI | 목표 조건 정의 후 조건/연속 수집 블록 분리 | 같은 주기의 다른 창을 나누지 않음. 기존에 본 자료임을 표시 |
| SKAB | 실험 파일/고장 유형 그룹으로 개발·보정·시험 분리 | 각 파일의 시작부를 자동 정상으로 가정하지 않음. 전체 라벨을 보고 적응하지 않음 |
| AI4EU | 날짜/운전 패턴으로 분리 | 같은 burst의 진동 행과 보간된 저속 센서를 중복 사례로 세지 않음 |
| PHM | 공식 개체 구분 우선, 개발 개체 내부에서 설정 선택 | 목표 정상 참조와 목표 이상 평가를 구분 |
| Beihang | 원 시험 회차·조건 조합으로 분리 | 비동기 채널 정렬이 미래를 쓰는지, 같은 물리 고장 부품이 양쪽에 있는지 |
| Paderborn | 베어링 개체 분리 후 조건별 비교 | 같은 베어링의 4초 기록들을 독립 설비로 취급하지 않음 |
| MIMII DUE | 공식 section·source/target 구조 | 같은 공식 데이터의 재배포본 중복 방지 |
| ESPset | `esp_id` 그룹으로 분리 | 스펙트럼 행 무작위 분할로 같은 개체가 섞이지 않음 |

외부 결과의 의미도 두 가지로 구분한다. **같은 알고리즘을 외부 자료의 정상으로 재학습**하는 것은 방법의 적용 가능성 평가다. **프레스에서 학습한 가중치/문턱을 그대로 이식**하는 것은 직접 전이 평가다. 둘의 결과를 혼용하지 않는다.

새 외부 자료를 선택하면 미리 분할 ID를 고정하고, 최종 시험 부분은 모델·증강·문턱 선택에서 제외한다. 시험 결과를 보고 수정하면 그 자료는 개발 자료로 상태를 변경하고 새 독립 검증 필요성을 남긴다.

### 3.3 증강·합성 자료

원기록 분할 → 학습 부분의 전처리·생성기 적합 → 학습 증강의 순서다. 보정·주 시험에는 실제 자료를 쓴다. 합성 평가는 별도 표로 둔다. 세부 비교군 U0~U5와 원본 계보는 [증강 계획](04_augmentation_plan.md)을 따른다.

## 4. 공통 지표와 분모

| 지표 | 정의·보고 방식 | 해석 제한 |
|---|---|---|
| 행 precision/recall/F1 | 고정 문턱, 실제 TP/FP/FN과 함께 | 양성 비율이 다른 A/B·외부 자료를 직접 순위화하지 않음 |
| AP 및 PR 곡선 | 문턱 변화에 따른 순위 품질 | 양성 비율 함께 표시. AP와 사다리꼴 PR 면적을 구분 |
| AUROC | 보조 순위 지표 | 불균형에서 이것만으로 판단하지 않음 |
| 기록 FPR | 경보가 한 번 이상 난 정상 기록 / 정상 기록 | 기록 길이·상태별 분모 함께 표시 |
| 사건 탐지율 | 시간창 안에 잡힌 실제 독립 사건 / 전체 사건 | 기록 21개를 고장 사건으로 바꾸지 않음 |
| 지연 | 정의한 시작점 이후 첫 탐지 시각 | 기록 시작, 라벨 변화점, 실제 고장 발생을 구분 |
| 확인 부담 | 점검/계측 확인/유보 요청을 포함한 알림 수 | 이름을 바꾼 경보도 포함 |
| 시간당 부담 | 정의한 관측 노출시간 대비 요청 수 | 미관측 공백을 정상 모니터링 시간으로 채우지 않음 |
| 최악 조건 | 상태·길이·개체·고장 종류별 오류 | 작은 분모와 판정 불가를 숨기지 않음 |
| 계산 비용 | 목표 장비의 추론시간·메모리·학습시간 | 측정 전에는 추정으로 표시 |

Point adjustment는 주 결과에서 사용하지 않는다. 사건 전체 중 한 점을 맞혔다고 모든 행을 정답으로 바꾸지 않는다. 이벤트 보조 지표는 정의와 허용 지연을 별도로 적는다. 평가 설계의 근거는 [AAAI 2022 원문](https://cdn.aaai.org/ojs/20680/20680-13-24693-1-2-20220628.pdf)이다.

미탐 사건은 지연 요약에서 사라지지 않도록, 일정 시간 이내 탐지 비율과 미탐 수를 먼저 제시한다. 탐지된 사건만의 중앙 지연은 보조로 둔다. 실제 고장 전 이력이 없는 프레스에서는 “고장 ○초 전 예측”을 계산하지 않는다.

시간당 부담을 계산한다면 관측시간 정의도 고정한다. `표본 수 × 0.1초`의 명목 노출시간과 각 기록의 마지막−첫 시각 합계는 같지 않다. 첫 관측의 노출구간과 길이 1 기록의 처리를 명시한다. 벽시계 77분 전체를 연속 정상 감시 시간으로 사용하지 않는다.

## 5. 문턱·확률·경보 정책의 검증

### 5.1 유한 보정 자료가 허용하는 해상도

큰 점수가 더 이상한 점수라고 할 때, 정상 보정 점수 `s_i`가 n개인 기본 순위 p값은 다음 형태다.

`p(s) = (1 + #{i: s_i ≥ s}) / (n + 1)`

여기에는 학습/보정 분리와 적절한 교환가능성 같은 전제가 있다. 종속 기록·조건 이동·반복 관찰에서 어떤 보장을 쓰는지 따로 확인한다. 참고: [Bates 등 원문](https://arxiv.org/html/2104.08279), 특히 주변 보장과 고정 보정셋 조건부 오차율의 구분.

현재처럼 n=120이면 최솟값은 `1/121 ≈ 0.826%`다. 이를 1만 개로 증강해도 실제 독립 보정 자료가 증가하지 않으므로 그 해상도를 정당하게 높인 것이 아니다. 상태별로 나누면 각 상태의 n은 더 작아진다.

### 5.2 작업자 경보 예산과 검정 확률은 다르다

아래는 **연속 운전·정해진 검사 간격·유효한 정상 p값을 가정한 산술 예시**다. 현재 프레스의 관측 실적이나 현장 보장이 아니다.

| 가정 | 8시간 검사 횟수 M | 기대 거짓 경보 3개에 대응하는 `α ≤ 3/M` | 기본 p값이 그 수준에 도달할 최소 n |
|---|---:|---:|---:|
| 5초마다 검사 | 5,760 | 약 0.0521% | 1,919 |
| 10초마다 검사 | 2,880 | 약 0.1042% | 959 |

마지막 열은 순위 p값의 **해상도 조건**일 뿐 충분한 안정성이나 독립성의 증명이 아니다. 유효한 주변 확률이라도 기대값 제한이 매 교대의 확정 상한은 아니다. 알림 묶기·재알림 정책을 쓰면 그 정책 전체의 단위와 경험적 부담을 검증한다.

모델 3개 각각 α로 경보를 내고 OR 결합했다면 최종 경보율을 α라고 부르지 않는다. 전체 결합 점수를 정상으로 보정하거나 명시적인 다중 비교 처리를 설계한다.

### 5.3 기록 길이와 상태

기록 최대값은 기록이 길수록 커질 수 있다. 전체 길이 혼합에서의 보정과 길이별 보장은 다르다. 길이 구간별 FP/분모를 우선 표시하고, 자료가 충분할 때에만 길이 조건부 문턱을 비교한다. 동일 최대 관측 길이의 비교와 전체 실제 길이의 비교를 구분한다.

### 5.4 확률

정상 p값과 제공 라벨 확률을 별도 출력한다. 현장 고장 확률은 독립 사건·유병률·검증 자료가 없으므로 확정하지 않는다. 보정 전후 Brier/log loss와 reliability 표는 분모·분할을 붙인 내부 진단으로만 사용한다.

증강으로 클래스 비율이 바뀌면 그 비율이 그대로 현장 확률에 들어갈 수 있다. 실제 검증 자료로 보정하고, 원래 유병률이 알려져 있지 않으면 가정별 민감도로만 제시한다. 임의의 사전확률을 정답처럼 쓰지 않는다.

## 6. 불확실성은 실제 독립 단위로 계산한다

외부 자료에 독립 회차·개체가 충분하면 그 그룹 단위 bootstrap 또는 조건에 맞는 구간 추정을 사용한다. 행·겹치는 창을 독립으로 bootstrap한 좁은 구간은 사용하지 않는다. 한 파일 내부 블록 재표본화는 해당 파일 안의 변동을 볼 뿐 새 고장 간 변동을 추정하지 못한다.

자료가 작으면 추정치를 내지 못하는 항목을 그대로 표시한다. “3개 FP가 2개가 됨”은 기술적으로 보고할 수 있지만 일반화된 개선이 유의하게 입증됐다고 단정할 수 없다.

계획 규모를 생각하기 위한 별도 예시로, 독립 사건 n개를 모두 탐지했을 때 단측 95% 이항 하한은 `0.05^(1/n)`이다. 약 29개의 독립 사건을 모두 탐지해야 이 하한이 90%를 넘는다. 현재 21개 기록에 이 계산을 적용하지 않는다. 이 예시는 사건 독립·동일 성공 확률을 가정하며 여러 고장 종류의 포괄성을 보증하지 않는다.

거짓 알림이 0개일 때에도 위험이 0은 아니다. 동질 Poisson 과정을 가정하면 발생률의 단측 95% 상한은 약 `2.996/T`다. 이 가정 없이 짧은 무경보 구간을 하루 성능으로 확대하지 않는다. 이러한 산술 예시는 수집 규모 논의용이며 현재 자료에 맞는 통계 모형을 확인한 결과가 아니다.

## 7. 비교 모델과 탐색 예산

| 순서 | 비교군 | 선택 이유 | 초기 탐색 범위 제안 |
|---|---|---|---|
| 필수 1 | 동결 v1/v2 | 기존 성능·실패조건 보존 | 변경 없음 |
| 필수 2 | robust 크기/단순 rule, PCA 또는 shrinkage 거리 | 간단한 모델이 충분한지 | 정상화·특징군 소수만 비교 |
| 필수 3 | logistic와 얕은 boosting 중 최소 하나 | 라벨 확률·지도학습 비교 | 정규화 강도/복잡도 3~6개 수준 |
| 주력 경쟁 | A 조건화, B 빠름/느림, C 관계 | 각기 다른 실패 원인을 해결 | 후보별 최대 6설정, 개발 자료에서만 선택 |
| 증강 비교 | U0~U4, 필요 시 U5 | 모델 변경과 증강 효과 분리 | 고정 모델 하나로 시작 |
| 외부 확장 | D 정상 참조 적응 | 새로운 환경에 대한 질문 | 참조량·적응 대상 분리 |
| 조건부 도전자 | 작은 시계열/사전학습 한 종류 | 특징 가정 밖의 대안 | 입력 적합성 통과 후 최대 1계열 |

파라미터 숫자는 검색 제한을 위한 초안이다. 최종 목록을 실행 전 고정한다. 무한 탐색의 최고 점수를 내세우지 않는다. 확률적 모델의 seed 반복은 후보를 좁힌 뒤 예를 들어 3회로 설정하고 전부 보고한다. 실패한 실행도 원인과 함께 남긴다.

같은 특징 비교와 원래 모델 전체 비교를 나눈다. 동일한 입력만 준 실험은 결합 방식의 효과를, 각 모델 고유 특징을 허용한 실험은 시스템 전체의 효과를 답한다. 가이드북의 다른 창·분할로 얻은 수치와 새 모델 수치를 그대로 우열 표로 놓지 않는다.

## 9. 인공 시험은 세 가지로 나눈다

1. **표현 통제:** 같은 물리값의 파일 형식·저장 표현 차이. 반올림/양자화로 값이 바뀌면 변화량도 표시한다.
2. **가정한 외란 민감도:** gain·offset·시간 흔들림 등. 실제 정상 변화일 수도 고장일 수도 있으므로 정상 라벨을 자동 부여하지 않는다.
3. **합성 이상:** jump·ramp·진동 증가·관계 붕괴. 정의한 신호 변화의 감도와 지연을 평가한다.

주입 시작점은 관측 시점으로 명시하고, 기록 시작에 이미 존재하는 변화와 중간에 생기는 변화를 나눈다. 기존 E1의 특정 주입 결과를 새 방법에 유리한 강도만 고르는 데 사용하지 않는다. 모든 주입의 원기록 ID·강도·시점·seed·목적을 남긴다.

## 14. 현장 확장 시 수집·운영 계획

### 수집 설계

먼저 계측 설정·단위·필터·동기화·펌프 모델을 확인한다. 이후 다른 날짜, 시동/정상 운전/조건 전환/정지, 서로 다른 제품·금형·유온·부하를 포함하도록 수집 범위를 설계한다. 예를 들어 3일×4조건×3회차는 탐색 설계의 출발점일 뿐 충분한 정상 표본 수의 증명이 아니다.

가능한 추가 변수는 PLC 단계·압력·유온·속도·유량·정비 이력이다. 고장 라벨은 알림 발생 여부가 아니라 점검 결과·부품 상태·교체 전후·담당자 확인으로 단계별 확정한다. 새 실제 사례의 확보 가능성이 확인되기 전에는 대회 일정의 필수 의존성으로 두지 않는다.

### 현장 담당자에게 확인할 질문 목록

- 이상을 놓치면 어떤 조치가 늦어지고 비용·위험이 어떻게 달라지는가?
- 경보 1건의 확인에는 몇 분이 들며 실제 확인할 센서·장치는 무엇인가?
- 시동·금형 교체·유온 상승·부하 전환 중 정상적으로 큰 변화가 있는가?
- 정비·센서 교체·PLC 설정 변경을 언제 어떤 형식으로 기록하는가?
- “확인된 정상”을 누가 어떤 근거로 승인할 수 있는가?
- 자동 판단이 어려울 때 추가 관측과 점검 중 어느 조치가 적절한가?

이번 작업에서는 인터뷰나 연락을 하지 않았다. 목록은 이후 현장 협업이 가능할 때의 조사 설계다.

### 도입 단계

과거 기록 재생 → 실제 운전의 관찰 모드 → 작업자 확인을 동반한 경보 검토 → 조건별 인수 판단 순서로 검토한다. 현재 근거에서 자동 정지·PLC 제어를 기본 범위로 넣지 않는다. 점검 결과가 없는 낮은 점수 자료를 자동 정상 재학습 자료로 흡수하지 않는다.

비용 평가는 `FP 확인 비용 + FN 영향 + 지연 영향 + 계측·유지 비용`의 가정별 민감도로 시작한다. 실제 빈도·비용을 알기 전 연간 절감액을 제시하지 않는다. 대시보드의 기능 수보다 경보 이후 의사결정이 명확한지를 검토한다.

## 15. 계획 완료 후의 정지점

이번 단계의 완료 기준은 **출처를 추적할 수 있는 조사 목록, 여러 경쟁 접근, 증강 대안, 실행 가능한 검증 순서와 판단 기준**을 팀이 검토할 수 있는 형태로 제공하는 것이다.

사용자의 피드백으로 우선순위를 조정할 수 있다. 다만 계획 문서의 완성, 내부 검토 통과, 남은 시간 계산을 다음 작업의 실행 허가로 해석하지 않는다. 구현·학습·실험·추가 데이터 취득·대회 보고서 작업은 이후 지시를 기다린다.
