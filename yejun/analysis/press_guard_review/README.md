## 2. 코드·방법 검토에서 남긴 것

- **향상의 출처.** v2의 남은 미탐은 A 44행 중 26행, B 31행 중 20행이 구간 위치 0·1에 몰려 있다. 그 위치에는 센서 크기 성분만 있고 AR(2) 잔차(위치 2부터)·짧은 파형(위치 5부터)이 없다. 미탐 감소 55행 중 위치 2~6의 개선은 A 49행·B 51행이고, 위치 10 이후에서도 A 6행·B 4행이 개선됐다. 위치 0·1은 v1과 같다.
- **교락 해석.** AR(2) 잔차는 정상 학습일의 전류 동역학과의 차이를 잰다. 이상 자료가 다른 날의 기록이라는 기존 교락(정상 하루·이상 하루)은 그대로이고, 새 성분이 그 날 차이에 더 민감할 가능성을 배제할 수 없다. 롤링 5구간은 정상 날의 오경보 쪽만 확인한다. 후보 5개는 v1의 초반 미탐 분석을 본 뒤 설계했고 같은 이상 21구간으로 골랐다(코덱스도 명시). "더 이른 고장 탐지"가 아니라 "기록 시작 뒤 더 이른 경보"다.
- **v1 배치 민감성 주장.** 코덱스는 v2에서 BLAS 배치 크기에 따른 사인 잔차 차이를 고정했다고 했다. v1을 확인하면 이상 600행을 단독 추론한 결과와 정상 평가와 이어 붙여 추론한 결과가 600/600 행 완전히 같았다(차이 0). v1은 파일 단위 추론만 지원하므로 v1 수정은 필요 없다.
- **`waveform_window` 열**은 위치 0~4에도 6을 적는다. 그 위치에는 파형 점수가 없다(NaN). 표시용 열이라 결과에 영향은 없고 그대로 두었다.
- **`GuardModel.load`는 v1 패키지 전체 코드 해시(run_all.py 포함)와 일치를 요구한다.** v1의 어떤 파일이 바뀌어도 v2 모델은 재학습해야 한다. 안전한 쪽의 설계이므로 유지한다.
- **외부 검증 코드.** 조건별 정상 사이클을 원래 순서로 60/20/20, 누설은 시험 전용, 학습·보정·시험 집합의 서로소 검사와 정상 라벨 검사가 있다. 환경 이동 모드의 시험 집합은 해당 냉각 조건의 안정 사이클 전부(정상 포함)이며 그 모드의 학습·보정과 겹치지 않는다. 결과를 바꾸는 오류는 없다. 코덱스의 결론(환경 이동 시 무너짐, 냉각 3에서 누설 다수 미탐, 좋은 조건만 고르지 말 것)은 표와 일치한다.
- **`train.py`의 코드 해시 목록**이 `*.py` 전체 glob이어서 이번에 추가한 파일이 섞이게 되므로 결과를 낳는 4개 파일로 고정했다. manifest만 다시 생성했고 다른 산출물은 바이트 동일하다.

기록해 둘 설계 비용: `CODE_FILES`에 웹·CSS·재현 스크립트까지 들어 있어 화면 문구 하나를 고쳐도 학습→분석→audit→재동결(약 40초)을 다시 해야 한다. 코덱스의 "커밋된 패키지 전체가 검증된 상태"라는 원칙에 동의해 유지한다. audit.py는 실행할 때마다 `audit.json`·`manifest.json`을 다시 쓰므로 검수 목적의 재실행 후에는 Git 변경을 되돌린다.
