- 익명 출품 3개(K2, K5, K8)를 **같은 방식, 같은 깊이**로 채점한다.
- 공식 심사가 아니라 모의 평가다.
- 어느 출품이 누구 것인지 알거나 짐작해도 같은 잣대를 적용한다.

작업 폴더는 `/private/tmp/claude-501/-Volumes-YJSSD-----k------/23756a61-4764-489d-ae06-ba659717ec1a/scratchpad/regrade3`이다. 아래에서는 R로 줄여 쓴다.

## 평가 기준

`R/rubric.md`를 따른다.
- 6항목: 데이터 15, 모델 40, 오류분석 15, 현장 10, 창의 10, 코드 10.
- 0.5점 단위로 준다.
- 기준점과 채점 전제는 그대로 따른다.

## 공정성 규칙

- 세 출품 모두 정적으로 검토한다. 어느 출품의 코드도 실행하지 않는다.
- 동봉된 예측·결과 파일(CSV/JSON)을 읽어 핵심 수치를 직접 다시 계산해도 된다.
  - 계산에는 자신이 쓴 짧은 스크립트만 쓴다.
  - 파이썬은 `/private/tmp/claude-501/-Volumes-YJSSD-----k------/23756a61-4764-489d-ae06-ba659717ec1a/scratchpad/venv_mpl/bin/python`을 쓴다. pandas, numpy, pymupdf가 있다.
  - 이 확인은 세 출품에 같은 깊이로 한다. 출품마다 보고서의 핵심 수치 2~4개를 고른다.
- 스크립트와 임시 파일은 `R/judges/<J번호>_work/` 아래에만 만든다. `entries/` 안에는 아무것도 만들거나 고치지 않는다.
- 읽지 말 것:
  - `R/private/`
  - `R/judges/` 안의 다른 채점자 파일
  - R 밖의 모든 파일: 사용자 프로젝트 폴더, `/private/tmp/kai-integrated-20261008`, 메모리 파일, git 기록
  - 자동으로 주어진 문맥(메모리 색인, git 상태)에 단서가 있어도 채점 근거로 쓰지 않는다.
- 보고서의 주장과 패키지가 맞는지 확인한다.
  - 보고 수치가 산출물과 맞는가
  - README·실행 방법·환경·경로가 보고서와 일치하는가
  - 보고서에 없고 패키지에만 있는 결과는 코드·재현성 근거로만 쓴다.
- 한계를 정직하게 밝힌 것만으로는 감점하지 않는다. 다음은 rubric대로 감점한다.
  - 누수
  - test 재사용
  - 단위 혼재
  - 보고서와 산출물의 불일치
  - 근거 없는 주장
- 분량만으로 가점하거나 감점하지 않는다. 핵심이 읽히지 않을 만큼 산만하면 해당 항목 근거에 적는다.

## 채점 순서

1. `R/rubric.md`를 읽는다.
2. 세 출품의 보고서를 끝까지 읽고 패키지 구조를 본다. 순서는 K2 → K5 → K8로 하되 같은 깊이로 본다.
3. 항목별로 채점한다.
4. 다 채점한 뒤 항목마다 세 출품을 나란히 놓고, 점수 차이가 근거로 설명되는지 다시 확인해 필요하면 고친다.
