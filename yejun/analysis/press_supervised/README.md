# 라벨 지도학습 기준선 — 최종모델이 이상 라벨을 학습에 쓰지 않는 이유 (2026-09-27, v2)

흔한 제출물처럼 정상·이상 라벨로 분류기를 학습하면 어떻게 되는지를 최종모델 v2(이상 라벨 미사용)와 같은 행·같은 문턱 규칙·같은 주입 조건에서 비교했다. 설계는 [protocol.json](protocol.json)(v2)이다. **대회 보고서가 아니다.**

- v1(`dcd300a`)은 v2의 파형·예측 오차 특징이 없는 창 특징만 썼다. 문턱도 0.5와 사후 최적값만 썼다. 루브릭 사이클2 평가관 02(M2)·05(O5·O6)의 지적대로 v2 성분 특징과 conformal 문턱을 더했다. 교차검증은 21겹을 더했고, 클래스 가중 변형과 주입 반복 5회도 더했다. 평가관이 같은 조건으로 계산한 수치를 먼저 보았으므로 사전 고정 실험이 아니다.
- **정상 학습·보정·평가 구간은 v2와 같다**(A: 0~359 / 360~479 / 480~599, B: 0~299 / 300~419 / 420~599). 정상 평가 행은 어느 지도학습 모델의 학습에도 쓰지 않는다.
- **특징:**
  - `window`: 창 특징 22개(센서별 값, 최근 3·8행 평균·표준편차, 1차 차분, 위치)
  - `window_plus_v2`: 창 특징 + 같은 분할 v2 모델(정상 학습만으로 적합)의 성분(크기 max|z|, 전류 예측 오차, 세 성분 꼬리 점수)
- **모델:** 로지스틱, HistGradientBoosting, 각각의 `class_weight="balanced"` 변형
- **문턱:** `conformal`은 정상 보정 기록구간의 최대 확률(α=1%, v2와 같은 규칙)이다. `0.5`와 사후 최적(평가 라벨 사용, 참고)도 함께 적는다.

## 1. 흔한 평가: 무작위 행 분할 — [random_rows.csv](random_rows.csv)

| 특징 | 모델 | F1 |
|---|---|---:|
| 창 특징(matched) | 부스팅 / 가중 부스팅 | 0.924 / 0.938 |
| 창 특징(matched) | 로지스틱 / 가중 로지스틱 | 0.662 / 0.283 |
| **저장 소수 자릿수(AI0 하나)** | 부스팅 | **0.994** |
| 저장 소수 자릿수(세 센서) | 부스팅 | 0.997 |

센서 값을 보지 않고 CSV의 저장 소수 자릿수만으로 F1 0.994가 나온다(정상·이상 파일의 저장 형식 차이). 무작위 행 분할은 같은 기록구간의 이웃 행도 학습·평가에 나눠 넣는다. 이런 평가의 높은 F1은 설비 상태를 배웠다는 근거가 되지 못한다.

## 2. 엄격한 평가: 이상 기록을 떼어 낸 교차검증 — [grouped_records.csv](grouped_records.csv)

이상 21구간을 1구간씩(21겹) 또는 7구간씩(3겹) 떼어 내고, 떼어 둔 구간은 그 겹의 모델과 그 문턱으로 예측한다. 아래는 21겹, conformal 문턱의 F1이다(괄호는 미탐 행 / 정상 알림 구간).

| 특징 | 모델 | A | B |
|---|---|---|---|
| 창 특징 | 부스팅 | 0.890 (119 / 0/120) | 0.886 (123 / 0/180) |
| 창 특징 | 로지스틱 | 0.598 (344 / 0) | 0.592 (348 / 0) |
| 창 + v2 성분 | 부스팅 | 0.915 (94 / 0) | 0.974 (30 / 0) |
| 창 + v2 성분 | 로지스틱 | **0.973** (32 / 0) | **0.972** (32 / 1) |
| **v2(이상 라벨 미사용)** | α=1% | **0.962** (44 / 0) | **0.971** (31 / 3) |

- **같은 입력(v2 성분)과 같은 문턱 규칙이면 대회 이상 21구간의 F1로는 지도학습과 v2가 구분되지 않는다.** 지도학습 − v2의 F1 차이는 −0.047~+0.011이고, 지도학습 로지스틱이 조금 높기도 하다.
- 3겹(7구간씩)은 학습 이상 자료가 줄어 지도학습이 대체로 낮아진다: 창 특징 부스팅 0.723·0.718, 창+v2 로지스틱 0.967·0.966.
- 사후 최적 문턱(평가 라벨로 고른 낙관적 상한, 21겹)에서 창+v2 지도학습은 0.970~0.975다.
- 창 특징만 쓴 지도학습의 낮은 F1(0.59~0.89)은 방식 차이가 아니라 특징 차이 때문이다.

## 3. 라벨에 없는 고장 모양으로의 전이 — [injection.csv](injection.csv)

두 분할 각각 정상 학습 + 이상 21구간 전체로 학습한 지도학습 모델을 보완 실험 E1과 같은 주입에 적용했다. 주입은 시작 1초 뒤 계단형이고, 대상은 길이 30행 이상의 정상 평가 기록이다. 잡음 족은 반복 5회를 평균했다. 수치는 2초 안 탐지율이고 A / B 순서다(conformal 문턱).

| 주입 | v2 | 창+v2 로지스틱 | 창+v2 부스팅 | 창 부스팅 |
|---|---|---|---|---|
| 진동 잡음 2σ | **74% / 94%** | 7% / 8% | 0% / 0% | 41% / 48% |
| 진동 잡음 4σ | **100% / 100%** | 86% / 87% | 12% / 10% | 100% / 100% |
| 전류 잡음 0.1σ | 95% / 97% | 87% / 79% | 95% / 92% | 1% / 1% |
| 전류 오프셋 0.2×진폭 | 40% / 52% | 8% / 9% | **61%** / 39% | 0% / 0% |
| 전류 오프셋 0.4×진폭 | 100% / 100% | 99% / 90% | 92% / 98% | 3% / 5% |
| 전류 배율 1.5 | 72% / 83% | 64% / 55% | 64% / 71% | 3% / 3% |
| 주입 없음(오경보) | 0% / 1% | 0% / 0% | 0% / 0% | 0% / 0% |

- **전류형 고장:** v2 성분을 넣은 지도학습도 v2와 비슷하게 잡는다. 일부 약한 세기에서는 지도학습이 더 높다(오프셋 0.2 A, 전류 배율 0.5 A 등, 표 전체는 CSV).
- **진동만 커지는 고장:** 지도학습이 크게 못 미친다(4σ에서 부스팅 10~12%). 학습에 쓴 이상 날에는 전류 성분이 늘 함께 튀었기 때문에, 지도학습은 진동 증거를 거의 쓰지 않도록 맞춰졌다. v2는 세 성분 중 하나라도 정상 기준을 넘으면 경보하므로 라벨에 없는 모양에도 반응한다.
- **창 특징만 쓴 지도학습:** 전류형 고장을 거의 놓친다.
- **가중 로지스틱(창 특징, 문턱 0.5):** 주입 없이도 A 91%·B 84%에서 경보해 쓸 수 없다(O6).

## 4. 최종모델 선정근거로서의 결론

1. **F1 우위가 아니다.** 같은 입력과 같은 문턱 규칙이면 대회 F1은 지도학습과 같다(0.96~0.97). "지도학습보다 F1이 높다"고 말하지 않는다.
2. **전이.** 한 날의 이상에 맞춘 지도학습은 그날 없던 모양(진동형 고장)을 놓친다. v2는 정상 운전 규칙에서 벗어나는 정도만 보므로 모든 성분의 이탈에 반응한다.
3. **라벨 불필요와 재보정.** 현장에는 고장 라벨이 드물다. v2는 정상 자료만으로 학습·보정하므로, 새 날짜·설비에서도 같은 절차([recalibrate.py](../../press_guard/recalibrate.py))로 다시 맞출 수 있다.
4. **해석성.** v2의 경보는 넘은 성분이 늘 있어 근거→조치 판단표로 이어진다.
5. **흔한 평가의 함정.** 무작위 행 분할의 높은 F1(0.92~0.99)은 저장 형식과 기록 내 이웃 행 공유로 부풀려진다.

## 한계

- 이상 21구간은 한 날 3분의 연속 기록이다. 교차검증과 주입 시험 모두 독립 고장 검증이 아니다.
- 지도학습 초모수는 조정하지 않았다(기본값).
- 주입은 인공 신호다. 진동형 고장이 실제로 이런 모양으로 온다는 보장은 없다. 다만 가이드북 7쪽은 기어 마모 시 진동·소음이 심해진다고 적는다.

## 재현

`yejun/`에서 실행한다(PowerShell은 첫 줄 대신 `$env:OMP_NUM_THREADS=1; $env:PYTHONDONTWRITEBYTECODE=1`). 시간은 이 기기(Apple M2) 실측이다.

```bash
export OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1
python analysis/press_supervised/run.py                                     # 약 2.5분(140초), 결과를 이 폴더에 쓴다
python analysis/press_supervised/run.py --out <폴더>                        # 다른 폴더에 다시 만들기
python analysis/package_contract.py --package analysis/press_supervised     # 실행 기록 무결성 + 동결 기대값 비교
python analysis/package_contract.py --package analysis/press_supervised --out <폴더>   # 다시 만든 결과를 동결값과 비교
python -m pytest -q analysis/press_supervised/test_contract.py              # 변조·삭제 검출
```

입력·코드·의존 파일(E1 요약, press_guard model.py, 동결 guard_A/B)·산출물 해시는 [manifest.json](manifest.json)에 있다. 공용 검사기 [package_contract.py](../package_contract.py)가 [contract.json](contract.json)에 따라 이 기록을 현재 파일과 대조하고, 결과 CSV 3개를 [expected/](expected)의 동결값과 비교한다(수치 허용오차 1e-9, 평가관 06 R8). 의존 파일(E1 요약·v2 모델)이 바뀌면 다시 실행해야 통과한다.
