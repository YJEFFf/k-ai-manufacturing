## 2. 직접 전수 확인: ID 59 기계부품 품질보증

검사 파일: `Dataset_기계부품 품질보증 AI 데이터셋.zip` 내부 `data/raw_total_data.csv`, `data/실습데이터.csv`.

- raw 파일은 **579,297행 × 58열**이다. 저장 인덱스 열을 제외하면 57열이다.
- 실습 파일은 **579,297행 × 57열**이다. 두 파일 모두 2022-05-02 06:32:33부터 2022-05-14 04:34:46까지, 실제 12개 날짜를 포함한다.
- 타임스탬프는 전체 행에서 유일하며 오름차순이다. 연속 행 간 1초 간격은 574,213회이고 더 긴 공백도 있다. 단순히 579,297행을 연속 등간격 신호라고 취급하면 안 된다.
- raw 파일의 결측은 **26,053,030셀**이다. 실습 파일은 결측 0셀이다.
- raw 파일에서 저장 인덱스를 제외하고 **이전 값으로 채운 결과(`ffill`)가 실습 파일의 33,019,929셀 전체와 정확하게 같다.** 두 파일은 독립적인 학습·검증 데이터가 아니다.
- 전체 행 중복은 타임스탬프가 있으므로 두 파일 모두 0이다. 인덱스·타임스탬프를 제외한 센서/설정 벡터 중복은 raw 37행, 실습 9행이다.
- 실습 자료에는 모든 값이 0인 전류·위치·경보 열도 있다. 데이터 용량과 센서 이름 수가 실제 유효 정보량을 뜻하지 않는다.

### 경보를 고장 정답으로 쓰면 생기는 문제

`MAIN_MOTOR_ALM.xlsx != 0`은 58,302행이다. 다만 이는 **직접 읽은 경보 값이지, 가이드와 정비 기록으로 확인한 고장 정답이 아니다.** 이 값으로 양성/음성을 정의해 구조를 조사했다.

| 경보가 유지된 구간 | 행 수 | 첫 시각 | 끝 시각 |
|---|---:|---|---|
| 1 | 49,283 | 2022-05-06 14:38:02 | 2022-05-07 04:24:51 |
| 2 | 9,019 | 2022-05-09 06:31:31 | 2022-05-09 09:02:02 |

수만 개 양성 행이 있어도 연속 경보 구간은 두 개뿐이다. 고장 사건 수, 수리 횟수 또는 수만 개의 독립 고장 사례로 세면 안 된다.

반대로 단순 시간 순서 80:20 분할의 마지막 20%인 **115,860행에는 이 경보 양성이 0개**다. 무작위 분할을 시간 분할로 바꾸기만 해도 문제가 끝나지 않는다. 모든 사건이 학습 기간에 몰려 있으면 테스트에서 고장 탐지율을 검증할 수 없으므로 사건 배치와 정상 감시 구간을 따로 설계해야 한다.

더 결정적으로 다음 두 조건은 `MAIN_MOTOR_ALM.xlsx != 0`과 **579,297행 전부 일치**한다.

1. `KO1_MOTOR_INVERTER_ALM.xlsx == 8995`
2. `CUTTING_INVERTER_ALM_ERR_CD.xlsx == 8995`

따라서 이런 동시 경보 열을 입력으로 넣고 메인 경보를 거의 완벽하게 예측해도, 경보가 뜨기 **전에** 고장을 예측했다는 증거가 아니다. 한 시점에 같이 기록된 경보를 복사한 결과일 수 있다. 무작위 행 분할은 같은 경보 구간을 양쪽에 나누므로 독립 사건 검증도 하지 못한다.

③ 원자료를 보강하려면 이 자료의 가치가 높은 부분은 **같은 시점 경보 제거, 시간 순서 분할, 경보 전 구간의 특징만 사용, 경보 사건 단위 평가**라는 검증 설계다. 현재 확인한 내용으로 펌프에 대한 새로운 실제 고장 검증셋을 확보했다고 말할 수 없다.

추가로 원구축 수행기관의 2022년 12월 [제조AI데이터셋 16종 구축 완료보고서](https://www.alio.go.kr/download/download.json?fileNo=2798483) 기계부품 요약에는 현업 전문가가 정상·비정상을 판정해 라벨링할 필요가 있다고 나온다. 이 공개 보고서는 확보했으나 개별 실습 가이드북 전체를 대체하지 않는다. 특히 위의 경보 값을 가이드북이 최종 정답으로 사용하는지는 별도로 확인해야 한다.

## 3. ID 23 장비이상 조기탐지: 전체 WAV 해시 중복

이름 붙은 `Dataset_장비이상 조기탐지 AI 데이터셋.zip`은 0바이트였으나 `미확인 761196.crdownload`에 실제 완성 ZIP이 있었다. 공정 CSV와 팬 WAV라는 구성, 용량이 공식 ID 23 설명과 부합하므로 해당 데이터로 추정한다. 다운로드 출처 메타데이터는 없어 가이드북과 최종 대조가 필요하다. 중앙 검사에서 내부 217항목의 CRC를 모두 통과했고, 내용은 공정 CSV 34개와 WAV 183개이다. 압축 해제 총량은 1,940,389,060바이트이나 디스크에 전체를 추출하지 않았다. WAV 개별 SHA-256은 압축 내부의 원본 전체 바이트를 읽고 계산한 값이다.

| 폴더 기준 구분 | WAV 파일 수 | 원본 바이트 전체가 서로 다른 파일 수 |
|---|---:|---:|
| `FAN_sound_OK` | 170 | **30** |
| `FAN_sound_error` | 13 | **13** |
| 합계 | 183 | **43** |

정상 파일 170개는 원본 30개가 각 5~7회 복제된 구성이다. 예를 들어 `FAN_sound_01.wav`, `50.wav`, `70.wav`, `81.wav`, `131.wav`는 전체 바이트 해시가 같다. 의미가 비슷한 소리가 아니라 **파일 내용 전체가 동일하다.** 복제 원인이 증강 목적이었는지, 배포 구성 때문인지는 확인하지 못했다.

실제로 파일을 계층화해 무작위 80:20 분할(`random_state=42`)하면 테스트 37개 중 **34개가 학습 파일과 전체 바이트가 같아진다.** 이때 테스트 정상 34개가 모두 학습에 이미 나온 소리이다. 이는 모델 성능 측정이 아니라 분할 누수 검사다. 정상/이상 분류기를 만들려면 SHA-256 그룹을 먼저 분리하고, 가능하다면 녹음 회차·실제 설비 상태별 독립성까지 확인해야 한다. 43개 고유 파일도 43개 독립 고장 사건을 뜻하지는 않는다.

이 추가 자료는 중복에 견디는 검증 방식을 비교하는 데 의미가 있지만, 많은 정상 파일 수나 높은 무작위 분할 점수를 ③ 유압펌프의 현장 성능 증거로 사용할 수 없다. 현재 음향 파형 자체의 주파수·샘플링·녹음 길이, 공정 CSV의 정답 연결은 아직 확인 전이다.

## 4. ID 45 로봇용접 예지보전: 이번에 재확인한 페이지의 범위

이 항목은 이전에 생성된 `/tmp/kamp_robot_guide_p10.png`, `p52.png`, `p53.png` 세 장을 직접 확인했다. **PDF 전체를 이번에 다시 읽은 결과가 아니다.** 파일명 숫자는 PDF 순서이고, 인쇄 페이지는 각각 9·51·52쪽이다.

- PDF 10쪽(인쇄 9쪽)은 수집 정상 데이터와 대시보드로 확인한 이상 데이터를 구분한다고 설명한다. 진동 입력은 주파수 영역 512개 값, 전류 입력은 주파수 영역 1,024개 값이다. 512개 값을 서로 다른 센서 512개로 해석하지 않는다.
- PDF 52·53쪽(인쇄 51·52쪽)의 평가는 진동 16개 정상+16개 이상, 전류 32개 정상+32개 이상이다. 그림에서 제시한 평가 집합은 각각 32개·64개이다.
- 보고된 완전 분리는 해당 가이드 실습 평가 집합에 대한 결과다. ③ 프레스 유압펌프에서 검증한 결과로 전용하거나 실제 고장까지 남은 시간(RUL)을 입증한 결과라고 표현할 수 없다.

## 5. ③의 수상 전략: 원자료 복구 후 판단할 핵심

아래는 최종 추천이 아니라 확인해야 할 논점이다. [KAMP 공식 ID 48 설명](https://www.kamp-ai.kr/aidataDetail?DATASET_SEQ=48)에 따르면 정상 20,000행, 이상 600행의 진동·전류 자료이고 가이드는 LSTM-Autoencoder를 사용한다. **공개 설명만으로는 이상 600행의 실제 고장 여부, 생성 과정, 정비 사건 수, 고장 시각을 확정할 수 없다.**

수상 경쟁력의 관건은 모델 이름을 바꾸는 것이 아니라 다음 질문에 답할 수 있는지다.

1. 정상 신호의 반복 작업과 비가동 구간을 이해하고, 정상 운전 조건이 바뀌어도 오경보를 줄일 수 있는가?
2. 이상 600행이 인공 주입이면 그 설정을 명시하고, 다른 이상 형태·강도에서도 견디는지를 분리 검증할 수 있는가?
3. 시간 창을 만든 뒤 무작위 분할해 동일 원신호가 학습·평가에 겹치는 누수를 차단할 수 있는가?
4. 간단한 범위 규칙, 변화량, 정상 기준 거리만으로 이미 풀리는지 확인한 뒤 복잡한 모델의 추가 가치를 보일 수 있는가?
5. 실제 고장 시각·수리 이력이 없다면 `이상탐지`로 범위를 정직하게 한정하고, RUL·실제 예방 정비 성과를 주장하지 않을 수 있는가?

**유망한 한 가지 주제:** `운전 상태 변화와 센서 이상을 구분하는 유압펌프 조기 경보 및 정비 우선순위 시스템`. 결과물은 경보 원인(진동·전류 기여), 경보 지속시간, 오경보 예산별 탐지 결과, 모델의 불확실성, 작업자가 확인할 항목을 함께 제시한다. 다만 실제 고장 라벨과 사건 전후 시간이 없다면 “조기” 성능은 입증 범위를 좁혀야 하며, 시스템 제안과 실제 검증 결과를 구분해야 한다.

**추천을 뒤집을 조건:** 이상 라벨이 실제 독립 고장 사건이고 시간 분할에서도 간단한 기준 대비 의미 있는 조기 탐지 개선이 확인되면 상위 후보가 될 수 있다. 반대로 이상이 단순 합성·정상 범위 밖 극단값이며 쉬운 규칙으로 거의 완벽히 분리된다면 모델 차별화 여지가 작아져 평가 순위를 낮춰야 한다. 추가 자료가 많다는 이유만으로 이 제약이 사라지지는 않는다.

## 6. 재현 자료

- `maintenance_audit.py`: 파일 내용을 디스크에 대량 추출하지 않고 CSV 전체를 검사. macOS dataless 파일은 명시적으로 건너뛴다.
- `maintenance_audit.json`: 열 목록, 결측, 고유값, 수치 분포, 중복, 날짜별 행 수, raw→실습 전체 일치 검사, 경보 구간 및 경보 열 간 정확 일치 결과.
- `maintenance_audio_hash_audit.py`와 `.json`: 장비이상 조기탐지 WAV 전체 파일의 해시 중복 그룹, 무작위 분할 시 학습·테스트 동일 파일 비율.
- `archive_checks.json`: 중앙 압축파일 전체 항목의 읽기·CRC 확인 결과.

현재 ③ 원자료를 실제 다시 읽기 전이므로 수상 확률 수치나 다섯 과제의 확정 순위를 이 문서에서 만들지 않는다.
