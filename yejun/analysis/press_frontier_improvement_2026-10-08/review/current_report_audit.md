# 기존 결과보고서 검수와 개선 판단 기준

검수일: 2026-10-08. 대상: `claude/report/final_v5.md`, 현재 61쪽 보고서의 Markdown 원본. 검수 원본 SHA-256: `77eb87b789646063f8885024bf55328d469fc6489eb2cf00fb96f32a50ca1c11`.

사용자가 기존 보고서 보존과 별도 복사본 개선을 명시적으로 요청했다. 이 기록 작성 시 기존 보고서·코드·데이터는 읽기만 했고, 새 개선 디렉터리만 작성했다. 기존 `yejun/AGENTS.md`의 보고서 착수 보류는 이번 명시적 작성 지시로 해제된 범위에서 해석한다. 준용의 `claude/` 원본은 계속 읽기 전용이다.

## 1. 판단 요약

현재 보고서는 데이터 진단·오류 분석·한계 공개가 이미 상당히 충실하다. 가장 큰 부족은 높은 행 F1 자체가 아니라 **진동만 변하는 이상을 놓치는 감시 범위, 관측 조건 변화에 취약한 점수, 개선안을 실제로 채택할 기준과 실행 증거**다. 단일 사건에서 경보를 유지하는 R1을 더 강하게 만들어 1.000을 반복하는 방식은 이 부족을 해결하지 못한다.

경쟁 리뷰의 E05는 `b05570e` 보고서와 ZIP으로 평가한 56쪽 버전이다. 현재 61쪽 보고서에 있는 특징 맞춤 5NN, Ridge 예측 오차, 진동 병행 실험, R2 재학습 평가, 시각 흔들림 확장, 43개 수치 검증을 없는 것으로 평가하면 안 된다. 당시 E19 89.3 대 E05 86.2는 공개 자료에 대한 비공식 비교점수이며, 현재본의 점수도 실제 대회 순위도 아니다.

목표는 다음 세 가지의 실측 증거를 더하는 것이다.

1. R1 없는 인과적 판정에서 전류형 탐지를 유지하면서 진동형 탐지를 넓힌다.
2. 병행 모델의 오경보 예산을 합쳐 관리하고, 정상 조건 변화에서 실제로 견디는지 같은 시험으로 비교한다.
3. 선택 과정, 예측 파일, 보고서 수치, 한 표본씩 들어오는 실행이 서로 맞는 것을 재현한다.

## 2. 우선순위별 검수

### P0-A. 설계 노출을 사후 분할이나 잠금으로 복구할 수 없다

- **주장:** 해시 잠금·시간순 분할로 평가 절차를 통제했으며 분할 변경·주입·수집 조건 시험으로 일반화를 따로 쟀다.
- **가정:** 설계자가 이미 본 관측 자료라도 이후 분할과 잠금을 만들면 새로운 평가 역할을 줄 수 있다.
- **반례:** 보고서 2.3절은 v2의 초반 창·AR(2), R1·R2·2행 상수를 전체 이상을 본 뒤 정했다고 직접 밝힌다. A와 B의 이상 test 11기록은 같고, 정상 test도 중첩된다. 알려진 기록을 다시 나누어도 독립 사건은 생기지 않는다.
- **근거:** 원본 1.7절 153~158행, 2.3절 233~236행, 2.5절 310~317행; J1/J2/J3 E05와 E19 모델 감점 사유.
- **수정:** 신규 실험은 `사후 개선 연구`로 명시한다. 실행 전에 후보·선택 조건·정상 내층 분할·섭동 종류와 강도·seed·평가 지표를 파일로 고정하고 해시를 기록한다. 이후 평가 결과를 보고 규칙을 바꾸면 새로운 탐색 버전으로 이력을 남긴다. 1.7절의 “일반화는 … 따로 쟀다”는 “같은 자료 안의 민감도와 합성 조건에서의 동작 범위를 점검했다”로 고친다.
- **필수 검증:** 학습·보정·선택·보고용 평가 기록 ID의 교집합 검사; 평가 라벨을 바꾸거나 제거해도 학습 파라미터·문턱·선택 결과가 변하지 않는 검사; 선택 파일 해시 검증.
- **남는 약점:** 기존 자료를 본 지식과 단일 사건 교란은 제거되지 않는다. 새 정상 날짜·독립 고장 사건이 필요하다. 어떤 재분할도 `새 독립 test`로 쓰지 않는다.

### P0-B. “공식 1.000” 중심 서술은 모델의 개선분을 가린다

- **주장:** 잠금 모델 v2+R1의 test 행 F1 1.000·0.995가 공식 성능이다.
- **가정:** 사건 지속 규칙이 포함된 행 F1이 앞단 모델의 탐지 성능을 대표한다.
- **반례:** valid에서 이어 돌리면 IsolationForest+R1도 1.000이고 max|z|+R1도 v2+R1과 동급이다. 특징 맞춤 5NN은 R1 없이도 F1 0.970·0.972로 v2 0.965·0.970과 동급이며 고부하 오경보는 더 적다.
- **근거:** 요약 17행, 2.4절 244~258행, 2.7절 350~366행. 현재 보고서는 이를 이미 솔직하게 공개한다. 문제는 거짓 수치가 아니라 대표 지표의 우선순위다.
- **수정:** 복사본 요약과 첫 표는 `R1 없는 탐지`, `정상 기록 오경보`, `기록별 탐지 지연`, `운영 상태 지속 후 결과` 순서로 배치한다. 기존 잠금 결과는 기존 버전의 기준선으로 보존한다. 신규 모델에 기존 잠금 모델 명칭을 붙이지 않는다. 행·기록·창 F1의 분모를 표 머리말에 적는다.
- **필수 검증:** raw 판정, 기록마다 상태 초기화, 연속 스트림 상태 유지 세 결과를 같은 예측 파일에서 재계산한다. 창이 차지 않은 행도 전체 행 지표의 분모에 남긴다. E19의 창 F1 0.931과 우리 행 F1을 직접 빼서 우열을 주장하지 않는다.
- **남는 약점:** R1 없는 높은 F1도 같은 사건·같은 날짜 구분 문제의 결과다. 독립 사건 일반화는 별도 문제다.

### P0-C. 진동형 감시 추가는 “별도 OR”에서 “통합 예산을 가진 후보”로 진행해야 한다

- **주장:** v2+R1에 Ridge 경보를 OR로 더하면 진동 단독 주입 탐지가 28.3~96.1%로 높아지고 α 1% test 오경보는 같다.
- **가정:** 각 α 1% 경보를 합쳐도 기존 시스템과 같은 오경보 부담으로 비교할 수 있다.
- **반례:** 기존 4.3절은 α 5% 정상 오경보 기록이 17→24/300으로 늘고, 1%에서 같은 것은 Ridge의 유일한 오경보가 우연히 겹쳤기 때문이라고 이미 설명한다. 또한 Ridge는 갑작스러운 진동 변화에 강하지만 기록 전체의 지속적인 수준 상승에는 둔할 수 있다.
- **근거:** 2.4절 257행, 3.6절 464행, 4.3절 540행; `tvt/14_baseline_injection_ridge.py`의 RidgeForecast와 `tvt/16_jitter_ridge_combo.py`의 COMBOS.
- **수정:** 경쟁 E19의 채널을 분리한 검증 사상을 활용하되, 전류형 경보가 있어야 진동형도 경보하는 필수 AND는 피한다. 전류 파형·동역학 경로와 전류에서 독립적인 진동 잔차/형태 경로를 각각 설명 가능한 점수로 만들고 결합한다. 학습 정상으로 척도를 고정한 결합 점수의 **기록 최대값을 한 번 정상 보정**하여 기존과 같은 명목 α로 비교한다. 기존 Ridge OR는 별도의 비교 후보로 남긴다.
- **유한 표본 제약:** 정상 보정 120기록이면 conformal 최소 p는 1/121≈0.00826이다. 두 경로에 Bonferroni α=0.005씩 배분하면 어느 경로도 경보를 낼 수 없다. 통합 점수 보정 또는 충분한 별도 보정 표본이 필요하다. 같은 보정 자료로 임의의 결합을 선택한 뒤 그 자료를 그대로 최종 보정에 쓰는 적응 문제도 피한다.
- **필수 검증:** 같은 α·같은 정상 평가 기록에서 raw v2, 특징 맞춤 5NN, Ridge, 독립 진동 후보, 통합 후보의 행/기록 FPR와 주입별 탐지를 함께 낸다. 주입 없는 paired 대조, 강도별 결과, 상·하부 채널별 결과와 처리 불가 기록을 포함한다. 선택은 정상 내부의 학습/검증으로 하고 기존 test는 최종 사후 보고에만 쓴다.
- **남는 약점:** 단일 결합 통계의 conformal도 시간순 비정상성에서는 명목 보장이 없다. 결합 뒤 R1·연속 조건을 붙이면 그 최종 경보의 FPR를 별도로 측정해야 한다. 주입 검출을 실제 베어링 고장 검출률로 부르지 않는다.

### P0-D. 강건성은 한계 설명에서 실제 후보 선택·안전한 보류로 이어져야 한다

- **주장:** 센서 시각을 동기화하고 재보정하면 현장 적용할 수 있다.
- **가정:** 변동이 감지 가능하고 전류 파형 불량을 설비 고장과 구별할 수 있다.
- **반례:** 0.1ms 가상 시각 흔들림에서 B 정상 기록의 35.2%가 2단계 경보를 낸다. 큰 전류 직류 이동에서는 거의 모든 정상 기록이 경보한다. 진폭 감소/센서 끊김은 0~2%만 탐지한다. E19의 진동 전용 확인도 오프셋 섭동에서 빨강 경보가 96.7배 증가한다.
- **근거:** 2.6절 E2/E5, 3.3절 오류 표, E19 팩트시트 §3. 현재본의 시각 흔들림 반증은 교란을 완전히 배제한 결과가 아니다.
- **수정:** 고장 민감도와 nuisance 민감도를 분리해 후보 선택 표에 둔다. 훈련에서 정한 차분·국소 중심화·부하 조건화·강건 척도 등을 제한된 후보로 시험한다. “센서/수집 확인 필요” 플래그와 “설비 이상 점검” 근거를 별도로 남기고, 수집 문제 의심 때문에 모든 경보를 조용히 제거하지 않는다. 진동 확인 채널에도 DC 오프셋 제거가 새 취약점을 만드는지 검사한다.
- **필수 검증:** 채널별 offset, gain, quantization, dropout/stuck, 시간 jitter, 부하 변화에 대한 정상 오경보와 이상 검출 유지율을 같은 후보 모두에 평가한다. 채택을 위해 nuisance 내성만 높이고 약한 전류 주입 탐지를 잃은 후보를 거를 조건도 실행 전 고정한다. baseline 대비 증분을 같이 기록한다.
- **남는 약점:** jitter의 60.6Hz 앨리어싱 가정, gain/offset 크기는 실측 사양이 아니다. 강건성의 범위는 시험한 가정에 한정한다. DC 제거는 실제 DC 이상을 제거할 수 있다.

### P1-E. 실시간이라는 주장에 상태·인과성 실행 증거가 더 필요하다

- **주장:** 행이 들어오는 순간 경보를 내고 미래 정보는 사용하지 않는다.
- **가정:** 일괄 계산 코드의 출력이 한 행씩 들어오는 실행과 같으며 기록 종료·경계도 인과적으로 처리된다.
- **반례:** 기존 evalcore는 완성된 table에서 정상·이상 스트림을 나눠 처리한다. 이것이 누수라는 증거는 없지만, 원본 보고서의 43개 수치 대조만으로 배포 형태의 경계·상태 관리가 확인되지는 않는다. 콘솔 역시 최종 R1/R2 미반영 프로토타입이다.
- **근거:** 1.7절, 4.2절 484행, 6장; `tvt/evalcore.py`의 `_streams`; E19 팩트시트 §4·6의 sample replay.
- **수정:** 신규 판정에 샘플 단위/임의 청크 단위 재생을 만들고 일괄 예측과 대조한다. 기록 전체를 미리 보는 특징과 인과적 prefix 특징을 명시적으로 나눈다. 관측 부족은 정상 확정 대신 별도 상태 또는 점수 없음으로 기록한다. 표본별 처리시간과 한 기록의 최대 필요 버퍼를 측정한다.
- **필수 검증:** prefix 결과 불변성(미래 suffix 교체 시 앞쪽 판정 동일), 1행/임의 청크/일괄 동등성, 긴 공백 후 reset, 짧은 기록, 반복 시각, 연속 정상→합성 이상→정상 복구, 전체 결과와 예측 CSV 일치. 현실에 없는 정상→고장 전이를 만들 때 합성 재생임을 표기한다.
- **남는 약점:** 실제 센서 전달이 5초 묶음이면 CPU 추론이 빨라도 표시 지연이 남는다. 참조 구현 재생을 PLC 현장 배포 검증으로 부르지 않는다.

### P0-H. 기존 감쇠 충격 생성은 선언한 시작 시각 이전의 입력도 바꾼다

- **주장:** 주입 시작 위치 이후의 경보로 합성 이상 탐지와 지연을 평가한다.
- **가정:** 합성 이상 생성 전후의 시작 시각 이전 입력은 같다.
- **반례:** `Generator.inject`의 `damped_impulse`는 시작 전 0인 감쇠 파형을 만든 뒤 기록 전체의 `wave.mean()`을 뺀다. 따라서 시작 전에도 0이 아닌 음의 상수가 더해진다. 탐지 함수가 인과적이어도 이 입력으로 잰 지연을 “시작 전 변화 없는 충격에 대한 지연”이라고 해석할 수 없다. 기존 코드의 계약 검사는 채널 불변·seed·진폭 배수는 확인하지만 시작 전 입력 불변은 확인하지 않는다.
- **근거:** `yejun/analysis/press_master_validation_2026-10-03/core.py` 356~381행, 같은 폴더 `test_contracts.py` 134~153행. 신규 모델 설계 검수 담당자의 지적을 이 코드에서 다시 확인했다.
- **수정:** 기존 보고서 인용 실험을 소급 수정하지 않고, 기존 주입의 해석 범위를 명시한다. 신규 시험은 시작 전 가산 파형이 정확히 0인 causal additive injection을 사용한다. 크기는 학습 정상에서 정하고 선택/보고 평가 seed를 분리한다. 새 생성기 결과를 기존 동일 주입의 재현이라고 부르지 않는다.
- **필수 검증:** onset 이전 모든 채널 바이트/배열 불변, 대상 외 채널 불변, 강도 0의 항등성, seed 결정성, 학습 전용 scale, 주입 시작 직전 경보 상태 기록, 대조와 주입 지연의 분리. 기존 방법과 비교할 때는 두 생성법을 같은 모델에 적용한 민감도 대조 또는 생성기 차이를 명시한다.
- **남는 약점:** 시작을 명확하게 만든 합성 시험도 실제 고장 시작의 물리적 정의나 고장 전 선행 시간을 제공하지 않는다.

### P1-F. 보고서 수치를 실행 없이도 감사할 수 있어야 한다

- **주장:** 한 명령 실행과 43개 수치 대조로 재현된다.
- **가정:** 모든 중요한 표의 숫자가 동봉 산출물에서 확인되고, 비교 실험의 별도 환경도 이해할 수 있다.
- **반례:** 경쟁 리뷰는 E05 표 원자료가 ZIP에 없어 감점했다. 현재본에서는 43개 대조로 강화되었지만 `run_all.py` 밖인 보완 LSTM·UCI·콘솔도 남는다. 실행 실패와 학습시간 부담 때문에 정적 검수 가능성이 중요하다.
- **근거:** 6장 595~606행; J1/J2/J3 E05 code/evidence_gap; 기존 `claude/code/press/tvt/outputs/`에는 현재 추가 실험 JSON/CSV가 있으므로 “자료 없음”을 현 상태에 자동 적용하면 안 된다.
- **수정:** 신규 복사본의 모든 새로운 대표 수치에 JSON/CSV 키 또는 예측 파일 열을 대응시킨다. 짧은 요약 CSV와 config·환경·원본/코드/선택 해시·실행 메타데이터를 함께 보관한다. 기존 표를 그대로 인용한 항목과 새로 실행한 항목을 구분한다. 계산 없이 보고서 숫자만 올리지 않는다.
- **필수 검증:** 입력 해시, 선택 결정 해시, 예측 행 수·ID·순서·라벨 정합성, 직접 혼동행렬 재계산, 요약표 재계산, 원본 보고서 해시 불변, 신규 산출물 전체 재실행의 핵심 결과 일치. ZIP에 넣는다면 archive inventory로 파일 포함 여부를 실제 점검한다.
- **남는 약점:** 옛 다세대 모듈 전체 리팩터링은 이번 성능 검증에 불필요한 위험을 만든다. 필요한 공용 코드를 읽기 전용 import하면서 신규 경로만 쓰고 `PYTHONDONTWRITEBYTECODE=1`을 적용하는 것으로 범위를 제한한다.

### P1-G. “최대 탐지율”과 이상확률을 과도하게 읽지 않도록 지표를 정리한다

- **주장:** 진동 단독 최대 탐지율 95.7% 또는 96.1%, 현장 가정 1% 이상확률을 제시한다.
- **가정:** 가장 잘 잡힌 강한 주입 조건이 진동 감시 전반을 대표하고, 같은 사건에서 보정한 확률이 현장 확률에 가깝다.
- **반례:** 약한 주입·다른 채널·초반 짧은 기록의 결과는 낮을 수 있다. 현장 가정 확률은 우도비 표시 상한 탓에 약 55%에서 포화하며 오경보 3행도 같은 값이다. 파일 비율 확률은 평가자료의 유병률을 사용한 참고값이다.
- **근거:** 2.4절 표의 최대값, 2.5절 이상 확률 문단, 4.3절 주입 없는 대조 경보율 12.5~37.5%.
- **수정:** 신규 주입 비교에는 family×강도별 탐지율과 macro 평균·최저값을 함께 제시하고, 같은 원본 정상 기록·seed의 대조와 짝을 맞춘 증가량을 보고한다. 실제 파일 탐지, 합성 이상 민감도, 정상 nuisance 강건성을 서로 다른 표로 둔다. 기존 확률의 생성 모델이 v2이면 신규 결합 모델의 확률로 이름만 바꾸지 않는다. 새 확률을 추가할 때는 보정 대상·사전확률·검증 단위를 다시 고정한다.
- **필수 검증:** 대조 경보와 주입 후 경보의 paired 집계, 미지원 주입 분모 유지, 지연 측정에서 미탐 검열 처리, 확률 단조성/범위/유병률 변환 검사. 단일 사건 확률을 안전 의사결정의 절대 확률로 표현하지 않는다.
- **남는 약점:** 합성 family를 더 많이 만들어도 실제 독립 고장 수는 늘지 않는다. 1개 사건에서 사건 단위의 정밀한 신뢰구간은 얻을 수 없다.

## 5. 채택 기준과 순위에 대한 결론

신규 후보는 기존 v2·특징 맞춤 5NN·Ridge를 같은 조건에서 이겨야 할 대조군으로 둔다. 진동 주입 탐지만 올리고 정상 오경보가 크게 늘거나 전류형 탐지를 잃으면 채택하지 않는다. 기존 운영 예측을 덮어쓰지 않고 후보의 장단점·실패·채택 범위를 기록한다. 작더라도 반복 실행으로 확인되는 개선만 보고서에 반영한다.

이번 신규 프로토콜은 기존 A/B의 공통 정상 학습 범위인 기록 0~299 안에서만 후보를 고르는 방향이다. 적합 0~119, 보정 120~239, 선택 개발 240~299로 나누고 후보를 잠근 뒤 A/B 전체 평가를 사후 보고한다. 이 설정은 신규 선택에 기존 A/B 평가자료를 직접 넣지 않는 장치이며, 이미 관측된 전체 자료가 새로운 독립 평가자료로 바뀐다는 뜻은 아니다. 실제 실행 config와 잠금 파일이 이 방향대로 구현됐는지는 신규 산출물 검증에서 확인해야 한다.

경쟁팀의 최고점과 우리 점수의 차이를 자동으로 메워 주는 공식은 없다. 이 검수는 새로운 점수나 순위를 계산하지 않았다. 이번 자료로 해결할 수 있는 것은 감시 범위·오경보 통제·강건성·인과적 재현 증거이며, 실제 1위 확보와 독립 사건 일반화는 보장할 수 없다.
