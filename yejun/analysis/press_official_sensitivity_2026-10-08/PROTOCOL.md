# 공식 모델 상수 민감도·선택 규칙 교차 확인 — 실행 전 계약

작성: 2026-10-08. 이 문서와 `protocol.json`은 평가 코드를 한 번도 돌리기 전에 고정하고, SHA-256과 UTC 시각을 `protocol_lock.json`에 남긴다. 잠근 뒤 바꾸지 않는다. 계약과 다르게 한 일은 README의 '프로토콜 이탈'에 적는다.

## 목적과 성격

- 심사 지적: 규칙 R1·R2와 그 상수(60초·2행·R² 0.5% 분위·8행)는 전체 자료를 본 뒤 정했다. 결과가 고른 상수에서만 나오는 산물(설계 누출)이 아닌지 근거를 낸다.
- 이 작업은 **민감도 감사**다. 새 검증이 아니고, 공식 모델과 상수를 바꾸거나 다시 고르지 않는다. 결과가 어떻게 나와도 공식 모델은 1단계 '주의' = v2+R1(잠금 모델), 2단계 '점검 요청' = v2+R1+R2, 상수 GAP_S 60·CONFIRM_ROWS 2·R2_Q 0.005·R2_MIN_LEN 8, α 1% 그대로다. 격자에서 공식값보다 좋아 보이는 점이 있어도 채택하지 않고 '더 낫다'고 쓰지 않는다.
- 격자는 자료를 본 뒤 고른 값을 가운데 둔 이웃 값이다. 같은 자료(약 3분짜리 단일 고장 사건, 이상 21기록)에서 상수를 흔들었을 때의 국소 민감도를 잴 뿐 표본 밖 성능을 보이지 않는다.

## 입력 (재학습 없음)

- 공식 코드와 점수 캐시: 새로 돌린 공식 실행 결과 폴더(`k-manufacturing-official-clean-20261008/unpacked/북적북적_code_통합본`)를 임시 폴더 `press_official_sensitivity_work/`에 통째로 복사한 사본만 쓴다. 원본 실행 폴더와 `claude/`는 고치지 않는다.
- 점수: 사본의 `code/press/tvt/cache/rows_{A,B}.pkl`(01_scores 출력). 모델을 다시 학습하지 않는다.
- R2_Q·R2_MIN_LEN을 바꾸면 기준값 r2_ref(정상 학습 구간 prefix R²의 분위)가 바뀐다. 캐시에 학습 구간 행이 없으므로 사본의 원본 CSV를 공식 함수(`01_scores.frame_rows`, `D.load`, `D.split_normal`)로 다시 읽어 학습 정상 전류만 얻는다. 모델 적합은 하지 않는다.
- 평가 함수는 사본의 공식 코드를 import해 그대로 쓴다: `lib.stream_rules`(R1), `lib.prefix_r2`, `evalcore.evaluate`·`predict_rows`·`candidates`, `07_r1_on_baselines.test_only`(이상 흐름을 test 기록부터 따로), `02_select_on_valid.main`(선택 규칙).

## 상수 격자 (완전 요인, 81점)

| 상수 | 값 | 공식값 | 쓰이는 곳(공식 코드) |
|---|---|---|---|
| GAP_S | 30, 60, 120 | 60 | `lib.stream_rules`: 직전 기록 끝과 새 기록 시작 간격이 이 값 이하일 때만 경보 이어받기 |
| CONFIRM_ROWS | 1, 2, 3 | 2 | `lib.stream_rules`: 자기 경보가 이 행 수 이상이면 '확인된 이상' |
| R2_Q | 0.001, 0.005, 0.01 | 0.005 | r2_ref = 학습 정상 prefix R²의 R2_Q 분위. R1 해제(파형 정상 행)와 R2 보류에 같은 r2_ref를 쓴다(`evalcore._streams`, `own_alarm`) |
| R2_MIN_LEN | 6, 8, 10 | 8 | `lib.prefix_r2`: 기록의 R2_MIN_LEN번째 행부터 R² 계산(그 앞은 NaN = 해제·보류 없음). r2_ref 계산의 학습 prefix R²에도 같은 값 |

- α: 1%(주), 3%·5%(보조). 분할: A·B. 상수는 모듈 전역값을 바꾸거나(GAP_S·CONFIRM_ROWS·R2_MIN_LEN) 인자로 넘긴다(r2_ref). R2_MIN_LEN은 행 표의 `prefix_r2` 열을 저장된 `current`로 다시 계산해 바꾼다.

## 대상 변형

- 1단계 = 후보 `v2+H1`(v2+R1), 2단계 = `v2+H1+H2`(v2+R2 후 R1). 참고 = `v2`(규칙 없음, 네 상수와 무관).

## 지표 (분할 × 격자점 × α × 변형)

1. test 실시간 행 F1, TP, 미탐 행(FN), 정상 오경보 행(FP): `evaluate(..., "test", r2_ref)["realtime"]`.
2. test 정상 오경보 기록 수: test 정상 기록(A 120·B 180) 중 실시간 경보 행이 1개 이상인 기록 수(`predict_rows`).
3. test 이상 기록 탐지 수(11기록 중 실시간 경보 1행 이상), test 기록 판정 F1(보조).
4. valid 실시간 행 F1(분할별, A·B 평균): `evaluate(..., "valid", r2_ref)`.
5. 이상 흐름을 test 기록부터 따로 돌린 실시간 행 F1과 미탐 행: `07.test_only`(α는 07 모듈의 PRIMARY_ALPHA를 바꿔 넘긴다. 정상 흐름은 1과 같다).

## 요약 (미리 정한 계산)

- 변형·α·지표마다 81점의 최솟값·중앙값·최댓값, F1 ≥ 0.99인 격자점 비율(A, B, 둘 다).
- 정상 오경보 기록 수가 공식 격자점(60·2·0.005·8) 값과 다른 격자점 수(분할·변형별).
- 상수 영향: (a) 한 번에 하나만 바꾼 8점(OAT), (b) 주효과 = 상수의 각 값에서 나머지 27점 평균을 내고 그 최대−최소. 1단계·2단계 test F1(A·B 평균), 정상 오경보 기록(A+B), valid F1 평균에 대해 주효과 크기 순으로 '가장 영향이 큰 상수'를 정한다. 같으면 동률로 적는다.

## 선택 규칙 교차 확인 (앞뒤 바꾸기)

- 이상 21기록의 역할만 바꾼다: 뒤 11기록(10~20) = valid, 앞 10기록(0~9) = test. 정상 분할·점수·보정은 그대로다(이상 기록의 점수와 p값은 이상 역할과 무관하게 계산되어 있다 — 01_scores에서 역할은 채점 뒤에 붙인다).
- 공식 `02_select_on_valid.main`을 고치지 않고 CACHE·OUT 경로만 임시 폴더로 돌려 실행한다(같은 후보, 같은 복잡도, α 1%, 동률 폭 0.002). 같은 방식으로 바꾸지 않은 표를 돌려 공식 `tvt_valid.csv`·선택이 그대로 나오는지 먼저 확인한다.
- test(앞 10기록) 채점은 `evaluate(..., "test")`로 모든 후보·α에 한다. 앞 10기록이 시간상 먼저라 valid 쪽 경보 상태가 test로 이어지지 않는다(이상 파일 첫 기록부터 돈 것과 같다).
- 보고: 규칙이 고른 모델(실시간·기록 단위), 그 모델의 앞 10기록 test 행 F1 A·B, v2+R1·v2+R1+R2·v2의 앞 10기록 F1. 결과가 무엇이든 공식 모델을 바꾸지 않는다.
- 같은 단일 사건의 앞뒤를 바꾼 것이라 독립 반복이 아니다. 선택 결과가 어느 절반을 valid로 쓰느냐에 달렸는지만 본다.

## E3 시간순 5창 정상 기록 (선택, 20분 안일 때만)

- 13_r2_oos_alpha.py와 같은 창: 학습 기록 < end, 보정 end~end+119, 평가 end+120~end+179(end = 180·240·300·360·420, 평가 합 300기록). 창마다 공식 `04.fit_split`으로 v2를 다시 적합한다(13과 같은 계산, 결정적).
- 격자 81점 × α 1·3·5%마다 v2·v2+R2·v2+R1·v2+R1+R2의 정상 경보 기록 수를 300기록 합계와 착안 기록(302~304·422~424·460~462·569~571) 제외 288기록으로 센다. 정상 전용이며 탐지는 보지 않는다.
- 공식 상수에서 13의 `A_per_fold`(rolling 5창의 all|·keep| 수)를 그대로 내야 한다. 20분을 넘으면 생략하고 README에 적는다.

## 검증 (통과해야 결과를 쓴다)

1. 공식 상수 재현: α 1·3·5%, A·B의 v2·v2+H1·v2+H1+H2 test/valid 실시간·기록 판정 TP·FP·FN이 공식 `tvt_test.csv`·`tvt_valid.csv`(사본과 `claude/` 판 모두)와 정수 일치, F1은 1e-12 안. 예: test 실시간 F1 v2+R1 A 1.000·B 0.995391705, v2+R1+R2 A·B 1.000. test부터 따로 F1(α 1%)은 `tvt_r1_baselines.csv`와 일치.
2. R2_MIN_LEN 8로 다시 계산한 prefix_r2가 캐시 열과 NaN 위치까지 같고, (0.005, 8)로 다시 계산한 r2_ref가 `tvt_scores_meta.json` 값과 같다.
3. 패치가 실제로 보이는지: `evalcore.stream_rules`·`07.stream_rules`·`04.stream_rules`가 `lib.stream_rules`와 같은 객체이고 그 전역이 `lib` 모듈인지 확인. 행동 확인: GAP_S = −1 또는 CONFIRM_ROWS = 10⁹이면 1단계가 v2와 같아야 한다. R2_MIN_LEN = m이면 길이 m 이상 기록의 앞 m−1행만 NaN이어야 한다. α를 바꾼 test_only의 정상 오경보 행이 evaluate와 같아야 한다.
4. 점수 캐시 SHA-256이 사본 `tvt_selection.json`의 `inputs.rows_sha256`과 같다. 실행 환경 판과 import한 공식 소스 해시(원문, 줄바꿈 LF 맞춤, `claude/` 판 대조)를 기록한다.
5. 검증 실패 시 격자 결과를 공식 코드 결과로 쓰지 않고 실패를 기록한다.

## 해석 규칙 (미리 고정)

- 주 결과는 α 1%다. α 3·5%는 보조로만 적는다.
- '81점 모두 F1 ≥ 0.99'는 A·B 모두 참일 때만 쓴다. 아니면 비율과 떨어진 격자점의 상수 조건을 적는다.
- '상수와 무관'은 그 상수의 모든 값에서 지표가 다른 상수 조합마다 같을 때만 쓴다. 아니면 범위를 적는다.
- 모든 문장에 같은 단일 사건, 상수는 자료를 본 뒤 정함, 격자는 민감도 확인이지 새 검증이 아님을 함께 적는다.
- 결과를 근거로 공식 모델·상수·α를 바꾸거나 '최적 상수'를 제안하지 않는다.
