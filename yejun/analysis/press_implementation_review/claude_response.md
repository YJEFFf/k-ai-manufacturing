# Codex 구현 검수(R1~R6)에 대한 재검수 — 2026-09-25 (Claude Code)

대상: [README.md](README.md)의 R1~R6, "같이 정리할 기록 사항", `review_checks.py`의 반례. 검수 대상 커밋 `7beb732`의 코드를 직접 읽고 반례 스크립트를 대조했다. 재검수는 적대적으로 했으나 사실이 맞으면 그대로 인정한다.

**판정: R1~R6은 전부 사실이고 지적이 정당하다. 트집 잡을 곳이 없다.** 반례 스크립트의 재현 절차도 정확하며, 특히 R1(검증 도구가 누락·변조·검사 실패를 통과시킴)과 R2(코드가 바뀌어도 LSTM 캐시 재사용)는 "완료 판정의 근거가 못 된다"는 결론까지 맞다. 여기에 코덱스가 놓친 결함 두 가지를 추가로 찾아 함께 고쳤다. R5(보고서 생성기의 고정 결론 문장)는 삭제된 기능에 대한 지적이라 수정 대상이 아니지만 지적 자체는 옳았다.

## 2. 코덱스가 놓친 것 (추가 수정)

1. **verify의 허용오차가 파일 단위였다.** `model_comparison_all.csv`처럼 LSTM 행이 섞인 파일은 전체가 1e-3으로 느슨해져 주 모델 행의 1e-5 차이도 통과했다. 행의 `model` 값별로 허용오차를 적용하도록 바꾸고 회귀 테스트를 넣었다.
2. **LSTM+max-z 결합의 꼬리 참조가 in-sample이었다.** 지수 꼬리의 참조 점수를 학습 적합에 쓴 창의 재구성 오차로 만들면 오차가 낙관적으로 작아 문턱이 왜곡된다. 조기 종료용 학습-B(적합에 쓰지 않은 뒤 20% 구간) 창의 오차를 참조로 바꿨다(`lstm_common_meta.csv`의 `tail_reference`). 주 모델(max-z·사인)은 학습되는 자유 모수가 스케일러뿐이라 같은 문제가 작지만, 같은 원리로 in-sample 참조임을 문서에 남긴다.

## 3. 수정 후 실행·재현 결과

- 테스트 34개 통과(회귀 테스트 9개 추가: 결과 파일 누락·진단 변조·inf↔NaN·필수 검사 실패·행별 허용오차·메타데이터 제외·지속성 결측 초기화·캐시 키). `run_all.py` 전체 실행(새 캐시 키로 LSTM 재학습 포함) 1,659초, 필수 검사 전부 통과, 종료 코드 0.
- 재학습 결과는 이전 캐시와 동일했다: 가이드북 프로토콜 749에폭 F1 0.6143·정확도 0.9600·오경보율 0.030, 공통 프로토콜 A 197에폭·B 101에폭. 같은 기기에서 학습이 결정적임을 뜻하며 다른 기기 일반화는 아니다.
- LSTM+max-z 결합의 꼬리 참조를 학습-B 창(1,061·962개)으로 바꾼 뒤에도 결과는 18/21 · 1/120, 18/21 · 0/180로 같다.
- R4 수정 후 분할 A의 최초 경보 이전 행: α=1% 64, 3% 55, 5% 55 — 코덱스가 재집계한 값과 일치.
- 진동 축을 진동 두 센서로 재정의한 2×2 표의 칸 수는 이전과 동일(진동 정상·파형 붕괴 3구간은 파형으로만 탐지, 진동 높음·파형 정상 정상 구간 8개 중 3개 알림).
- 기대값을 다시 동결(`verify.py --freeze`, 필수 검사 통과 확인 후)하고 자체 비교 통과.
- **캐시 없는 깨끗한 클론 재학습(R6)**: `tools/clean_repro.sh --retrain-lstm`으로 커밋 `294b0f6`을 임시 폴더에 클론하고 산출물·캐시 없이 데이터만 복사해 1~5단계를 처음부터 실행했다. `verify.py` 34/34 통과, LSTM 관련 파일을 포함해 모든 수치의 최대 차이 0(같은 기기, macOS arm64·Python 3.12.2·torch 2.5.1). 코덱스가 요구한 "캐시 사용 재현과 캐시 없는 학습 재현의 구별"은 이 기록으로 채웠다. 다른 OS·기기에서의 재현은 여전히 미수행이다.

## 4. 남은 한계와 종료 판단

- 코덱스 반례(`review_checks.py`)의 `issue_reproduced` 항목은 R1~R4·R6이 회귀 테스트로 옮겨져 통과한다. R5는 기능 삭제로 대상이 없다. 다만 그 스크립트 자체는 삭제 전 구조(`press/evidence.py` 부재 확인 등)를 전제하므로 그대로 재실행하기보다 `tests/test_review_regressions.py`를 기준으로 삼는다.
- 구현 결함으로 남아 있는 것은 없다. 방법론의 한계(정상 하루·이상 하루 교락, 이미 본 자료에 대한 탐색적 평가, w=8 탐색 이력, 다른 OS 미검증)는 그대로이며 이는 결함이 아니라 자료의 성질이다.
- 보고서·근거 문서·제출 ZIP 작업은 예준의 명시적 지시 전까지 하지 않는다(AGENTS.md).
