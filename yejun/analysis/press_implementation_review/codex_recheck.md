# 프레스 구현 재검수 — Codex, 2026-09-25

대상: Claude 수정 `294b0f6`과 재학습 기록 `e43d96b`. [Claude 재검수](claude_response.md)를 읽고 실제 코드·테스트·출력 및 별도 반례로 확인했다. 오류 개수를 목표로 삼지 않았다. 대회 보고서·발표자료·ZIP 작업은 진행하지 않았다.

**판정: 기존 지적의 주요 수정은 유효하다. 완료 판정과 재현 도구에 남은 누락을 이번에 수정했으며, 아래 확인 범위에서 미해결 구현 오류는 발견하지 못했다.** 데이터·방법론의 알려진 한계와 예준의 최종 판단은 별개로 남는다. 이 판정은 보고서 착수 허가가 아니다.

## 1. Claude 수정에 대한 확인

- 기존 테스트 34개 통과. 수정 전 임시 클론의 캐시 사용 1~5단계 실행과 기존 검증 34/34도 재현했다.
- **R2 캐시:** 합성 자료로 실제 1에폭 학습 후 임시 패키지의 LSTM 출력에 +100을 더했다. 캐시 키가 바뀌고 기존 캐시를 재사용하지 않았다. 이전 점수와 차이는 약 10,130, 변경 코드의 강제 재학습과 차이는 0이었다. 키 함수만 호출하는 검사 외에 실제 캐시 사용 경로도 확인했다.
- **R3 결측:** `[10,10,10,NaN,0,0,0]`의 (2,3) 정책은 `[NaN,NaN,10,NaN,NaN,NaN,0]`으로 창을 다시 채운다.
- **R4 운영점:** 분할 A의 최초 경보 이전 관측 수는 α=1/3/5%에서 64/55/55, B는 55/55/55로 예측 파일·직접 추론·조건표가 일치했다.
- 진동×파형 표의 진동 축은 진동 두 센서만 사용하며, 진폭 신뢰 제한 표시도 추가됐다. LSTM 꼬리 참조의 학습-B 사용은 정상 학습 범위 안의 변경이다. 학습-B는 조기 종료에도 사용하므로 완전히 독립적인 검증 자료라는 뜻으로 해석하지 않는다.
- **R5:** 초안과 생성기가 없고 재실행 후에도 생성되지 않았다.
- **R6:** Claude가 기록한 캐시 없는 학습 결과와 저장된 수치를 확인했다. 이번 Codex 실행은 캐시 사용 재현이다. 전체 LSTM의 캐시 없는 30분 재학습을 다시 수행했다고 주장하지 않는다. 학습·점수 산식과 모델 설정은 이번 수정에서 바꾸지 않았다.

구현: `press/validation.py`, `verify.py`, `run_all.py`, `tools/clean_repro.sh`. 기존 반례 스크립트도 새 캐시 코드 경로와 파일 무결성 검사에 맞췄다. 정상 실행에서 환경·경로만 다른 경우를 파일 변조와 혼동하지 않도록 검사한다.

## 4. 현재 상태와 한계

이번에 확인된 오류는 수정했다. 오류를 추가로 찾지 못한 부분은 그대로 통과시켰다. 정상 하루·이상 하루의 교락, 이미 본 자료에 대한 탐색적 평가, 창 길이 탐색 이력, 다른 OS 미검증은 기존 한계로 유지한다. 21/21은 각 이상 기록구간에서 한 번 이상 경보한 결과이며 모든 이상 행의 정답이나 독립 고장 21회의 검증은 아니다.

이후에도 예준이 만족할 때까지 구현·실험·디버깅·검수를 진행한다. 보고서·장별 근거·발표자료·최종 ZIP은 예준의 명시적인 시작 지시 전까지 보류한다.
