# 프레스 1~6단계 구현 검수

검수일: 2026-09-25. 검수 대상: `7beb732ad07011fb841056dc53daf6efab39e67c`의 `yejun/press_submission/`.

**판정: 1~6단계에 해당하는 코드와 산출물은 존재하고 주 모델 결과는 재현된다. 최종 완료 판정에는 아래 R1~R6 수정·확인이 필요하다.** 확정 플랜의 방법론을 다시 심사하는 작업이 아니라 구현과 완료 조건을 확인한 결과다.

## 1. 실제 확인한 범위

- 임시 클론과 별도 Python 3.12.2 가상환경에 `requirements.txt`를 설치했다. numpy 1.26.4, pandas 2.3.3, scikit-learn 1.8.0, scipy 1.13.1, matplotlib 3.9.2, torch 2.5.1, pytest 9.0.3.
- 기존 테스트 **26개 통과**.
- 빈 출력 폴더에서 1~5단계를 재실행했다. LSTM에는 제공된 캐시를 사용했고, 다른 점수·보정·표·그림은 다시 계산했다. 기존 `verify.py`는 **33/33 통과**, 비교한 CSV의 최대 수치 차이는 0이었다.
- README에 적힌 `tools/clean_repro.sh --with-lstm`도 별도로 실행하여 **33/33 통과**를 확인했다. 이 스크립트도 LSTM 캐시를 복사한다.
- 저장 artifact를 사용하는 `predict_frame()`에 원본 평가 자료를 넣고, 평가 함수와 별개로 구간 알림·행 혼동행렬·F1을 재계산했다. 최초 일부 관측만 제공할 때의 점수 일치와 잘못된 시각·센서값의 상태 표시도 확인했다.
- 기존 제출 ZIP의 125개 내용 파일과 ZIP manifest를 확인했다. 필수 코드·데이터·주 모델·예측 파일이 있었고 해시 불일치와 ZIP 손상은 없었다. 블라인드 검사는 현재 구현된 문자열 검사 범위에서 0건이다.
- 검수 반례는 임시 복사본·합성 자료에서 실행했다. 재현 코드: [review_checks.py](review_checks.py), 관측 결과: [review_results.json](review_results.json), 실행 요약: [execution_summary.json](execution_summary.json).

전체 LSTM을 캐시 없이 다시 학습하는 30~40분 실행은 이번 검수에서 수행하지 않았다. 캐시 사용 재현과 캐시 없는 학습 재현은 구별한다. 보고서 PDF·발표자료·설문 캡처의 최종 대조도 아직 별도 작업이다.

### 주 모델의 독립 재집계

matched·w=8·구간 conformal α=1% 기준이다.

| 분할 | 이상 탐지 구간 | 정상 알림 구간 | 정상 경보 행 | 이상 미탐 행 | 전체 행 F1 |
|---|---:|---:|---:|---:|---:|
| A | 21/21 | 0/120 | 0 | 99/600 | 0.9100817438692098 |
| B | 21/21 | 3/180 | 3 | 86/600 | 0.9203222918531782 |

21/21은 모든 이상 기록구간에서 한 번 이상 경보했다는 뜻이다. 모든 이상 행을 맞혔다는 뜻으로 확대하지 않는다. `f029b42` 커밋 설명의 “FN 137/600”에서 137은 첫 7관측 준비 행 수와 혼동된 값이다. 실제 전체 행 FN은 위 표와 같다.

### 단계별 판정

| 단계 | 확인 | 남은 일 |
|---|---|---|
| 1 데이터·구간·분할·진단 | 원본 해시, 600/21구간, 분할, 정상 입력 경로 확인 | 필수 검사 실패를 실행 실패로 처리하는 R1 |
| 2 주 모델·보정·추론 | 주 결과, artifact 추론, 잘못된 입력 상태, 과거 점수 불변 확인 | R1의 실행 완료 판정 보완 |
| 3 민감도·절제·오류 분석 | 모든 후보 재계산과 기존 결과 일치 | R4 운영점별 최초 경보 이전 행 집계 |
| 4 비교모델·LSTM·불확실성 | 코드·표 존재, 캐시를 사용한 비교표 재현 | R2 캐시 무효화, R6 캐시 없는 재학습 확인 |
| 5 업무량·지속성·진폭·근거 | 기본 자료의 개선 후보 결과 재현 | R3 결측 처리, R5 결과에 따른 설명 생성 |
| 6 환경·재현·ZIP | 별도 환경 설치, 캐시 사용 재현, 기존 ZIP 내용 확인 | R1 검증 도구, R6 재학습 검증, 수정 후 최종 자료 대조·ZIP 갱신 |

## 2. 수정할 사항

### R1 — P1: 필수 결과와 정확성 검사에 문제가 있어도 성공으로 종료한다

위치: `press_submission/verify.py` 63행·76행·83행·40행, `run_all.py` 313행.

- `verify.py`가 **현재 존재하는 파일만** 비교한다. `model_comparison_all.csv`를 삭제하면 `32/32 통과`, 현재 결과 파일을 모두 삭제하고 manifest와 expected만 남기면 **`1/1 통과`, 종료 코드 0**이다.
- `diagnosis.json`은 내용이 다르더라도 파일 이름만으로 통과시킨다. 정상 행 수를 `-123`으로 바꿔도 `33/33 통과`였다.
- 수치 비교는 두 값이 모두 비유한이면 같게 취급한다. 경보 문턱을 `+inf`에서 `NaN`으로 바꾸어도 통과했다.
- `run_all.py`는 checks를 출력·반환할 뿐 필수 검사 실패 시 실패 종료하지 않는다. 합성 MC 검사 실패를 주입하니 `conformal_mc_within_4se=false`와 **종료 코드 0**이 동시에 나왔다.

영향: 단계 누락·진단 오염·정확성 검사 실패를 완료로 오인할 수 있다. 현재 `33/33`은 전체 완료의 충분한 근거가 되지 않는다.

최소 수정: 실행 단계별 필수 파일을 정의하고 누락을 실패시킨다. 진단 수치와 NaN/±inf를 구분해 비교한다. 필수 check가 false이면 실행을 실패 종료한다. 부분 실행은 확인한 단계·파일만 명시하고 전체 완료와 구별한다. 기대값 동결 전에도 같은 검사를 적용한다.

수정 확인: `verify_missing_result`, `verify_all_results_missing`, `verify_corrupted_diagnosis`, `verify_inf_to_nan`, `runner_failed_check_exit` 반례가 더 이상 재현되지 않아야 한다.

### R2 — P1: LSTM 구현을 바꿔도 이전 예측 캐시를 재사용한다

위치: `press_submission/press/lstm_ae.py` 123행·174행, `PLAN.md` §7의 캐시 키 계약.

캐시 키에는 일부 설정·원본 해시·torch 버전이 들어가지만 **학습/점수 코드, 전처리의 실제 값, 스케일러·구간 처리, 전체 실행 환경을 식별할 정보**가 빠져 있다. 고정 문자열 `protocol="common_lstm20"`도 구현 변경을 감지하지 못한다.

재현: 작은 합성 자료로 1에폭 학습한 뒤, 임시 복사한 LSTM의 출력을 `+100` 바꾸었다. 같은 입력·설정으로 호출하면 `cached=True`로 이전 점수가 그대로 반환됐다. 같은 변경 코드를 `retrain=True`로 실행한 점수와는 최대 **10,130.3879** 차이가 났다.

영향: 디버깅한 코드의 효과가 비교표에 반영되지 않아 잘못된 모델 비교와 완료 판정으로 이어질 수 있다.

최소 수정: 학습·전처리·점수 계산에 영향을 주는 코드와 설정을 캐시 키에 포함한다. 실제 입력/분할·스케일러·전처리 사양도 식별하고, manifest에 같은 정보를 남긴다. 이 수정 후 기존 캐시를 재검증하거나 새 키로 재학습한다.

수정 확인: 동일 코드·설정은 캐시 사용, 모델/전처리/학습 설정 변경은 캐시 미사용. `cache_reuses_changed_implementation` 반례가 사라져야 한다.

### R3 — P2: 지속성 경보가 결측 점수를 건너뛰고 이전 창을 유지한다

위치: `press_submission/press/field.py` 55행, `tests/test_step5.py` 10행. 관련 계약: `PLAN.md` §6의 결측 시 미판정·창 처리.

`persistence_score()`는 유효값만 버퍼에 추가하고 결측에서 버퍼를 비우지 않는다. 버퍼가 이미 찼으면 결측 행 자체에도 점수를 낸다.

재현: 같은 구간 점수 `[10,10,10,NaN,0,0,0]`에 (2,3)을 적용했다.

- 현재: `[NaN,NaN,10,10,10,0,0]`
- 결측에서 창을 다시 채우는 규칙: `[NaN,NaN,10,NaN,NaN,NaN,0]`

현재 기본 데이터의 주 결합 점수에는 이 결측 사례가 없어 기존 성능표는 재현된다. 결측 입력에 대한 운영 규칙은 수정이 필요하다. 기존 테스트는 결측을 건너뛰는 현재 동작을 기대하므로 함께 수정해야 한다.

최소 수정: 결측에서 버퍼를 초기화하고, 새로운 연속 유효 관측 n개가 쌓이기 전까지 미판정으로 둔다. 문턱 보정과 평가 양쪽에 같은 규칙을 적용한다.

### R4 — P2: α=3%·5% 오류표에 α=1%의 최초 경보 시점을 재사용한다

위치: `press_submission/press/analysis.py` 57행·87행.

`first_alarm_pos`를 `alarm`(α=1%)에서 한 번만 계산한 뒤 모든 운영점의 `rows_before_first_alarm`에 재사용한다.

실제 자료 재현:

| 분할 A의 α | 현재 표 | 해당 α의 예측에서 재집계 |
|---|---:|---:|
| 1% | 64 | 64 |
| 3% | 64 | 55 |
| 5% | 64 | 55 |

영향: 경보 민감도를 바꿨을 때 최초 경보 전 놓친 관측이 얼마나 줄었는지 잘못 설명하게 된다. 주 모델 α=1%의 F1·구간 탐지 수는 이 오류와 별도로 일치한다.

최소 수정: alpha별 경보 열에서 최초 경보 위치를 다시 계산하고 각 조건표에 연결한다. 위치·길이·진폭·진동 분류별 합계가 같은 alpha의 전체 집계와 맞아야 한다.

### R5 — P2: 자동 생성 보고서의 결론 문장이 실험 결과와 함께 갱신되지 않는다

위치: `press_submission/press/evidence.py` 135행·154행·182행·183행.

표는 파일에서 읽지만 “21구간 유지”, “정상 알림 0”, “B 3→1, A 0→1”, 최종 모델 선정 등의 설명이 고정 문자열이다. 모듈 첫 설명의 “하드코딩 없음”과도 다르다.

재현: 임시 결과표에서 (2,3) 정책의 α=1% 탐지를 0구간, 정상 경보를 5구간으로 바꿔 근거 문서를 다시 만들었다. 표는 바뀌었지만 본문은 여전히 **“이상 21구간 탐지를 유지한 채 정상 알림을 0으로 줄였다”**고 썼다.

영향: 앞으로 디버깅·실험 설정 변경 후 숫자와 보고서의 결론이 어긋날 수 있다. 현 기본 실행의 주요 성능 수치는 별도로 재현됐다.

최소 수정: 수치와 성능 비교 문장은 해당 실행 결과에서 생성하고, 개선·악화·동률을 관측에 따라 표현한다. 고정 연구 배경 문장과 결과 해석을 분리한다. 선정 근거도 실제 비교 대상과 분모를 함께 표시한다.

### R6 — P2: 캐시 없는 재학습 확인이 남아 있고, 현재 비교기는 그 실행을 올바르게 비교하지 못한다

위치: `press_submission/tools/clean_repro.sh` 14행·19행, `verify.py` 83행, `PLAN.md` §8의 6단계·§9의 6번 검사.

현재 `clean_repro.sh --with-lstm`은 기존 LSTM 캐시를 복사하고 `--retrain-lstm`을 전달하지 않는다. 이 범위의 재현은 확인됐다. 플랜에서 요구한 캐시 없는 전체 재학습은 완료 증거에 포함되지 않는다.

또 `lstm_guidebook_reproduction.json`을 통째로 비교하기 때문에, 성능·예측을 그대로 두고 실행 메타데이터인 `cached=False`, `train_seconds=1.0`만 바꾸어도 **검증 실패(32/33 통과, 종료 코드 1)**가 났다. `lstm_common_meta.csv`도 같은 종류의 실행 상태·시간 열을 담는다.

최소 수정: 결과 수치·경보 판정과 실행 시간·캐시 여부를 분리해 검사한다. R1·R2 수정 후 별도 깨끗한 환경에서 캐시 없는 학습을 실행하고, 학습 결과와 경보 차이를 기록한다. 허용오차 초과는 이유와 영향을 검토한 뒤 기대값 갱신 여부를 정한다. 먼저 기대값을 덮어써서 통과시키지 않는다.

## 3. 같이 정리할 기록 사항

- manifest와 `numbers.json`의 실행 ID가 짧은 HEAD만 사용하므로 같은 커밋의 다른 설정·미커밋 구현을 구별하지 못한다. 제출 ZIP의 manifest는 LSTM 구현 전 커밋인 `f029b42`를 가리킨다. 이번 별도 실행의 기록은 `7beb732`이며, 이후에는 코드 내용·설정·입력·환경 식별자를 함께 남기는 것이 필요하다.
- `run_all.py`는 manifest의 파일 해시를 만든 뒤 `checks.json`을 쓴다. 새 출력 폴더에서는 checks 해시가 빠졌고, 기존 출력 폴더에서는 이전 checks 해시를 담을 수 있다. 파일 생성 순서를 고쳐 현재 실행의 체크 결과를 포함한다.
- `checks.json.pending_steps`는 6단계를 항상 남긴다. README의 완료 표기와 실제 검증 범위를 일치시킨다.
- 가이드북 인쇄 페이지 35의 코드 26에는 `restore_best_weights=True`가 명시되어 있다. `PROVENANCE.md`와 `lstm_ae.py`의 “원 코드에서 확인되지 않음/우리 선택” 설명을 바로잡는다. 현재 최적 가중치 복원 구현 자체는 이 설정과 맞는다.
- `analysis.py`의 `vib_high`는 전류를 포함한 3센서 max-z로 정의된다. 진동×파형 해석을 유지하려면 진동 두 센서에서 계산한 값으로 정의하거나 표의 이름을 정확히 바꾼다. `amp_reliable`도 현재 길이만 보므로 플랜에 적힌 파형 적합 품질 제한을 어떻게 표시할지 명시한다.

## 4. 다음 작업과 종료 기준

1. R1·R2: 완료 검사와 캐시 무효화를 먼저 수정한다.
2. R3·R4·R5: 지속성 규칙·오류 집계·결과 설명을 수정하고 관련 반례를 회귀 검사로 전환한다.
3. R6: 캐시 없는 학습·평가를 수행하고 최종 결과를 다시 만든다.
4. 수치·근거 문서·상태 기록을 같은 실행으로 맞추고 제출 ZIP을 다시 조립한다.
5. Codex는 위 반례와 변경된 결과를 재검수한다. 확정된 연구 질문·프로토콜의 반복 계획 심사는 추가하지 않는다.

현재 검수 스크립트는 관측한 결함을 `issue_reproduced=true`로 기록한다. 수정 후 실행했을 때 이 값이 false인지 또는 재현 절차를 정상 회귀 테스트로 옮겨 통과하는지 확인해야 한다. 스크립트 자체의 종료 코드 0을 제품 완료 판정으로 사용하지 않는다.
