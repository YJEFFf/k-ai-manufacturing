## 1. 데이터 이해·진단
- 기록 단위(조각) 구조 [있음] (repo/docs/data_design.md §1; repo/notebooks/KMAP_analysis.ipynb 셀 7·11): 0.11초 초과 간격으로 정상 599·이상 21개 구간 생성, 구간 길이 분포(이상 3~50행, 중앙 28행) 확인.
- 샘플링 간격·시간 공백 [있음] (repo/docs/data_design.md §1): 연속 간격 0.1초, 0.11초 초과 간격의 최솟값 정상 1.545초·이상 1.780초를 경계값 근거로 제시.
- 중복 행 [없음] (repo/src/data.py): 중복 점검·제거 코드 없음. 간격 표에 0.1초가 아닌 0.11초 이하 간격 1건이 보이나 설명 없음.
- 결측·이상치 [부분] (노트북 셀 3): 결측 0 확인. 이상치 진단 없음.
- 클래스 불균형 [있음] (노트북 셀 3·5; repo/src/compare_models.py L31-56; repo/src/config.py L17): 행 기준 97.09:2.91, Accuracy 대신 Recall·F1·BA·PR-AUC 사용, 모든 모델에 클래스 가중치.
- 정상·이상 날짜 차이 [부분] (repo/README.md §7; repo/docs/validation_notes.md): "별도 수집 세션이라면 교란 가능성"을 한계로만 적음. 실제 날짜 차이는 확인·기술하지 않음.
- 두 파일 저장 방식 차이 [없음].
- 변수 의미 [부분] (repo/README.md §2): 진동 2·전류 1 채널 이름만. 단위·설치 위치·전류 파형 해석 없음(노트북 셀 15 출력에서 1초 창 전류 평균이 −104~108로 흔들리나 언급 없음).
- 이상이 한 사건뿐이라는 한계 [부분] (repo/docs/validation_notes.md): 사용 가능한 이상 구간이 17개로 적다는 점만 언급. 21개 구간이 약 3분짜리 한 사건이라는 점은 언급 없음.
- 전처리 [있음] (repo/src/features.py L12-51; repo/docs/data_design.md §2-3): 구간 안에서만 10행(1초) 비중첩 창, 센서별 mean·std·RMS·min·max 15개 특징, max−min과 선형종속인 P2P 제외. 창 길이는 이상 구간 보존율(10행 17/21, 20행 13/21)과 CV 결과로 결정.
- 진단→검증전략 [있음] (repo/docs/validation_notes.md; repo/src/evaluate.py L22-43): 구간을 그룹으로 StratifiedGroupKFold, 학습·평가 그룹이 겹치면 예외 발생.

## 2. 모델
- 베이스라인: 로지스틱 회귀(표준화+클래스 가중치), 랜덤포레스트 (repo/src/compare_models.py L29-57).
- 비교한 모델: 위 2개와 CatBoost, 모두 지도학습 이진 분류. 같은 15개 특징·같은 5-fold 그룹 분할(seed 42)·같은 지표 (repo/src/compare_models.py L60-104). 조정 CatBoost로 창 0.5/1/2초 민감도 비교 (repo/src/window_sensitivity.py).
- 최종 모델과 선정 근거: CatBoost(depth 4, 학습률 0.03, 400회, Balanced 가중치; repo/src/config.py L13-23). 비교에서 정밀도·재현율 균형이 가장 좋았다는 이유(F1 0.941). 조정 효과는 작다고 스스로 밝힘(F1 0.937→0.944).
- 검증 설계: 구간 단위 그룹 5-fold를 분할 seed 10개로 반복 (repo/src/evaluate.py L30-58). 창이 비중첩이고 구간을 넘지 않아 같은 기록 조각이 학습·평가에 함께 들어가지 않음. 문턱은 0.5 고정 (repo/src/config.py L11). 별도 test 없이 같은 개발 CV로 특징·창 길이·조정·집계 방식을 골랐으며, README도 독립 test 성능이 아니라고 밝힘 (repo/README.md §7).
- 보고 성능(창 단위, CV out-of-fold, 정상 1,820·이상 53창): 조정 CatBoost F1 0.944±0.008, PR-AUC 0.979±0.003, Recall 0.915, BA 0.957 — repo/results/summary_metrics.csv 및 노트북 셀 23 출력과 일치 확인. 3모델 비교(LR F1 0.801, RF 0.927, CatBoost 0.941) — 노트북 셀 19 출력과 일치(비교 결과 CSV는 미커밋). 창 길이 표 — repo/results/window_sensitivity_summary.csv와 일치. 구간 평균 집계 F1 0.997은 "참고"로만 제시. summary_metrics.csv의 기본 CatBoost 반복 CV 행(F1 0.937)은 생성 코드가 없어 확인 불가(evaluate.py는 조정 설정만 사용).
- 이상 확률 산출: CatBoost predict_proba를 `abnormal_probability`로 출력 (repo/src/predict.py L36-47). Balanced 가중치로 학습했고 확률 보정 절차는 없음.
- 누수·과대평가 위험: (1) 정상·이상이 다른 날·다른 파일인데 지도 분류기라 파일·세션 차이를 학습할 위험을 점검하지 않음(전류 mean·min·max 특징 포함; repo/src/config.py L5-7). (2) 이상 17개 구간은 한 사건의 조각인데 독립 그룹으로 섞어, 접기마다 같은 사건의 인접 조각이 학습과 평가에 나뉘어 들어감 (repo/src/evaluate.py L31-41) — 새 사건에 대한 성능보다 낙관적일 수 있음. (3) 창 길이·특징·조정을 같은 CV로 고름(작가 인정). (4) 창 길이 비교는 길이마다 이상 구간 수(18/17/13)와 창 수가 달라 직접 비교가 제한적.

## 3. 영향요인·오류분석
- 영향변수 분석: 최종 모델의 전역 중요도 없음. 초기 18특징 기본 모델의 단일 창(구간 20) local SHAP만 제시: 전류 min·mean·max는 이상 방향, AI0 진동 RMS·mean·min은 정상 방향 (repo/docs/shap_error_analysis.md; repo/results/shap_segment20_baseline18.csv). SHAP 생성 코드 없음.
- 변수 간 상호작용: "고전류·저진동이 충돌하는 패턴"이라는 정성 서술뿐 (노트북 셀 29).
- FN 조건 [정성]: 구간 16 안에서 창 확률이 0.014→0.999로 바뀌는 전이(평균 집계 시 희석), 구간 20의 저진동·고전류 사례 (repo/README.md §5). 구간 16 그림은 정적 SVG이고 생성 코드 없음. 접기당 평균 FN 1.0 (노트북 셀 19).
- FP 조건: 분석 없음(접기당 평균 FP 0.2만 보고).

## 4. 현장 활용
- 경보 단계: 없음. 점검 우선순위: 표준 점검 템플릿 항목(이상확률·지속시간·설비 중요도·정비이력 등)만 제안하고 가중치·행동 문턱은 현장 합의 이후로 미룸 (repo/docs/action_plan.md). 작업자 행동: 센서→탐지→템플릿→현장 판단→조치→기록 흐름. 실시간 적용: 새 CSV 일괄 추론 스크립트 (repo/src/predict.py). 재보정·운영 절차: 없음. 외부 사례 50개 조사는 외부 스프레드시트 링크뿐 (repo/docs/market_research.md).

## 5. 창의성·차별성

## 6. 코드·재현성
- 실행 진입점: `python -m src.train --data-dir data --save-model` 한 명령으로 반복 CV와 전체 재학습 모델 저장. 모델 비교·창 길이·추론은 별도 명령 (repo/README.md §9). 노트북은 src를 불러 재실행.
- 의존성 고정(requirements.txt 핵심 8개 핀 + pip freeze 142줄 lock), 상대경로, seed 고정(random_seed 42, 분할 seed 목록), 데이터 배치 안내 있음(원본 미포함), 예측결과 파일 없음, 단위 테스트 2개(구간 분리·창 경계; repo/tests/test_pipeline.py).
- 정적 점검 문제: SHAP CSV·구간 16 그림·summary_metrics.csv는 생성 코드가 없는 정적 산출물. compare_models.py·train.py가 쓰는 결과 CSV는 미커밋. 노트북 셀 12는 미리 저장된 창 길이 CSV를 읽음.

## 7. 강점 3가지 / 약점 3가지
- 강점 1: 구간 단위 그룹 분할, 비중첩·구간 내부 창, 그룹 겹침 검사로 같은 조각 누수를 코드로 차단.
- 강점 2: 베이스라인 포함 3모델을 같은 분할·같은 지표로 비교하고 반복 CV 평균±SD를 제시했으며, 보고 수치가 결과 파일·노트북 출력과 일치.
- 강점 3: 개발 CV 성능, 세션 교란, 소수 이상 구간 등 한계를 솔직히 적고 한 명령 실행·버전 고정·단위 테스트를 갖춤.
- 약점 1: 한 사건의 조각을 독립 그룹으로 섞는 CV와 지도 분류기 조합에서 날짜·파일 차이를 학습했을 가능성을 점검하지 않음(저장 방식 진단 없음).
- 약점 2: 영향변수·오류분석이 초기 모델의 단일 창 SHAP과 사례 2개에 그치고, FP 조건·운전조건별 정량화와 상호작용 분석이 없음.
- 약점 3: 현장 활용이 일반론이며 경보 단계·재보정 절차가 없고, 결과보고서·테스트 예측결과 파일이 없음.
