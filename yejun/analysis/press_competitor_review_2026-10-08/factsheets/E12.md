## 2. 모델
- 베이스라인: 명시적 지정 없음. 기본 통계 15특징 + 로지스틱 회귀가 가장 단순한 비교 대상 역할을 한다.
- 비교한 모델(지도학습): 로지스틱 회귀·랜덤포레스트 × 특징 세트 4종(기본 통계 15, 분포 특징 추가 27, 센서 관계 특징 추가 21, 시간 변화 특징 추가 28) = 8조합. 모두 같은 분할을 쓴다(repo/src/modeling.py:263-306).
- 최종 모델과 근거: 시간 변화 특징 28개 + 로지스틱 회귀. OOF F1·PR-AUC 순 정렬에서 1위(repo/src/modeling.py:305-306), FP 0·FN 1. 랜덤포레스트는 네 세트 모두 FN 3이다(README §9).
- 검증 설계: 조각 620개를 표본으로 StratifiedKFold(5겹, shuffle, 시드 42)(repo/src/modeling.py:98-108). 조각 단위라 행·창 중복은 없다. 결측 대체·표준화는 파이프라인 안에서 학습 겹에만 적합한다. 문턱은 0.5로 고정(repo/src/config.py:41). 그러나 다음 문제가 있다.
  - 무작위 분할이라 한 사건의 이웃 이상 조각이 학습 겹과 평가 겹에 나뉘어 들어간다.
  - 별도 시험 자료 없이 같은 OOF 결과로 특징 세트와 모델을 골랐다.
  - 관계·시간 특징은 기존 오류를 본 뒤 설계했다(README §13 4번, repo/src/features.py:116 주석).
- 보고 성능(README §9): OOF 정밀도 1.000, 재현율 0.952, F1 0.976, PR-AUC 0.994, ROC-AUC 0.9998, TN 599·FP 0·FN 1·TP 20(단위: 조각). 결과 파일이 저장소에 없어 대조하지 못했다. 표 안의 정밀도·재현율·F1끼리는 산술적으로 맞는다(예: 기본 통계+로지스틱 18/22=0.818).
- 이상 확률 산출: 있음. 로지스틱 회귀 OOF 확률(repo/src/modeling.py:183-184). 확률 보정 검토는 없다.
- 누수·과대평가 위험:
  - 정상(7/12)과 이상(7/17)이 다른 날 기록인데, 조각 평균(직류 성분 포함)을 특징으로 쓰는 지도 분류다(repo/src/features.py:53-92). 파일·세션 차이를 학습할 수 있으며 이를 확인한 실험이 없다.
  - 특징 설계와 모델 선택에 평가 결과를 다시 썼다.
  - 순위가 이상 21개 중 1~3개 차이로 갈린다.

## 3. 영향요인·오류분석
- 영향변수 분석: 겹별 랜덤포레스트 중요도(기본 통계 세트)와 로지스틱 계수 크기(시간 변화 세트)의 평균(repo/analysis/influence_analysis.py). 결과 파일이 없어 어떤 변수가 상위인지 확인할 수 없다.
- 변수 간 상호작용: 전류/진동 비율 같은 관계 특징을 만들어 넣은 정도(repo/src/features.py:115-141). 통계적 상호작용 분석은 없다.
- FN 조건: 최종 미탐 1개(이상 조각 3번)를 정상 분포 백분위로 비교. 진동은 정상과 겹치고 전류 변화가 큰 혼합형이며 시간 특징 추가로 확률은 올랐으나 0.5를 넘지 못했다고 서술(README §10, repo/analysis/abnormal3_analysis.py). 사례 수준이고 조건 정량은 없다. 랜덤포레스트 문턱 민감도 표는 OOF 확률로 계산한다(repo/analysis/error_analysis.py:111-130).
- FP 조건: 최종 모델 FP가 0이라 분석이 없다. 다른 조합의 FP가 시간 특징으로 해소된 사례를 뽑는 코드만 있다(repo/analysis/error_analysis.py:66-71).

## 4. 현장 활용
- 경보 단계: RED(랜덤포레스트 이상) / YELLOW(랜덤포레스트 정상·로지스틱 이상) / GREEN(둘 다 정상)(repo/src/alarm.py:38-41). OOF 기준 GREEN 정상 599·이상 1, YELLOW 이상 2, RED 이상 18(README §11). README는 "Random Forest"라고만 쓰지만 코드는 기본 통계 세트의 랜덤포레스트를 쓴다(repo/src/alarm.py:9).
- 점검 우선순위: 단계가 곧 우선순위라는 개념 수준이다.
- 작업자 행동·재보정 절차: 없음.
- 실시간 적용: 없음. 조각 전체를 요약해 판정하며 리드타임은 평가하지 않았다고 밝힘(README §13 6번).

- 오류 사례에서 착안해 센서 관계·시간 변화 특징을 단계적으로 추가했고, 두 분류기의 불일치를 경보 단계로 썼다.
- 불균형은 클래스 가중치로만 처리. 불확실성 추정·확률 보정·앙상블·설비 물리 지식 결합은 없다.

## 6. 코드·재현성
- 실행 진입점: 한 명령 `python main.py`(전처리→특징→5겹 OOF→경보, repo/main.py), 보조 분석 `python run_analysis.py`(main.py 산출물 필요, README §5).
- 의존성 정확히 고정(repo/requirements.txt), 프로젝트 루트 기준 상대경로(repo/src/config.py:3-6), 시드 42 고정. 데이터는 data/에 수동 배치. 예측결과는 실행해야 생성되며 저장소에 없다. 테스트 코드는 없다.
- 정적 점검 문제: *.csv 무시 규칙 때문에 결과 표와 예측 파일이 커밋되지 않았다. 하드코딩된 절대경로나 없는 파일 참조는 보이지 않았다.

## 7. 강점 3가지 / 약점 3가지
- 강점 1: 조각 단위 표본화, 공백 기준 민감도, 중복·결측 처리, 극단값 유지 등 전처리 근거가 분명하다.
- 강점 2: 8조합을 같은 분할로 비교하고 전처리를 파이프라인 안에서 적합해 겹 사이 전처리 누수가 없다. 한 명령으로 실행된다.
- 강점 3: 세션 차이, 오류를 본 뒤 설계한 특징, OOF는 독립 시험이 아님, 리드타임 미평가 같은 한계를 README에 솔직하게 적었다.
- 약점 1: 날짜가 다른 두 파일을 무작위 층화 5겹으로 지도 분류해, 세션·사건 의존성이 통제되지 않았다. F1 0.976은 과대평가 가능성이 크다.
- 약점 2: 오류를 본 뒤 특징을 설계하고 같은 OOF로 최종 모델을 골랐다. 독립 시험이 없다.
- 약점 3: 결과·예측 파일이 저장소에 없어 수치를 검증할 수 없다. FN/FP 조건 정량, 상호작용 분석, 현장 절차가 빈약하다.

## 8. 치명적 문제 (있으면)
- 학습·평가 사이 행 중복 같은 직접 누수는 없다.
- 결과 산출물과 테스트 예측결과 파일이 저장소에 전혀 없어 보고 수치를 산출물로 확인할 수 없다(실행하면 생성된다). 세션 차이 미통제는 약점 1로 적었다.
