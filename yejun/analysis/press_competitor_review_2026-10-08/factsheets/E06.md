## 1. 데이터 이해·진단
- 기록 단위(버스트·조각) 구조 [부분]: 0.15초 넘는 간격에서 기록 조각을 나누고, 조각은 수집 단위일 뿐 프레스 사이클이나 독립 고장으로 단정하지 않는다고 명시했다(`repo/src/pump_data.py` 47–55; README 공통 평가 원칙 7). 조각 수·길이 분포 같은 진단 결과는 없다.
- 샘플링 간격·시간 공백 [부분]: "구간 내부 약 0.1초, 구간 사이 공백 존재"라는 서술만 있다(README 프로젝트 소개 표).
- 중복 행 [부분]: 시각·값이 같은 중복은 제거하고 같은 시각에 값이 다르면 중단하는 처리 코드와 시험이 있다(`pump_data.py` 32–37; `repo/tests/test_data.py` 32–46). 실제 중복 건수 진단은 자료에 없다.
- 결측·이상치 [부분]: 결측·비유한 값·예상 밖 라벨이 있으면 중단한다(`pump_data.py` 24–31). 이상치 분석은 없다.
- 클래스 불균형 [없음]: 정상 20,000·이상 600행 수치만 있다.
- 정상·이상의 날짜 차이와 교란 [있음]: 라벨과 날짜(7/12, 7/17)가 겹쳐 고장 효과와 날짜 조건을 분리할 수 없고 재분할은 날짜 holdout이 아니라고 명시했다(`repo/docs/EVALUATION.md` '데이터 한계'; `repo/configs/split.json`; `pump_data.py` 73–78). 교란 크기를 잰 분석은 없다.
- 두 파일의 저장 방식 차이 [없음].
- 변수 의미 [부분]: AI0/AI1의 상·하부 대응과 센서 단위는 추가 확인이 필요하다고만 적었다(README).
- 이상이 한 사건뿐이라는 한계 [부분]: 조각을 독립 고장 1건으로 부르지 않고, 짧은 이상 세션이라 검증·시험이 매우 적다고 적었다(`EVALUATION.md` '기본 분할', `repo/docs/EXPERIMENT_PLAN.md` '경보').
- 전처리 내용: 중복 제거, 시간순 정렬, 조각 분할, 분할 매니페스트(`segments.csv`, `rows.csv`)와 감사 기록(`audit.json`, 파일 SHA-256·한계 문구 포함) 생성(`pump_data.py` 70–113).
- 진단 결과와 검증전략: 정상·이상을 각각 조각 단위 시간순 70/15/15로 나눈다(`split.json`; `pump_data.py` 58–67, 85). 창을 만들기 전에 조각 단위로 나누고, 스케일러·회귀는 학습분에서만, 문턱·규칙은 개발 데이터 안에서 정한다는 원칙이 있다(README 공통 평가 원칙 1–6). 공개 원본에 같은 규칙을 적용해 다시 세면 정상 599조각이 419/89/91, 이상 21조각이 14/3/4(시험 85행)이다. 시험 이상은 같은 사건의 마지막 4조각뿐이다(시험 코드도 21조각→14/3/4를 확인, `tests/test_data.py` 18–20).

## 2. 모델
- 베이스라인: 없음(계획: Logistic Regression·LightGBM, `EXPERIMENT_PLAN.md`).
- 비교한 모델: 없음. 계획 순서는 기준 모델 → 부하로 예측한 진동의 잔차 특징 → 강한 이상·지속 이상 경보 → 진동·전류 별도 판단 → PCA·IF·AE 보조 모델이다(`EXPERIMENT_PLAN.md`, README '모델 개발 계획').
- 최종 모델과 선정 근거: 없음. 선정 원칙(개발 데이터에서 목표 Recall·허용 오경보를 미리 정하고, 시험을 보고 조건을 바꾸지 않으며, 차이가 작으면 단순한 모델)만 있다(`EVALUATION.md` '최종 선정').
- 검증 설계: 분할 도구만 구현됐다. 계획대로면 지도학습에 이상 앞 70% 조각을 쓰고 시험은 같은 사건의 뒤 4조각이라 같은 사건 안의 평가다(문서가 스스로 인정). 문턱 후보를 평가 데이터에서 가져오지 않는다는 원칙이 있다(`EVALUATION.md` '평가 단위').
- 보고 성능: 없음. 지표 계획은 창·조각 단위 Precision·Recall·F1·AP·FP/FN·판정 커버리지다(`EVALUATION.md`).
- 이상 확률 산출 여부: 없음. "정상 점수나 p값을 보정된 고장 확률로 부르지 않는다"는 원칙만 있다.
- 누수·과대평가 위험: 구현이 없어 판단할 수 없다. 설계상 같은 조각이 학습·평가에 섞이지 않고 시간·파일명·라벨은 특징에서 뺀다(`pump_data.py` 77; README 원칙 1).

## 3. 영향요인·오류분석
- 영향변수·상호작용·FN 조건·FP 조건: 모두 없음. 실험 기록 양식에 FP/FN 집중 조건 칸만 있다(`repo/experiments/TEMPLATE.md`). 부하 조건부 진동 잔차는 계획 단계다.

## 4. 현장 활용
- 경보 단계·점검 우선순위·작업자 행동·실시간 적용·재보정: 모두 없음. 계획 수준으로 강한 이상·지속 이상 경보, 공백 뒤 경보 이력 초기화, 전류 단독 이상 때의 확인 항목을 적었다(`EXPERIMENT_PLAN.md` '경보').

## 5. 창의성·차별성
- 실제로 한 것은 없다. 부하 조건부 진동 잔차와 채널별 판단 불일치는 계획이다. 협업 체계(브랜치 전략, Issue·PR 양식, 실험 기록 양식, CI)를 갖춘 점은 과정 관리 측면의 특징이다.

## 6. 코드·재현성
- 실행 진입점: `python scripts/prepare_data.py`(데이터 점검·분할 산출물)와 `python -m unittest discover -s tests -v`. 학습·추론·예측 진입점은 없다.
- 의존성·경로·시드·데이터·테스트: 표준 라이브러리만 쓰고(requirements는 주석뿐), `Path(__file__)` 기준 상대 경로, 데이터는 `data/raw/`에 직접 넣도록 안내(Git 제외), GitHub Actions에서 파이썬 3.12로 시험과 compileall을 돌린다(`repo/.github/workflows/checks.yml`). 처리가 결정적이라 시드는 필요 없다.
- 정적 점검에서 보인 문제: 데이터가 자료에 없어 준비 도구도 그대로는 돌릴 수 없다(배치 안내는 있음). 문서가 참조하는 기존 보고서(HTML)와 모델 코드가 자료에 없다(`EXPERIMENT_PLAN.md` '아직 구현하지 않은 작업').

## 7. 강점 3가지 / 약점 3가지
- 강점 1: 날짜 교란, 조각의 비독립성, 기존에 본 자료의 시험 재사용 한계를 문서와 감사 기록의 한계 문구에 명시했다(`pump_data.py` 73–78).
- 강점 2: 조각 단위 시간순 분할, 중복·충돌 처리, 파일 해시 기록 등 누수를 막는 평가 원칙과 도구를 시험·CI와 함께 갖췄다.
- 강점 3: 같은 분할·같은 평가 모집단, 커버리지 보고, 시험 결과로 조건을 바꾸지 않는 선정 원칙 등 평가 규칙이 구체적이다(`EVALUATION.md`).
- 약점 1: 모델·비교·결과가 없어 예측모델, 오류분석, 현장 활용 요구를 충족하는 내용이 없다.
- 약점 2: 데이터 진단이 원칙 서술 수준이다(저장 형식 차이·불균형·변수 의미·공백 통계 진단 없음).
- 약점 3: 계획된 분할은 이상 21조각 중 4조각(85행)만 시험에 남아 평가가 매우 불안정하고, 지도학습 계획은 세션 교란을 그대로 안는다.

## 8. 치명적 문제 (있으면)
- 예측 모델과 결과가 없다. 분석 착수 전 단계의 준비 저장소다.
