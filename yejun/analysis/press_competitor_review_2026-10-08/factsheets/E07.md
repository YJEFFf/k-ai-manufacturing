(별칭 대체: 최종 탐지기 = 전류 파형 모양 경로 + 진폭 크기 경로를 합친 2경로 탐지기. 경로는 `entries/E07/` 아래 상대경로.)

## 0. 자료 범위

- 완성도: 중간. 탐지 모델과 시연 앱은 갖췄지만, README가 가리키는 원래 제출 폴더의 비교·오류분석·예측 스크립트와 결과가 이 저장소에 없다(`repo/vendor/experiment.py` 2–3행이 `predict.py`·`compare_models.py`·`error_analysis.py`를 언급).

## 1. 데이터 이해·진단
- 기록 단위 구조 [부분]: 0.2초 넘는 간격에서 burst를 나누고, burst 안 전류 봉우리 사이를 '사이클'(약 1.67초)로 정의했다(`repo/vendor/pdm_hybrid.py` 22–45). 10행 미만 burst는 버린다. 같은 규칙으로 다시 세면 정상 599개 중 69개(358행), 이상 21개 중 4개(19행)가 판정에서 빠지는데, 이 제외는 보고되지 않았다.
- 샘플링·시간 공백 [부분]: 업로드 데이터의 burst 안 간격이 0.09~0.11초인 비율을 검사한다(`repo/pdm_app/data_quality.py` 113–122). 공백 분포 진단은 없다.
- 중복 행 [있음]: 같은 시각 중복을 제거하고(`pdm_hybrid.py` 25), 정상 파일의 중복 1건을 알고 있어 센서 점검 기준에서 뺐다(`data_quality.py` 37–39).
- 결측·이상치 [부분]: 업로드 품질 점검(결측·비숫자·5행 이상 고착·물리적으로 불가능한 고립값·시각 역행)과 두 파일의 값 범위 제시(`data_quality.py` 1–22). 원본 데이터 점검 스크립트(`data_check.py`)는 인용만 있고 자료에 없다.
- 클래스 불균형 [없음]: 사이클 수(정상 756·이상 30)만 있다.
- 날짜·세션 차이 [부분]: "이상 데이터가 다른 날 하루치 파일 하나"라 일반화를 보장할 수 없다는 한계만 적었다(`repo/README.md` 7절). 교란 분석은 없다.
- 저장 방식 차이 [없음]: 진단하지 않았다. 사용 특징이 진폭·파형 기반이라 자릿수 차이의 직접 영향은 작아 보이나 확인되지 않았다.
- 변수 의미 [부분]: AI0 상부·AI1 하부 진동, AI2 전류로 표기(`repo/app.py` 그래프 라벨)하고 전류 0.6Hz 주기를 사이클로 썼다(`pdm_hybrid.py` 8). 전류 신호의 성격(교류 순시값, 10Hz 표본의 접힘)은 다루지 않았다.
- 이상이 한 사건뿐이라는 한계 [부분]: "30사이클, 약 2.7분" 한 파일이라는 서술만 있다(README 7절).
- 전처리: 중복 시각 제거, burst·사이클 분할, 모양은 20점 리샘플·z 정규화, 크기 특징 8개는 부호 보존 log 변환 뒤 학습 사이클로 표준화(`pdm_hybrid.py` 47–75).
- 진단 결과와 검증전략: 정상 burst를 시간순 10개 블록으로 나누고 블록마다 60/20/20을 학습·검증·시험에 배정한다(`pdm_hybrid.py` 103–109). 같은 burst가 학습과 평가에 섞이지 않는다. 같은 규칙으로 세면 정상 burst 310/110/110개다. 이상 30사이클은 모두 평가에만 쓴다. 진단이 분할 설계로 이어진 근거 서술은 없다.

## 2. 모델
- 베이스라인: 자료 안에서는 같은 탐지기의 모양 단독·크기 단독 원점수 판정(규칙 없음)만 비교 항목으로 출력한다(`pdm_hybrid.py` 97–100, 120–126). 지도학습·IsolationForest 비교용 입력 함수는 있으나(`repo/vendor/experiment.py` 86–105) 비교를 돌리는 스크립트와 결과는 없다.
- 비교한 모델(학습 방식): 위의 비지도 경로별 판정뿐이고 결과 수치는 없다.
- 최종 모델과 선정 근거: 모양 경로(전류 사이클과 정상 평균 파형의 RMS 거리)와 크기 경로(사이클 진폭·변동 특징 8개의 One-Class SVM, nu 0.01). 모양 경보는 1사이클 만에, 크기 경보는 문턱 초과 + 정상 중앙값보다 큰 특징이 하나 이상 + 2사이클 연속일 때 낸다(`pdm_hybrid.py` 60–95). 선정 근거와 비교표는 자료에 없다.
- 검증 설계: 정상 burst 시간 블록 분할, 이상은 전부 시험. 문턱은 정상 검증 사이클의 99.5 백분위로 이상 데이터를 쓰지 않는다(`pdm_hybrid.py` 67–69). 블록 안 60/20/20이라 블록 경계마다 학습·검증·시험 burst가 시간상 붙어 있다. 규칙 상수(2사이클 연속, '정상보다 큼' 조건, 99.5, nu)를 어떤 자료로 정했는지는 기록이 없다. 이상 데이터를 보고 정한 것은 앱의 파일 단위 5% 기준(정상 전체·이상 전체 경보율을 보고 정함, `repo/pdm_app/judge.py` 5–17)과 확률 보정기다.
- 보고 성능: 자료 안 수치는 앱 기준값뿐이다. 정상 파일 전체(학습 구간 포함) 경보 사이클 3/756(0.40%)·burst 3/530(0.57%), 이상 파일 전체 30/30 사이클·17/17 burst(README 4-1절, `judge.py` 5–10). 단위는 사이클·burst이고, 시험 구간만의 F1·혼동행렬은 없다. 결과 파일이 없어 경보 수치는 확인하지 못했고, 사이클·burst 수(756·530, 30·17)만 같은 규칙으로 재계산해 일치를 확인했다.
- 이상 확률 산출 여부: 있음(앱). 두 점수를 검증 중앙값 0·문턱 1로 정규화한 위험지수(`experiment.py` 55–62)에 로지스틱 보정을 하고, 학습 자료로 정상 검증 사이클과 이상 파일 전체 사이클을 쓴다(`repo/pdm_app/model_service.py` 45–49). 같은 이상으로 맞추고 같은 이상에 표시하는 표본 내 확률이며 화면에 고지한다. 이상 burst 단위 GroupKFold 확률 함수(`experiment.py` 95–105)는 호출하는 코드가 없다.
- 누수·과대평가 위험: ① 정상 경보율이 학습 구간을 포함한다(README가 밝힘). ② 확률 보정과 파일 5% 기준을 평가 대상 이상으로 정했다. ③ 10행 미만 burst 제외로 판정 범위가 줄었지만 보고하지 않았다. ④ 파일 판정이 사이클 비율과 burst 비율을 OR로 섞는다(`judge.py` 56). ⑤ 이상 30사이클은 한 사건의 조각이라 독립 표본이 아니다.

## 3. 영향요인·오류분석
- 영향변수 분석 방법과 결과: 경로별 탐지율 출력과 결함 주입 시험(진동 진폭 증가, 전류 진폭 증가, 전류 파형 왜곡, 강도 0~1.0; `pdm_hybrid.py` 130–165)이 코드에 있으나 결과 수치는 없다. 변수 중요도 분석은 없다.
- 변수 간 상호작용: 정상 학습 사이클에서 전류 RMS로 진동 RMS를 회귀하고 잔차 최댓값을 넘으면 '진동 과다'로 표시한다(`experiment.py` 48–51, 80–82). 결과는 없다.
- FN이 몰리는 조건: 없음. 'burst 첫 사이클 탐지' 지표 정의만 있다(`pdm_hybrid.py` 115–126).
- FP가 몰리는 조건: 부분. 저부하 구간(정상 행 15,900~18,400)을 표시하는 열과 크기 경보의 '정상보다 큼' 조건으로 조용한 구간의 오경보를 막도록 설계했다(`experiment.py` 15, 79; `pdm_hybrid.py` 91). 정량 결과는 앱 기준값(정상 3/756)뿐이다.

## 4. 현장 활용
- 경보 단계: 파일 단위 3상태(정상 작동·센서 점검 필요·이상 발생), 우선순위 이상>센서>정상(`judge.py` 40–91). 사이클 위험지수와 관리도식 추이 그래프(`app.py`).
- 점검 우선순위: 모양 경보가 우세하면 전기·구동·부하 계통, 크기 경보가 우세하면 체결·베어링 등 기계 계통부터 본다(`judge.py` 69–72). burst별 요약을 경보 순으로 정렬한다.
- 작업자 행동: 센서 문제 안내(결측·고착·불가능 값·시각 역행·샘플링), 사이클 결과 CSV 내보내기, 라벨이 있으면 혼동행렬(`app.py`).
- 실시간 적용: 없음. 파일 업로드 일괄 분석이며 크기 경보는 2사이클(약 3.3초) 연속이 필요하다.
- 재보정·운영 절차: 없음(경보량 목표·재보정 주기 없음).

## 5. 창의성·차별성
- 전류 파형 모양 거리와 진폭 OCSVM의 두 경로, 저부하 오경보를 줄이는 '정상보다 큼' 조건과 2사이클 지속 규칙, 센서 고장과 설비 이상을 나누는 판정과 합성 센서 오류 예시(`repo/pdm_app/samples.py`), 위험지수 정규화와 로지스틱 확률. 불확실성 추정·conformal은 없다(Wilson 구간 함수는 정의만 있음, `experiment.py` 118–122). 근거 수치가 자료에 없어 효과는 확인되지 않는다.

## 6. 코드·재현성
- 실행 진입점: `streamlit run app.py`(앱 시작 때 학습, 결과는 화면), `python vendor/pdm_hybrid.py`(학습·평가·주입 시험을 콘솔에 출력). 예측결과 파일을 만드는 진입점은 없다.
- 의존성·경로·시드·데이터·테스트: requirements 6개 판 고정(`repo/requirements.txt`), 코드 경로는 `Path(__file__)` 기준 상대 경로, 데이터 사본 포함, 시드 고정(합성 샘플 42, 주입 0, OCSVM은 결정적). 테스트 코드는 없고 README 6절의 수동 확인 기록만 있다.
- 정적 점검에서 보인 문제: README의 실행 명령이 특정 PC의 Windows 사용자 경로 python.exe로 하드코딩되어 있고 `cd web_app`도 현재 저장소 구조와 맞지 않는다(README 1절). `experiment.py`가 참조하는 다른 스크립트가 없다. README에 '3.' 절이 두 번 있고 "데이터를 복사하지 않음" 문장이 vendor 사본 설명과 어긋난다. `experiment.py`를 import하면 `results/` 폴더를 만든다.

## 7. 강점 3가지 / 약점 3가지
- 강점 1: 정상만 학습하고 문턱을 정상 검증 사이클 백분위로 정해 문턱 결정에 이상 데이터를 쓰지 않는다. 정상 burst를 시간 블록 단위로 나눠 같은 burst가 학습·평가에 섞이지 않는다.
- 강점 2: 전류 파형 모양과 진폭의 두 경로, 저부하 억제 조건과 지속 규칙처럼 해석 가능한 설계이고, 경보 근거별로 전기·기계 계통 점검을 권한다.
- 강점 3: 센서 품질 문제와 설비 이상을 구분하는 시연 앱이 완성돼 있다(업로드 검증, 오류 안내, 합성 센서 오류 예시, 결과 CSV, 한계 고지).
- 약점 1: 성능 근거가 없다. 시험 구간 F1·혼동행렬·베이스라인 비교·오류분석 결과가 자료에 없고, 제시 수치는 학습 구간을 포함한 경보율과 이상 전체 30/30뿐이다.
- 약점 2: 평가 대상 이상으로 정한 요소(파일 5% 기준, 확률 보정), 단일 사건 30사이클 평가, 짧은 burst 제외 미보고 때문에 과대평가와 판정 범위 문제가 있다.
- 약점 3: 데이터 진단이 좁다(저장 형식 차이·세션 교란·불균형·전류 신호 성격 미진단). 실행 안내가 특정 PC 경로에 묶여 있고 테스트·예측 파일·보고서가 없다.

## 8. 치명적 문제 (있으면)
- 탐지기 본체의 학습·문턱에는 이상 데이터가 쓰이지 않는다. 다만 모델 성능을 평가한 결과가 자료에 전혀 없어 예측모델의 성능 주장을 확인할 수 없다.
