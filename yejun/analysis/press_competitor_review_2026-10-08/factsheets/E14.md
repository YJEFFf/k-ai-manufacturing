# E14 팩트시트

## 0. 자료 범위
- 구성: README 있음(주요 결과표, 실행법, 평가 규칙) / 연구 보고서 마크다운 1개(약 660줄, `repo/research/reports/m15_phys_fusion_report.md`). 대회 제출 형식 보고서는 아니다. / 노트북 0개 / 파이썬 20개(가이드북 재현 1, 공통 모듈, 실행기, 시각화, 방법별 15개)와 셸 2개 / 결과: 점수 방식별 `metrics.json` 48개와 점수 분포 그림, `research/results/seed42/summary.csv·md`, 기준선 결과 1개 / 테스트 예측결과 파일 없음(점수 `scores.npz`는 `.gitignore`로 제외) / 데이터 미동봉.
- 완성도: 중간. 비교 실험과 연구 보고서는 충실하다. 하지만 과제가 요구하는 오경보 조건 분석, 현장 활용, 예측결과 파일, 이상 확률이 비어 있다.

## 1. 데이터 이해·진단
- 기록 단위(조각) 구조 [있음]: 정상 599개, 이상 21개 연속 구간, 최대 50샘플, 평균 4.5초(최대 16.6초) 공백. 가이드북이 공백을 무시하고 20행을 "2초"로 다룬다고 지적했다(보고서 §1.1). 코드의 구간 구분 문턱은 1.0초다(`repo/research/common.py:32`).
- 샘플링 간격·시간 공백 [있음]: Δt 중앙값 0.1초, 약 10Hz, 나이퀴스트 5Hz(보고서 §1.1, `methods/m06_oscillator.py:18`).
- 중복 행 [없음].
- 결측·이상치 [없음].
- 클래스 불균형 [부분]: 행·윈도 수를 제시하고 PR-AUC를 주지표로 삼았다. 정상만 학습하므로 별도 처리는 없다.
- 날짜 차이와 교란 [있음]: 7/12 대 7/17이므로 모델이 "다른 날의 세션"을 탐지할 가능성을 명시했다(README, 보고서 §8.3). 같은 세션의 과거 점수로 정규화하면 ROC-AUC가 0.51로 무너지는 결과를 근거로 들었다(`research/results/seed42/summary.md`, 시험 시점 적응 행).
- 저장 방식 차이 [부분]: 이상 파일 둘째 행부터 진동0이 정상 최댓값의 3배라는 관찰과, 전류 오프셋 +2.4σ 이동이 있다(보고서 §6.2, §8.3). 둘 다 이상 신호 또는 교란 정황으로만 해석했다. 정밀도·양자화·타임스탬프 형식 비교는 없다.
- 변수 의미 [부분]: 진동 2채널과 전류 1채널. 전류는 ±270 수준의 사인형 교류이고, 가이드북이 전류에도 절댓값을 취해 오프셋 정보가 흐려진다고 지적했다(보고서 §1.1, §7.2). 센서 위치·단위 설명은 없다.
- 이상이 한 사건뿐이라는 한계 [있음]: test 이상 180윈도가 독립 스트로크 6개이고, 실제 과제는 "세션 단위 탐지"라고 적었다(보고서 §7.3, §8.2).
- 전처리 [있음]: 부호를 유지한 z-score(train에만 맞춤)와 Δt 입력을 추가했고, 가이드북 방식(|x|+MinMax)도 병행한다(`common.py:59-68,100-102`).
- 진단→검증전략 [부분]: 가이드북과 비교 가능하도록 분할을 그대로 유지했다. 진단 결과는 신뢰구간 계산(스트로크 블록 부트스트랩)에만 반영했다(보고서 §2.1).

## 2. 모델
- 베이스라인: 가이드북 LSTM-AE를 재현했다(마지막 시점 복원 MSE). test PR-AUC 0.771, F1 0.643(`repo/results/baseline_seed42/metrics.json`).
- 비교한 모델: 정상만 학습하는 비지도 방법 다수(LSTM-AE 변형, 진동↔전류 교차 예측, 마스킹 트랜스포머, 스트로크 단위 트랜스포머, 공백·길이 예측, 시간 간격 인지 GRU, 감쇠 사인 오실레이터 AE, Koopman AE, 확산 복원, 메모리 AE, Deep SVDD, RealNVP, 시험 시점 적응)와 valid 이상 k개를 쓰는 준지도 1종. 같은 분할·문턱 규칙으로 48개 점수 방식을 비교했다(`summary.md`).
- 최종 모델과 선정 근거: 물리-밀도-확산 결합 모델이다. 오실레이터 AE의 물리 파라미터·인코더 특징에 대한 잠재 RealNVP 밀도와, 물리 파라미터를 조건으로 한 잔차 확산 오차의 robust z를 합한다. test PR-AUC 0.996, F1 0.960(오탐 1, 미탐 13)이다. valid PR-AUC는 잠재 밀도 단독과 1.000으로 동률이어서 "설계 의도"로 결합 점수를 골랐다(보고서 §5.1). 보고서는 "14개 방법을 test로 평가한 뒤 상위 세 방법을 골라 설계했다"고 스스로 밝힌다(§8.1).
- 결과표 누락: 스트로크 단위 트랜스포머(이전 8개 스트로크로 다음 스트로크 요약 예측)가 summary에서 test PR-AUC 1.000, F1 0.997(오탐 1, 미탐 0)로 가장 높다. 그런데 README 결과표와 보고서에서 언급도 설명도 없다(`research/results/seed42/m03_stroke_tf/next_stroke/metrics.json`).
- 검증 설계:
  - 분할: 정상 앞 15,000행이 train이다. 나머지 정상과 이상 전체가 평가 구간이며, 그 앞부분(정상 880·이상 300윈도)이 valid, 뒷부분(정상 4,000·이상 180윈도)이 test다(`common.py:96-121`).
  - 윈도: 20행 stride 1이 기록 조각 공백을 넘어 이어진다(`common.py:71-75`).
  - valid와 test는 같은 이상 사건의 앞·뒤이고 경계에서 원시 19행을 공유한다. 가이드북의 "120행 뒤 라벨" 규칙 때문에 이상 499~599행은 어떤 윈도에도 들어가지 않는다.
  - 학습·문턱: 모델은 정상만 학습하고 조기종료는 정상 valid로 한다(예: `methods/m15_phys_fusion.py:68-69,100,113`). 문턱은 valid의 정밀도=재현율 교차점으로 이상 라벨을 쓴다(`run_all.py:134`, `common.py:303-309`).
  - 정상 test는 시간상 뒤쪽 블록이다.
- 보고 성능: 윈도 단위 PR-AUC가 주지표이고 F1은 보조다. README 표 7행의 수치를 각 `metrics.json`·`summary.md`와 대조해 모두 일치함을 확인했다. 보고서의 스트로크 블록 부트스트랩 신뢰구간, 라벨 없는 99% 문턱 F1, 사후 점수 앙상블(0.999), 채널 교체 실험, 물리 파라미터 이동표는 계산 코드와 결과 파일이 저장소에 없어 확인할 수 없었다.
- 이상 확률 산출: 없다(점수와 문턱만).
- 누수·과대평가 위험:
  - 최종 구조를 test 결과를 보고 설계했다(본인 인정).
  - valid·test가 같은 사건의 인접 구간이고 경계 행을 공유한다.
  - test 이상은 독립 스트로크 6개뿐이다.
  - 세션 교란이 해소되지 않았다.

## 3. 영향요인·오류분석
- 영향변수 분석 방법과 결과:
  - 결합 모델 헤드 소거: 잠재 밀도 0.987, 잔차 확산 0.814, 결합 0.996, 물리 복원 추가 시 0.968(`research/results/seed42/m15_phys_fusion/*/metrics.json`).
  - 진동 2채널 전용 변형: 0.985(`m16_phys_fusion_vib/latent_nll`).
  - 마스킹 AE 채널별 점수: 전류 0.459, 진동0 0.844, 진동1 0.847.
  - 보고서에는 최종 모델이 아닌 같은 구조의 구성 요소 모델로 얻은 분석이 있다. 이상 시 진동1 주 주파수 −5.0σ, 전류 오프셋 +2.4σ 이동, 그리고 밀도 모델에서 이상 윈도의 전류를 정상으로 바꾸면 ROC가 0.946으로 가장 크게 떨어진다는 결과다(보고서 §6.2-6.3). 해당 코드는 없다.
- 변수 간 상호작용: 교차 센서 예측(전류→진동 PR-AUC 0.795, 진동→전류 0.281) 정도다. 상호작용을 정량화한 분석은 없다.
- FN이 몰리는 조건 [정성]: 상위 세 방법의 미탐 윈도가 거의 겹치지 않는다는 서술이 있다(보고서 §1.3, 코드 없음). 조건별 정량은 없다.
- FP가 몰리는 조건 [없음]: 혼동행렬의 개수만 있다.

## 5. 창의성·차별성
- 실제 타임스탬프를 쓰는 감쇠 사인 물리 디코더와, 그 파라미터 공간의 밀도(정규화 흐름) 및 조건부 확산을 결합했다(`methods/m06_oscillator.py`, `m15_phys_fusion.py`).
- Koopman 고유값으로 0.6/1.79/3.6Hz 모드를 교차 확인했다(보고서 §6.2).
- 같은 세션 점수 정규화로 교란을 점검하고(`methods/m14_tta.py`), 스트로크 블록 부트스트랩을 썼다.
- 가이드북 점수 계산 결함을 찾았다. 마지막 시점 대신 윈도 평균 MSE를 쓰면 0.771에서 0.943이 된다(`m00_lstm_ae/mean/metrics.json`).
- 앙상블은 사후 계산뿐이고, 확률보정은 없다.

- 의존성은 버전 고정(`repo/requirements.txt`, torch 1.13.1 등)이고 시드를 고정한다(`common.py:43-47`, cuDNN 결정론 설정 없음). 경로는 저장소 기준 상대경로다(`common.py:23`). 데이터는 다운로드 후 최상위에 두라고 안내한다. 예측결과 파일과 테스트는 없다.
- 정적 점검에서 보인 문제:
  - 두 셸 스크립트가 사용자 홈의 특정 conda 환경 파이썬 경로를 하드코딩했고(`run_baseline.sh:10`, `research/run_all.sh:12`), README가 안내하는 환경 이름과 다르다.
  - 보고서 재현 절이 절대경로를 쓴다.
  - 보고서 수치 일부를 만드는 코드가 없다.
  - 시험 시점 적응 방법은 gitignore된 LSTM-AE 가중치에 의존한다(없으면 재학습).

## 7. 강점 3가지 / 약점 3가지
- 강점
  1. 가이드북 기준선을 재현하고 같은 분할·같은 문턱 규칙으로 48개 점수 방식을 비교했다. README 수치가 결과 파일과 일치한다.
  2. 한계 공개가 구체적이다. test 오염, 독립 스트로크 6개, 세션 교란을 밝혔고, 교란 증거(같은 세션 정규화 시 붕괴)와 블록 부트스트랩도 제시했다.
  3. 물리 디코더·밀도·확산 결합 같은 방법 독창성이 있고, 가이드북의 점수 계산·전류 절댓값 문제를 정량으로 지적했다.
- 약점
  1. 최종 모델을 test를 보고 설계했고 valid 동률을 설계 의도로 정했다. test 최고 방법이 설명 없이 결과표에서 빠졌다.
  2. 중복·결측·저장 형식 진단, FN/FP 조건 분석, 현장 활용, 이상 확률이 없다. 과제가 강조하는 오경보 조건 분석이 비어 있다.
  3. 윈도가 기록 공백을 넘고 크게 겹친다. valid와 test가 같은 사건에서 인접하고, 예측결과 파일이 없으며, 보고서 수치 일부를 재현할 코드가 없다.

## 8. 치명적 문제 (있으면)
- 최종 모델 설계에 test 결과를 사용했다(보고서 §8.1에서 인정). 보고 수치는 낙관적 추정치이며, 같은 사건 안의 6개 스트로크로만 평가됐다.
