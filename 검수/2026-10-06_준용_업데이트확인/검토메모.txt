2. 준용의 확인 요청

답변 위치: PR #3 댓글.
마감: 2026-10-07(수) 12:00 KST.
요청 조건: 본인이 PDF를 직접 읽고, 각 답에 PDF 쪽 번호를 적을 것. AI 요약을 그대로 붙여 넣지 말라는 요청이 있다.

아래는 직접 확인할 때 사용할 근거 안내다.

질문 1 — IsolationForest+R1 결과와 v2 선택 근거
PDF 18~19쪽(기본 비교표는 17쪽).
- IsolationForest+R1 test 실시간 F1: A 1.000, B 1.000.
- valid 사건 앞부분을 포함하면 평균 F1은 IsolationForest+R1 0.426, v2+R1 0.997.
- 이상 흐름을 test부터 따로 시작하면 IsolationForest+R1은 0.612/0.609, v2+R1은 1.000/0.995.
- 보고서는 첫 경보 생성, 정상 오경보, 해석 가능한 성분 및 데이터 조건으로 v2 사용을 설명한다.
- 다만 max|z|+R1, v1+R1이 v2+R1과 거의 같아서 R1을 붙인 뒤 v2의 추가 성분이 기여하는 정도는 이 자료로 분리하지 못한다고 19쪽에 명시한다. v2가 모든 단순 대안보다 우월하다는 답은 부정확하다.

질문 2 — 최종 모델 선택의 성격과 잠금 모델
PDF 20~21쪽.
- 최종 v2+R1+R2 선택은 통계적 우월성의 증명이 아니라 설계 판단이라고 21쪽에 명시한다.
- 잠금 규칙: valid F1 차이 0.002 이내면 더 단순한 모델.
- 잠금 선택은 v2+R1, test F1 A 1.000 / B 0.9954.
- 고부하 정상의 크기 단독 경보를 파형으로 확인하기 위해 R2를 최종에 추가했다. R2 효과를 이미 본 데이터에서 확인했고 진동 단독 이상 탐지 손실이 있다는 단서가 붙는다.

질문 3 — 이상 양상별 점검표
PDF 32쪽.
- 상부 진동만 큰 기록은 5개: 기록 11·12·14·16·18.
- 점검 순서: 상부 센서 쪽 체결·지지와 센서 부착 → [정지] 커플링 정렬 → 흡입측.
- 전체 양상: 상·하부 모두 큼 9, 상부만 큼 5, 진동 정상·작음/전류만 이상 3, 판단 보류 4.
- 21기록은 독립 고장 21건이 아니라 하나의 사건을 잘라 놓은 것이다. 유형은 고장 종류가 아니라 사건 안 기록별 양상이며 원인 진단도 아니다. 점검 순서는 현장 관례에 따른 추정이다.

질문 4 — 이상 확률 보정·Brier·55% 상한
PDF 22쪽.
- v2 점수를 valid 정상 행(0)과 이상 행(1)에 단조 회귀로 맞춘다. test 행으로 이 함수를 학습하지 않는다.
- test 파일의 실제 이상 행 비율을 사전확률로 쓴 Brier: A 0.0046, B 0.0038.
- 현장 사전확률 1%를 쓴 Brier: A 0.018, B 0.012.
- 표시 정책으로 우도비를 보정 기록 수+1=121에 제한한다. 사전확률 1%에서 0.01×121/(0.01×121+0.99)=0.55라 최대 55%다. 이는 자연적으로 도출된 고장 확률의 상한이 아니라 코드의 표시 정책이다.
- 55% 상한은 현장 1% 확률 열에만 해당한다. 파일 비율 사전 확률 열의 최대값은 A 0.905530, B 0.865411이다.
- 파일 비율 사전은 test 라벨의 구성비를 사용한 사후 평가 조건이다. 현장에서 사전 비율을 모르는 상황의 성능과 구분해야 한다. 보고서는 이 조건을 명시한다.

질문 5 — 전체 실행과 재생성하지 않는 항목
PDF 38~39쪽.
- 전체 대조 26개, quick 대조 19개. 전체 약 56분은 작성자가 보고한 실행 시간이다.
- run_all.py가 다시 만들지 않는 항목: 2.6절 UCI 외부 실험, 2.4절 단순 규칙 F1, 4.2절 콘솔 화면. v1·v2·v3 개발 당시 결과를 인용했다.
- 새 이상 확률과 Brier는 이번 버전부터 재생성 범위에 포함된다.

질문 6 — 직접 수정할 곳 3개: 아래는 AI 검토자가 제안하는 후보이며 사용자의 판단을 대체하지 않는다.

(가) PDF 19쪽, LSTM 비교 설명
문제: ‘위 표의 0.289·0.238과 직접 비교하지 않는다’는 문장 바로 위에는 +R1 결과 0.998/0.998 표가 있다. 직접 비교하지 않는 대상이 가이드북의 기존 점수인지 비교 모델 자체인지도 모호하다.
수정안: ‘가이드북의 기존 F1 0.7476은 평가 조건이 달라 참고값으로만 제시한다. 모델 간 비교에는 17쪽 주 비교표의 동일 조건 재평가 결과(A 0.289, B 0.238)를 사용하며, R1 적용 결과는 위 사후 비교표에 별도로 제시했다.’

(나) PDF 14쪽, R1의 ‘확인된 이상’
문제: 고장 원인을 확인한 상태로 읽힐 수 있으나 구현은 자기 경보 2행 또는 이전 경보가 기록 끝까지 유지됐는지를 판단한다.
수정안: ‘직전 기록이 끝난 지 60초 이내이고 경보 지속 조건(자기 경보 2행 이상 또는 이어받은 경보가 기록 끝까지 유지됨)을 충족하면, 새 기록 첫 행부터 경보를 이어받는다.’

(다) PDF 37쪽, ‘시각을 계산값으로 보고’
문제: 5쪽에서는 실제 표본 간격과 시각 생성 방식이 미확인인 추정이라고 했는데, 5장에서는 계산된 시각으로 확정한 것처럼 읽힌다.
수정안: ‘계통 60Hz 및 접힘 가정 아래 표본 간격 후보를 약 99·101ms로 계산했다. 실제 표본 간격과 시각 생성 방식은 확인하지 못했으므로, 실측 타임스탬프 확인을 수집 개선의 첫 단계로 제안했다.’

추가 편집 후보: 11쪽 고장 모드 표에는 기계적 고장 5개 외에 계측·수집 이상이 추가되어 있다. 첫 열을 ‘원인 후보’로 바꾸면 앞선 질문에서 생긴 혼동을 줄일 수 있다. 24쪽 V1~V5도 모델 v1~v3와 다르게 ‘검증 V5’ 등으로 풀어 쓰는 편이 좋다.

질문 7 — 예상 심사 질문과 답의 근거
질문 후보: ‘IsolationForest+R1도 test F1이 1.000인데, 복잡한 v2를 쓴 이유와 실제 기여는 무엇인가?’
답변 근거: ‘한 사건이 이어지는 test에서는 경보 유지의 영향이 크므로 test F1만으로 v2의 우수성을 주장하지 않는다. 사건 앞부분을 포함한 valid, 상태를 초기화한 test, 정상 오경보, 경보 근거의 해석 가능성을 함께 봤다. 다만 max|z|+R1과의 차이는 충분히 입증하지 못했다. 이 연구의 확인된 기여는 기록 경계 미탐과 정상 고부하 오경보를 분해하고 R1·R2의 효과와 손실을 분석한 데 있다.’ (18~21, 24, 26~28쪽)

질문 8 — 남은 역할
발표자료 초안(10/8 제출물)을 맡을지 회신해 달라는 요청이다. 이 메모로 사용자의 역할 수락을 대신하지 않았다. 최신 PDF 42쪽의 만족도 조사 화면도 아직 ‘예시’ 표시가 남아 있어 실제 완료 화면 교체가 필요하다.

3. 이번 검토에서 직접 확인한 범위

- GitHub 최신 PR 댓글·브랜치·커밋과 요청 파일을 읽었다.
- 최신 PDF에서 질문별 페이지를 확인했고, 19·22·32·42쪽은 이미지로도 확인했다.
- ZIP CRC 검사 이상 없음, 288개 파일.
- ZIP의 원본 CSV 2개가 작업공간 원본과 SHA-256 기준으로 같았다.
- 저장된 산출물을 expected_results.json과 대조한 26개 항목이 모두 일치했다. 전체 모델을 재학습해 26개를 재생성한 검증은 아니다.
- 제출 예측 CSV에서 TP/FP/FN을 다시 세었다. 최종 모델은 A·B 각각 TP 324, FP 0, FN 0, F1 1.000. 잠금 모델은 B FP 3, F1 0.9953917051.
- 제출 확률 열로 Brier를 다시 계산했다. 파일 비율 사전 A 0.0045582297, B 0.0038062106. 현장 1% 사전 A 0.0182487648, B 0.0124536693.
- ZIP 제출 예측 파일과 Git에 올라온 tvt 출력 예측 파일은 줄바꿈 정규화 후 동일했다.
