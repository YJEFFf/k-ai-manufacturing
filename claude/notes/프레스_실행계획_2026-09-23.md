## 핵심 설계 계약 (v2 신규)

**점수 → 보정 → 경보의 단위와 기준셋**

| 단계 | 기준셋 | 단위 | 설명 |
|---|---|---|---|
| 점수 정규화 | 정상 **학습** | 행 | 각 성분(max-z, 사인)을 학습 ECDF 꼬리 −log10 p로 → `fmax`로 결합. 이건 **고정된 점수 함수**일 뿐 p값이라 주장하지 않음 (07과 동일 → 재현 가능) |
| 보정 | 정상 **보정** | 기록구간 (segment_max) | 결합 점수의 구간 최댓값 분포로 conformal p값: `p = (1 + #{cal 구간 max ≥ s}) / (n_cal + 1)` |
| 경보 | 같은 보정 문턱 | 행 → 구간 첫 알림 | p ≤ α(1·3·5%)면 경보. 확률 열과 경보 열의 단위 일치 |

- 행 단위 보정(예준 비교용)은 07과 같은 `cutoff_at_budget` 문턱만 쓰고 p값 열은 만들지 않는다. **conformal p값·오경보 보장은 구간 단위에서만** 주장한다
- 재현 경보(07 문턱)와 conformal 경보(p ≤ α)는 **별도 열**. 둘이 같은지는 단위 테스트로 확인하고, 다르면 차이를 그대로 보고
- 보고서 용어: **"정상 이탈 p값(오경보 상한)"**, `anomaly_score = 1 − p`. "이상일 확률(사후확률)"이라 쓰지 않는다. 사후확률(Platt)은 이상 행을 보정에 써야 해서 하지 않는다
- 보장 범위: 정상 구간이 교환가능할 때 **구간 단위 주변(marginal) 오경보율 ≤ α**. 시간 자기상관·날짜 교란으로 가정이 약함을 명시하고, 실제 평가 구간 오경보율을 옆에 적는다
- `fmax` 결합의 p값 문제: 결합 점수를 **보정셋에서 다시 보정**하므로 최종 p값은 결합 점수 하나에 대한 conformal p값 → 유효

**창 길이 w — 라벨 없는 선택 규칙 (v3)**
- 정상 학습 구간을 시간순으로 **학습-A(앞 80%) / 학습-B(뒤 20%)**로 다시 나눈다. 사인 ECDF·스케일러는 학습-A로만 만든다
- 후보 w ∈ {5,6,8,10,12}. 각 w로 결합 점수를 만들고 **정상 보정 구간** 1% 구간 예산 문턱을 정한 뒤, **학습-B**에서 알림 구간 비율을 잰다. 이때 모든 후보가 판정하는 행(구간 내 12번째 관측 이후)만 센다 → 판정 행 수를 맞춰 큰 w가 유리해지는 편향 제거
- 가장 낮은 w 선택(동률이면 작은 w). 이상 데이터 미사용
- 한계로 명시: 라벨 없는 규칙은 검출력을 보지 못한다 → "오경보가 가장 안정적인 창"을 고르는 규칙이지 최적 창이 아니다
- 이 규칙이 고른 w의 결과를 **주 결과**, w=8(탐색에서 정한 값)과 5~20 민감도는 부록
- 결합 구조(max-z + 사인)를 이상 데이터를 본 뒤 떠올렸다는 사실은 보고서 모델 선정 근거에 그대로 쓴다

  - (b) 단위 테스트: 구간 단위에서 `p ≤ α` 경보 집합 == `cutoff_at_budget` 문턱 경보 집합 (다르면 차이 행 수 보고)

  - 보고용(수용 기준 아님): 정상 **평가** 구간의 실제 오경보율을 예산 옆에

### T2. 테스트 예측 파일 — 최소형 (≈0.3h)
- `predictions_test.csv`: 두 분할 × 평가 행(정상 평가 + 이상 600). 열: `split, source, record_uid, row_in_record, timestamp, is_scored, score_maxz, score_sine, score_comb, p_value, anomaly_score(=1−p), alarm, alarm_reason(maxz/sine/both), budget(=1% 구간)`
- `source`는 출력 메타데이터일 뿐 입력이 아님. 추론 함수 입력은 센서 3열 + TimeStamp만
- **수용 기준**
  - 분할별 행 수 = 정상 평가 행 + 600 (코드에서 계산해 assert)
  - `0 < p_value ≤ 1`
  - 라벨 우회 검사: 평가 행을 **기록구간 단위로 섞어** 추론 → 행별 결과 동일 (순서·파일 출처에 의존하지 않음)
  - 파일에서 다시 센 알림 구간 수 = 평가표 값
- README: 공식 테스트셋이 없어 자체 평가셋, 이상 600행은 두 분할 공유 + 결합 구조 탐색 때 본 데이터. [[문의메일_초안]]에 "별도 테스트셋 제공 여부" 문항 추가

### T1b. 베이스라인 IF·AE (≈0.5h)
- IF: `IsolationForest(random_state=0)` 기본값, 3센서 표준화 행 입력
- AE: 구간 안 최근 5관측 × 3센서 표준화 = 15차원(RMS5와 같은 창, 앞 4관측 미판정), `MLPRegressor(hidden_layer_sizes=(8,3,8), random_state=0, max_iter=300)` 정상 학습만, 점수 = 재구성 MSE
- **수용 기준**: 두 모델이 비교표에 모델당 12설정(2분할×2단위×3예산)으로 들어가고, 보정 구간 알림 ≤ 예산 (구성상 참이므로 코드 버그 검사용)

### T3. 영향요인·오류 분석 (≈1h)
- 영향요인: 경보 행에서 max-z를 만든 센서 비율(AI0/AI1/AI2), 규칙 발화 비율, 정상 vs 이상 성분별 분포
- FN: 놓친 이상 행 — 구간 내 위치(사인 미판정 첫 w−1행인가), max-z 값, 구간 길이
- FP: 정상 알림 구간 — 전류 진폭, 진동 표준편차, 구간 길이, 발화 규칙
- 그림: 진동 수준 × 사인 R² 산점도(색 = 정상/이상/알림), 구간 내 위치별 재현율
- **수용 기준**: FN 행 합계 = 평가표 fn, FP 알림 구간 수 = 평가표 정상 알림 구간 수

### T4. 진단 보고 (≈0.5h)

- 그림: 정상/이상 전류 파형 + 사인 피팅, 구간 길이 분포
- **수용 기준**: `diagnosis.md`는 코드가 템플릿에 값을 채워 생성 → 원천 CSV를 바꿔 재실행하면 문서 수치가 바뀌는지 1회 확인
