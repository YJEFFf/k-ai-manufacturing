## ① 사출성형기 — `1_사출성형기/`

| 파일 | 행×열 | 내용 |
|---|---|---|
| `moldset_labeled_cn7.csv` | 1,211×26 | 제품 CN7, `PassOrFail` 있음 — 1이 17건(1.4%) |
| `moldset_labeled_rg3.csv` | 1,182×26 | 제품 RG3, 1이 25건(2.1%) |
| `moldset_unlabeled_cn7.csv` | 35,239×25 | 라벨 없음 |
| `moldset_unlabeled_rg3.csv` | 35,941×25 | 라벨 없음 |

- **변수 24개**: 사출·충전·가소화·사이클·형체 시간, 쿠션·가소화·형개 위치, 최대 사출속도·스크류 RPM(최대·평균), 최대 사출압·전환압·배압(최대·평균), 배럴온도 1~6, 호퍼온도, 금형온도 3·4
- 전 컬럼 **Z-표준화**(평균 0) → 실제 공정값(℃, bar)을 모름. 파일마다 따로 표준화됨
- `Unnamed: 0` = 원래 인덱스뿐, **타임스탬프 없음**
- 라벨셋은 고유값 수가 매우 적음(컬럼당 1~50개) → 같은 조건이 반복 기록된 형태. `Clamp_Open_Position`은 라벨셋에서 상수(0)
- `PassOrFail` 0/1 중 어느 쪽이 불량인지 설명 문서 없음(소수 클래스 1을 불량으로 추정)
- 활용 포인트: 무라벨 7만 행 → 준지도·이상탐지 여지. 한계: 불량 42건으로 모델 40점·오류분석 15점을 버티기 어려움

## ② 용접기 — `2_용접기/`

| 파일/시트 | 행×열 | 내용 |
|---|---|---|
| `Welding Data Set_01.xlsx` › `Raw data` | 11,939×10 | 용접 1건 = 1행 |
| › `result` | 23×7 | 날짜 × 불량유형별 **불량 개수** |
| › `data set` | 10×3 | 변수 설명·수집 범위 |
| `scaled_data.csv` | 11,939×5 | Raw의 가압력·전류·전압·통전시간을 0~1 스케일링(결측 15~23개) |

- Raw 변수: `idx`(날짜마다 1부터 다시 셈), 설비 `Spot-01` **1대**, 품목 `65235-25800` **1개**, 작업일자(**날짜만, 시각 없음**), 소재두께1·2(**0.7mm 고정**), 가압력(bar), 전류(kA), 전압(V), 통전시간(ms, 70~73 정수)
- 기간: 2020-03-24 ~ 04-07 중 9일(일 669~2,000건)
- `result`: 불량유형 1=파임불량, 2=용접부족, 3=크랙발생. 하루 0~3개, **총 약 39건**. 3/27은 Raw에는 있고 result에는 없음
- ⚠️ 어느 용접이 불량인지 연결할 키가 없음 → 지도학습 불가. 할 수 있는 건 일 단위 집계 상관이나 비지도 이상점수뿐
- 두께·설비·품목이 고정이라 출제문의 "소재 두께에 따른 변화"는 분석 불가

## ③ 소성가공 예지보전 — `3_소성가공_예지보전/`

| 파일 | 행 | 시각 범위 | 연속 구간 |
|---|---|---|---|
| `press_data_normal.csv` | 20,000 | 2022-07-12 00:00:00 ~ 01:16:55 | 599블록 (1초 넘게 빈 곳 598곳) |
| `outlier_data.csv` | 600 | 2022-07-17 10:51:07 ~ 10:53:53 | 21블록 |

- 컬럼: `TimeStamp`(ms), `AI0_Vibration`(상부 진동), `AI1_Vibration`(하부 진동), `AI2_Current`(모터 전류), `Equipment_state`(정상 파일=0, 이상 파일=1 **상수**)
- 샘플 간격 0.1초(10Hz)이며, 짧은 블록이 띄엄띄엄 이어짐. 블록당 평균 약 33행(3초)
- 값 차이가 뚜렷함: 진동 범위 정상 ±0.4, 이상 −1.5~1.8. 전류 평균 정상 1.4, 이상 57 → 분류는 쉬워 보이지만 **날짜·운전조건 차이를 학습할 위험**이 있음
- 고장 전→후로 이어지는 흐름, 고장 시각, 정비이력이 없음 → "조기" 탐지(리드타임)는 검증 불가

## ④ X-ray 검사장비 — `4_X-ray_검사장비/` (2.3GB)

```
4_X-ray_검사장비/
├─ test1/yolov3/                         YOLOv3(ultralytics 구버전) 코드 일체 + 예제 15장
│   ├─ X선이물검출기(06.23_09.22)/        ★ 원본 BMP
│   │   ├─ 1호기 SN77128  40일 폴더  1,031장
│   │   ├─ 2호기 SN77127  40일 폴더    920장
│   │   └─ 3호기 SN12053  40일 폴더    858장   (2020-06-22 ~ 09-18)
│   └─ weights/last.pt (250MB)
├─ 라벨링 6종 세트/
│   ├─ images 15 / 50 / 100 / 200 / 300 / 400   JPG (앞 세트를 포함하며 누적 → 고유 400장)
│   └─ labels/  YOLO txt 500개 (class 0 = defect, 1,147박스)
├─ OpenLabeling-master/                   라벨링 툴 + PASCAL_VOC xml 833개
├─ 실습별 가중치파일/ last15~last400.pt   6개 × 250MB (세트 크기별 학습 결과)
└─ yolov3_20201200.ipynb                  실습 노트북
```

- 원본 폴더 이름이 전부 `*_NgImage` → **불량(NG) 판정 영상만 있음**. 정상품 영상이 없어 오경보율을 잴 수 없음
- 라벨 박스가 매우 작음(폭·높이 약 1~3%) → 소형 객체 탐지
- 팀원 실사: 원본 2,532장 전부에 색 검출 표식이 그려져 있음 → 모델이 표식을 학습할 위험(누수). 표식 제거가 선행 과제
- 파일 중 `.jpg`로 이름이 잘못 바뀐 코드 파일(`README.jpg`, `train.jpg` 등)이 섞여 있음. 배포본 그대로라 손대지 않았음
- 3개 호기 × 40일 → 호기·날짜별 일반화 분석 재료는 5개 중 가장 풍부함

## ⑤ 자원 최적화 — `5_자원최적화/`

`okm_augumented_2021.csv` 6,168행 × 18열, 2021-01-01 ~ 09-14 (257일 × 24행)

| 컬럼 | 의미·관찰 |
|---|---|
| `날짜`, `시간` | 시간은 0~23이어야 하는데 최대 188 → 7/13·7/15의 48행 오류 |
| `15분` `30분` `45분` `60분` | 시간 내 15분 단위 전력(0~222) |
| `평균` | 위 4개의 평균 → 타깃 시점에 입력하면 누수 |
| `생산량` | 0~9,830 |
| `기온` `풍속` `습도` `강수량` | 기상(풍속 결측 3, 강수 결측 1) |
| `전기요금(계절)` | 3개 값 — 1~2월 109.8 / 3~5·9월 167.2 / 6~8월 191.6 (계절 요금 단가) |
| `day` `d` `m` | 요일(1~7)·일·월 |
| `공장인원` | = 생산량 ÷ 전력합으로 계산된 파생값 → 누수(결측 17) |
| `인건비` | 1.0 / 1.5 두 값 — 요일과 무관, 의미 설명 없음 |

- 파일명부터 `augumented` → 증강 데이터. 하루 96개 전력 패턴 중 고유 142개, 반복 115일(팀원 실사)
- 설비별 전력, 제품 종류, 작업 스케줄이 **없음** → 가동시점 조정 제안은 가정에 기반한 시뮬레이션만 가능
- 출제문(피크 예측·저감)과 데이터 구조가 가장 잘 맞음. 시간순 검증도 가능

## 선정 관점 메모

- 서면평가 공통 지표가 "이상 확률 예측, F1, FN/FP"로 분류 과제 기준이라 ⑤(회귀)는 **피크 초과 경보 분류**를 함께 제시해야 지표에 맞음
- **정답 구조의 완결성** 순서: ⑤ > ③ ≈ ① > ④ > ②
- **데이터 규모·풍부함** 순서: ④ > ① > ⑤ > ③ > ②
- ②는 출제문이 요구하는 불량예측의 정답이 데이터에 없음 → 사실상 제외
