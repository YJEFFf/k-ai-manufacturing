  7. 분석 결과 100점
  8. 검증·일반화를 위해 여러 방식과 **외부 데이터**를 사용했다

## 1. RALPLAN-DR 요약

**원칙**
1. 실제로 실행한 절차·수치만 쓴다. 모든 수치는 근거 파일에 연결한다
2. 사용자 스토리라인을 따르되, 장 순서는 채점 6문항 양식에 맞춘다
3. 강점(1.000, 가설 채택)은 앞에 두고, 한계는 짧게 하지만 빠짐없이 쓴다
4. 외부 데이터 일반화는 실패해도 그대로 쓴다. 성공만 골라 쓰지 않는다
5. 남은 5일 안에 끝나는 범위로 잡는다

**결정 요인 (상위 3)**: (1) 서면평가 득점, 특히 모델 40·오류 15 (2) 심사위원 검증에 견디는 정직성(코드 zip과 보고서 일치) (3) 일정

**선택지**
- A. 스토리라인을 장 안에 녹인다(양식 6장 유지). 장마다 첫 문단을 스토리 연결 문장으로 쓴다
  - 장점: 채점 항목과 1:1이라 점수 누락이 없다
  - 단점: 이야기 흐름이 장 경계에서 끊긴다
- B. 스토리 순서로 장을 재구성한다(서론·구조·결함·case·분석·검증)
  - 장점: 읽기 흐름이 좋다
  - 단점: 양식 위반 위험, 채점자가 항목을 찾기 어렵다
- C. A + 표지 '내용요약'과 1장 앞 '분석 흐름도' 1쪽에 전체 스토리를 압축한다
  - 장점: A의 단점을 보완한다
  - 단점: 1쪽이 추가된다
- **채택: C.** B는 양식의 "작성 요령" 구조(장별 배점 표기)와 맞지 않아 기각한다

**외부 검증 선택지**
- E1. v3 생성기로 시험 정상 기록에 인공 고장을 주입해 탐지율(POD)을 잰다
  - 주입: 진동 대역 잡음, 감쇠 충격, 전류 잔차
  - 손실: 전류 감소·무효
  - 대상: 최종 모델, v2, v3 B1
- E2. SKAB(펌프 시험대, 진동 RMS 2·전류·압력 등, 1Hz, 라벨 있음, 고정판)에 같은 구조를 다시 학습시킨다
  - v2형 성분(max|z| + AR 잔차) + H1(사건 지속) + H2(진동 단독 경보를 다른 채널로 교차 확인)
  - 규칙을 넣기 전후 F1을 비교한다. 예준이 정정한 30그룹 분할과 주석 충돌 237개 마스크를 쓴다
- E3. UCI 유압(예준 기존 결과): v2 구조를 그대로 옮기면 실패한다는 결과를 인용한다
- **채택: E1 + E2 실행, E3 인용.** Beihang·ESPset은 일정상 제외하고 그 이유를 쓴다

## 2. 장별 내용 (스토리라인 대응)

**표지 내용요약 (6줄)**
- 프로젝트명(안): "데이터 결함 진단과 고장 지속성 가설에 기반한 프레스 유압펌프 실시간 이상 경보"
- 결함 진단 → case 분할 → 가설 2개 → test F1 1.000 → 외부 검증 → 한계

**분석 흐름도 (1쪽, 1장 앞)**: 스토리 8단계를 한 장 그림으로

**1장 데이터 이해 및 진단 [15] — 스토리 1·2·3**
- 1.1 주제 선정: 펌프 고장 시 2~3일 정지(가이드북), 5개 과제 중 ③을 고른 이유
- 1.2 설비 구조
  - 파인블랭킹 3힘, 1000톤 유압, 기어펌프와 기어 마모 메커니즘
  - 수직 모터-펌프 유닛과 센서 위치(가이드북 그림 3)
- 1.3 변수 정의: 5개 열, 전류는 교류 순시값, 10Hz, 기록 최대 50행, 정상 600(중복 제거 599)·이상 21기록
- 1.4 **데이터 결함 진단표** (cases 수치)
  - 측정 시간 43%, 50행 단위로 끊김
  - 저장 형식 누수: 규칙 F1 0.992 (test 0.994)
  - 화요일 자정 vs 일요일 오전 교락
  - 고장 1건(3분)
  - 전류 겉보기 주파수 0.60→0.19 Hz, 평균 흐름 −185→+272
  - 라벨이 파일 단위, 중복 1행
- 1.5 전처리·검증 전략: matched 정밀도, 기록 분할, train/valid/test 표, LOO 보정, 잠금 절차

**2장 AI 예측모델 [40] — 스토리 4·5·6·7**
- 2.1 구조 기반 고장 case 분류: FM1~6과 센서별 관측 가능성 표
  - **현재 데이터로 불가능한 분석 명시**: 고장 직전 패턴(5일 공백), 서서히 진행되는 열화, 고장 모드 구분
  - 그래서 "정상과 다른 상태의 조기 경보"로 문제를 다시 정의한다
- 2.2 사고 전 패턴 확인: 기록(case) 특징 AUROC(전류 R² 1.000 등), 정상 날 전조 없음, 이상 3분 안의 변화
- 2.3 가설 등록 (valid 근거): H1~H4 표
- 2.4 모델 비교 (같은 test, 실시간·기록 단위): 베이스라인 5종, 예준 v1·v2·v3 계열, 최종
- 2.5 최종 모델과 선정 근거
  - v2 3성분 + H1 + H2. valid 1위, H1·H2 사전 등록 가설 test 채택
  - 동률 규칙에 따른 대안(v2+H1, test B 0.9954)을 1줄로 공개
  - α 1/3/5% 민감도, 이상 확률 보정(예준 Brier·ECE)
- 2.6 검증·일반화 (스토리 8): E1 POD·손실표, E2 SKAB 전후 F1, E3 UCI 인용

**3장 영향요인 및 오류분석 [15]**
- 3.1 주요 변수·상호작용: 전류 파형 R², 진동 lag-1, 상·하부 역위상, 하부진동–전류 결합
- 3.2 FN 집중 조건: 기록 위치 0~1, 진동이 작은 이상 기록(valid·test 모두)
- 3.3 FP 집중 조건: 고부하 정상의 크기 단독 초과(prefix R² 0.995~0.998)
- 3.4 가설별 효과 분해(ablation)
- 3.5 한계(짧게): 고장 1건, 교락, α 5%에서 저하, 외부 일반화 결과

**4장 현장 활용 [10]**
- 2단계 경보, 사건 단위 알림, 근거 → 점검 조치표(예준 v2)
- H1을 경보 래치·해제 운영 규칙으로 설명
- 수집 개선 권고: 연속 수집, 동기 샘플링, 온도·압력, 형식 통일

**5장 창의성 [10]**: 결함 우선 진단, 제조 구조 지식, 가설 사전 등록·잠금 절차, conformal 보정·확률 보정, 외부 검증. 각 항목을 2·3장 수치와 연결한다

**6장 코드·재현성 [10]**: 실행 명령 3줄(01→02→03), 잠금 해시, 재현 확인, 결정성(2회 동일). 코드 zip 구성안
