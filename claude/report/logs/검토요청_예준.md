## 직접 검토 (본인 판단으로)

6. 직접 읽고 고치고 싶은 곳 3군데: 쪽 번호 / 문제 / 고칠 문장
  6.1. 한글파일에 빨간색으로 표시
7. 심사위원이라면 가장 먼저 물을 질문 1개와 우리 답
  7.1. 근데 모델 차이를 두고 어차피 우리 최종 모델에서 R1을 사용하는데 이게 없는 값으로 비교를 한다고 한들 그게 의미가 있는 값인건가?
    - 답: 의미 있다. 다만 최종 모델의 성능이 아니라, R1이 대신해 줄 수 없는 부분(사건의 첫 경보와 정상 오경보)을 비교하는 값으로 읽어야 한다. 보고서가 "우열은 R1 없는 값으로 읽는다"고 쓴 이유다(p1, p2).
      - R1은 켜진 경보를 이어 갈 뿐 첫 경보를 만들지 못하고, 앞단 모델의 오경보도 번지게 한다(p18). 그래서 최종 모델에서도 사건이 시작되는 기록은 앞단 v2가 혼자 잡아야 한다. 이상 파일 첫 기록의 첫 경보(A 0.1초·B 0.0초)도 이어받을 직전 기록이 없어 v2가 낸 것이다(p21).
      - 반대로 R1을 붙인 test 값으로는 모델을 가를 수 없다. test 이상 11기록은 valid에서 이미 확인된 한 사건의 뒷부분이다. valid→test를 한 흐름으로 돌리고 전류 파형도 끝까지 정상으로 돌아오지 않아, R1이 test 첫 행부터 경보를 이어받는다(p18, p21). 그래서 단독으로는 0.133/0.094인 IsolationForest도 R1을 붙이면 1.000/1.000이다(p17, p19).
      - R1을 붙인 비교도 R1이 채워 주지 못하는 곳에서는 했고, 거기서는 차이가 남는다(p18~19 † 표). 사건 앞부분이 든 valid에서 IsolationForest+R1 0.426 대 v2+R1 0.997, test 기록부터 따로 돌린 흐름에서 0.612/0.609 대 1.000/0.995다. B test 오경보는 R1을 붙이면 5NN 5→12행, MLP 오토인코더 2→9행으로 늘고 v2는 3행 그대로다.
      - 한계: R1을 붙이면 max|z|·v1도 v2와 거의 같다(valid 0.996, p18~19). 최종 모델 기준으로는 v2의 파형·동역학 성분이 더하는 몫이 이 데이터로 보이지 않고, 그 몫은 R1 없는 미탐(v1 57/50행 → v2 22/16행, p17)과 R2의 파형 판정에 있다(p19).
  7.2. 규칙(R)을 붙일수록 성능이 좋아지는데 그럼 많은 규칙을 붙일수록 더 성능이 좋아지는거 아닌가? 그리고 R을 2개만 붙인 이유가 있는지?
    - 답: 아니다. 이 데이터에서 규칙을 붙일수록 점수가 오른 것은 규칙을 이 데이터에서 본 오류에 맞춰 만들었기 때문이고, 규칙마다 다른 곳에 비용이 생긴다. 2개인 것은 v2의 오류가 두 종류였기 때문이고, valid로 고르는 잠금 규칙이 고른 것도 R1까지다.
      - 점수가 오른 이유: R1·R2와 그 상수는 전체 데이터를 열람한 초기 탐색에서 착안했다(p15). 이미 본 오류를 고치는 규칙은 같은 데이터에서 점수를 당연히 올린다. 이 데이터는 쉽게 갈리는 편이라, 이상 자료를 본 뒤 만든 단순 규칙(최댓값 세 개만 학습)도 행 F1 0.890·0.900이 나왔다(p17). 그래서 R2가 test에서 줄인 오경보 3행도 착안 때 본 행이라 표본 밖 근거가 없다고 적었다(p21).
      - 규칙은 맞바꿈이다. R1은 미탐을 없애지만 오경보를 번지게 한다(α 5%에서 기록 446의 경보 2행이 다음 기록 447의 앞 7행으로 번짐, p26~27). R2는 고부하 오경보를 줄이지만 진동 단독 고장의 탐지율을 최대 23.7%p 낮춘다(p24). 남은 미탐(진동이 작은 기록 3·19·20)을 잡으려고 "진동이 너무 작음" 규칙을 더하면, 학습에 없던 정숙 구간 기록 A 28·B 27개가 오경보가 된다(p28).
      - 더 고칠 오류도 없다. test는 이미 미탐·오경보 0행이다. valid에 남은 2행은 사건의 첫 표본(이어받을 직전 기록이 없음)과 파형을 판단할 8행 전의 오경보라(p27), 이걸 없애는 규칙은 한 행에 맞춘 규칙이 된다.
      - 2개인 이유: v2의 오류는 기록 시작 직후 미탐(위치 0~1에 A 14·B 12행)과 고부하 정상의 크기 성분 단독 오경보, 두 종류였다(p27). 각각에 물리 근거가 있는 규칙을 하나씩 붙였다. R1은 "고장은 수 초짜리 수집 공백 사이에 사라지지 않는다"(경보 관리의 OFF-delay·래치), R2는 "두 물리 채널이 함께 이상을 가리킬 때만 크기 경보를 낸다"는 규칙이다(p14). 후보는 하나 더 있었다. v3 부하 조건부 진동 성분도 test 전에 판정 기준을 잠갔지만 넘지 못했다(A 0.965→0.968, B 0.970→0.955, p17~18).
      - 잠금 규칙도 규칙이 적은 쪽을 고른다. "valid 차이 0.002 이내면 더 단순한 모델"이라 R2를 뺀 v2+R1이 선택이었다(valid 0.997 대 0.998, 복잡도 4 대 5, p20). R2는 과업 ②(정상 운전변화 오경보 억제)를 위해 넣은 설계 판단이다(p21).
  7.3. 사후 비교를 넣은 이유? 테스트 결과를 보고 한거면 어떤 걸 가져다놔도 1.000이 나오는게 당연한거 아닌가?
    - 답: test 1.000이 v2 덕인지 R1 덕인지를 스스로 확인하려고 넣었다. "아무거나 가져다 놔도 1.000"이라는 관찰은 맞고, 그게 사후 비교가 드러낸 결과다. 다만 원인은 test를 보고 해서가 아니라 데이터 구조이고, 그래서 보고서는 test 1.000을 모델 우열의 근거로 쓰지 않는다.
      - 1.000이 나오는 이유: test 이상 11기록은 60초 안 간격으로 이어진 한 사건의 뒷부분이고, 전류 파형이 끝까지 정상으로 돌아오지 않는다. 그래서 R1(또는 기록 사이 상태를 이어 가는 CUSUM·EWMA)이 test 첫 행부터 경보를 이어받고, 앞단 모델과 상관없이 나머지 행이 다 맞는다(p18, p21). 보고서도 test 1.000을 "이 사건에서 정상 오경보가 없고 경보가 사건 끝까지 유지됐다"로 읽으라고 적었다(p18).
      - test에 맞춘 값도 아니다. † 행도 다른 모델과 같은 분할·같은 valid 보정(α 1%)으로 채점했고(p16), CUSUM 상수는 valid로 골랐으며(p18), R1 상수(60초·2행·R² 기준)는 test 전에 정한 값 그대로다(p15). test를 보기 전에 돌렸어도 같은 숫자가 나온다. †는 "test 채점 뒤에 추가해 선택·잠금·최종 선정에 쓰지 않았다"는 표시다(p16).
      - 넣은 이유는 두 가지다. ① 심사위원이 "1.000은 R1 덕 아니냐"고 묻기 전에 우리가 먼저 보이려고(IsolationForest+R1 1.000/1.000, p18~19). ② 공정 표준 기법(PCA 관리도·CUSUM·EWMA)과 견줘 규칙의 위치를 확인하려고(p16). CUSUM·EWMA도 기록 사이 상태를 이어 가면 R1 수준이 되므로 이득의 핵심은 "수집 공백을 넘는 기억"이고, 차이는 경보 해제에서 났다(R1 0.7초, CUSUM 11.4~12.2분, p18, p21).
      - 1.000이 아닌 곳에서는 모델 차이가 남는다. 상태를 잇지 않으면 PCA 관리도 0.557/0.908, 기록마다 0으로 되돌린 CUSUM 0.978/0.975다(p17~18). R1을 붙여도 사건 앞부분이 든 valid(IsolationForest+R1 0.426), test 기록부터 따로 돌린 흐름(IsolationForest+R1 0.612/0.609, LSTM 오토인코더+R1 0.924/0.924), 정상 오경보(5NN+R1 B test 12행)에서는 갈린다(p18~19).
      - test를 보고 정해서 생긴 약점은 사후 비교가 아니라 최종 모델 쪽에 있다. R1·R2는 전체 데이터를 보고 착안했고, R2를 넣은 최종 모델은 test를 확인한 뒤 정했다(p15, p20~21). 그래서 보고서는 test 점수를 "성능 추정치가 아닌 확인값"이라고 적었다(p10).
