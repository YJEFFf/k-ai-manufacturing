# 결과보고서 작성 계획 v4 — ③ 프레스 유압펌프 이상탐지 (마감 2026-10-08 23:59)

## 0. 확정 사항
- 범위: 결과보고서 hwpx·PDF, 6장이 요구하는 코드 zip·test 예측 파일. 발표자료는 10/7 시작

- **사용자 결정: 최종 모델 = v2+R1+R2, test 행 단위 F1 1.000 (A·B, α 1%)**
  - 서사: "작은 데이터에서 다 맞았지만 의심했다 → 예준 v3 방식으로 검증했다"

### 실제 경위 (보고서 서술의 기준)
1. 초기 탐색(cases/)에서 전체 데이터를 열람했다. 예준 v2의 오답을 분석해 R1·R2를 착안했고, 규칙 상수도 이때 정했다
   - 60초·2행: 예준 v2 사건·2단계 규칙 값
   - R² 0.5% 분위·8행: 정상 학습 자료 기준
2. train/valid/test(tvt/)로 다시 돌렸다
   - valid는 문턱 보정(LOO), 모델 선택, test 판정 기준 기록에 썼다
   - 선택 결과는 해시로 잠갔고, 그 선택을 바꾸지 않고 test를 채점했다(재실행 결과 동일)
3. valid 실시간 F1은 3개 모델이 공동 1위(0.9982)였다: v2+R1+R2, v2+C1d1+R1+R2, v2+C2d1+R1+R2
   - 잠금 동률 규칙(0.002 이내 → 단순)이 고른 모델: v2+R1. test A 1.000 · B 0.9954
   - v2+R1과 v2+R1+R2의 valid 차이는 A 오경보 1행이다
4. 최종 모델(v2+R1+R2)은 test 결과(1.000 대 0.9954)를 본 뒤 정했다. R2가 test에서 없앤 B 오경보 3행은 착안 때 본 행과 같다
5. 기록 단위 트랙의 잠금 선택(v3 B3k10)은 test에서 0.889/0.954로 내려갔다

### 필수 공개 문장 (원문 고정, 윤문 대상에서 제외, 문자열 검사)
- P1 "규칙 R1·R2와 그 상수는 전체 데이터를 열람한 초기 탐색에서 착안해 정했다."
- P2 "이후 시간순 train/valid/test로 다시 평가했으며, valid에서 선택 결과를 해시로 잠근 뒤 그 선택을 바꾸지 않고 test를 채점했다(재실행 결과 동일)."
- P3 "잠금 규칙이 고른 모델은 v2+R1(test F1 A 1.000·B 0.9954)이며, 최종 모델 v2+R1+R2는 test 결과를 확인한 뒤 정했다."
- P4 "R2가 test에서 줄인 오경보 3행은 초기 탐색에서 이미 본 행이다."
- P5 "이상 데이터는 약 3분(2분 46초)짜리 단일 고장 사건이라, 1.000은 이 사건에 대한 결과다."

## 2. 의심 → 실험 → 판정 기준 (실행 전 고정, `code/press/tvt/04_validation.py`)
- 공통 설정
  - 대상: v2, v2+R1, v2+R1+R2(최종), v3 B1
  - α 1%, A·B를 따로 보고하고 평균도 낸다
  - V 실험은 test 채점 **이후에** 같은 test 정상 기록을 써서 한다(2.6에 명시)
  - 주입은 예준 `core.Generator`를 쓴다(seed 11·29·47, seed 3개 평균)
    - **판정 강도는 `design_v1.json`의 selection 값으로 고정한다**: D1 대역 잡음 0.5·1, D2 감쇠 충격 2·4, D3 전류 잔차 0.5·1
    - 판정은 강도마다·대상 채널마다 따로 한다
    - 나머지 격자 강도는 기술만 한다. 강도 0은 기준선 오경보로 보고한다
  - POD는 기록 단위다. **주입 시작 이후의 경보만** 센다. 보조 지표로 첫 경보 지연과 8행 이후 행 재현율을 함께 보고한다
  - R² 기준은 각 분할의 train만으로 다시 계산한다
  - **판정 집계 규칙**: 판정 칸(강도·채널·분할 A/B)이 하나라도 기준을 넘으면 그 실험의 적용 조건 문단을 쓴다. "−5%p 이내" 같은 통과 판정은 A·B 모두 충족해야 한다
  - V5 ①②의 판정 대상은 최종 모델이다. 지표는 1단계 경보(경보 1행 이상) 기록률이고, 흔들림 0 ms·이동 0 기준선을 함께 보고한다
  - "8행 미만 정상 기록 수" 같은 보조 수치는 tvt 분할 정의로 스크립트에서 산출해 facts.csv에 연결한다

| 의심 | 실험 | 판정 기준 (고정) |
|---|---|---|
| D1 모델이 고장이 아니라 파일·수집 조건 차이를 잡는 것 아닌가 | **V5 교락 대조** (예준 스트레스 재사용) ① 정상 test 전류를 +81.4(이상 기록 \|평균\| 중앙값)·+272.4(최댓값) 옮김 ② 표본화 시각 흔들림 ③ 이상 기록 평균 제거 | ①② 정상 경보 기록률 ≤ 2α면 "둔감", 넘으면 "수집 조건에 민감 → 현장 재보정 필요"(v2에서 이미 민감했으므로 이 문단을 미리 작성). ② **판정 셀은 0.1 ms·60.6 Hz 가설로 고정**하고, 0.05·0.2·0.5·2.4 ms는 기술만 한다. ③ 이상 탐지 ≥ 20/21이면 "수준 차이에는 의존하지 않음"으로 판정한다. 단 "파형·시각 교락은 배제하지 못함"을 함께 적는다 |
| D2′ 다른 모양의 이상에도 반응하나 ("우연히 맞았나"는 주입으로 검증할 수 없어 '검증하지 못한 것'으로 옮김) | **V1 단일 기록 주입 POD**: 전류 잔차(D3) 계열만 판정한다. 진동 계열은 V1b에서 따로 판정 | selection 강도에서 최종 모델 POD가 v2 대비 −5%p 이내면 "규칙이 탐지를 해치지 않음" |
| D3 R2가 진동이 먼저 나타나는 고장(베어링·커플링)을 숨기지 않나 | **V1b 진동 단독 주입** (D1·D2, 채널별) | 강도·채널별 POD 손실(최종 대 v2+R1) ≤ 5%p면 비용 허용. 넘으면 "R2는 전류 파형 이상을 동반하는 고장(가이드북: 기어 마모 → 출력 유압 약화)에만 적용" 문단을 쓴다(넘을 가능성이 높아 미리 작성). 8행 이후 행 재현율도 함께 보고한다 |
| D4 R1은 이 사건 구조 덕분 아닌가 | **V1a R1 동작 확인**(이어지는 기록 2~3개 주입, 기술만, 일반화 판정 안 함) + **V1a′ R1 비용**: 기록 k에만 주입하고 k+1부터는 정상 | V1a′ 분모 = 래치가 걸린 경우(기록 k의 경보 ≥ 2행). 판정: 해제 위치 ≤ 8행인 비율 ≥ 90%면 "래치 비용 제한". 사슬 길이(기록 수·행 수)를 보고하고, 8행 미만 기록(정상 600개 중 50개, 해제 불가)으로 이어진 경우는 따로 센다 |
| D5 줄어드는 고장은 못 잡지 않나 | **V2 손실**: 진동 진폭·전류 0.75/0.5/0.25/0배 | 기술. 0.5배 POD를 3장 "감소형 탐지 한계"에 쓴다 |
| D6 분할을 바꾸면 무너지지 않나 | **V3 분할 강건성**: 예준 P2 틀(분 단위) + 시간순 5창 | 기술. 모든 분할에서 이상 21/21과 정상 기록 오경보율 ≤ 2α인지 보고한다. 이 실험은 정상 쪽만 새로 보고, 같은 이상 21기록을 쓴다는 점도 밝힌다 |
| D7 경보 기준을 느슨하게 하면 | **V0** (이미 산출) | 최종 모델 B α3% 오경보 1행·α5% 9행(F1 0.9985·0.986), v2+R1은 21·32행. 운영 α 1% 고정 |
| D8 다른 설비에서도 되나 | 외부 데이터 | SKAB 비적용 사유 1단락. UCI는 `press_supplement/e2_uci_metrics.csv` local 행(AUROC 0.43~0.55, v2 구조)만 인용 |
- 검증하지 못한 것 (2.6 표에 공개)
  - 이상 사건이 하나뿐이라 우연히 맞았을 가능성(실제 다른 고장 사건이 없음)
  - 고장 직전 패턴
  - 다른 날·다른 설비에서의 성능
  - 이상 파일의 파형 붕괴가 고장 때문인지 계측 때문인지(V5는 수준 이동·흔들림만 일부 배제)
  - 주입 신호는 관측된 이상(1Hz 이하 저주파형)과 모양이 다르다
- 기존 결과는 비교로 인용한다: `press_supplement` E1(v1/v2 주입, 9/26), `representative_target_pod.csv`
- Brier·ECE: 최종 모델로 다시 계산하지 않는다. 규칙은 점수가 아니라 경보를 바꾸기 때문이다. 쓴다면 "v2 점수 기준"으로 표기한다. 첫 경보 지연은 최종 모델로 계산한다

## 3. 장별 내용 (스토리라인)
**표지 내용요약 (6줄)**
- 결함 진단 → 문제 재정의 → 규칙 R1·R2 → **test F1 1.000 (행 단위, α 1%, 단일 고장 사건)** → 의심과 검증(V1~V5) → 적용 조건
- 프로젝트명(안): "데이터 결함 진단과 고장 지속성 규칙에 기반한 프레스 유압펌프 실시간 이상 경보"

**1장 데이터 이해 및 진단 [15]**
- 1.1 주제 선정 / 1.2 설비 구조(파인블랭킹·기어펌프·센서 위치) / 1.3 변수 정의
- 1.4 결함 진단표 (정의 고정, 수치는 스크립트 출력에서)
  - 측정 43%, 50행 단위로 끊김
  - 형식 누수: 자릿수>6 규칙 F1 0.992 (test 0.994)
  - 요일·시간대 교락, 고장 1건
  - 전류 겉보기 주파수: 그리드 사인 적합 정상 0.60 / 이상 구간 중앙 0.22 (`outputs/alias/segment_sine_fit.csv`)
  - 기록 평균 범위 −184.8 ~ +272.4 (스크립트로 산출)
  - 라벨 파일 단위, 중복 1행
- 1.5 전처리·검증 전략(train/valid/test, LOO, 잠금), 흐름도

**2장 AI 예측모델 [40]**
- 2.1 구조 기반 고장 case 분류(FM1~6 × 관측 가능성), 현재 데이터로 불가능한 분석, 문제 재정의
- 2.2 사고 전 패턴 확인: 케이스 특징 AUROC, 정상 날 전조 없음
- 2.3 규칙 R1·R2와 경위(P1·P2)
- 2.4 같은 test 비교표: 베이스라인 5종, 예준 v1·v2·v3, v2+R1(잠금 선택), v2+R1+R2(최종). 실시간·기록 단위 모두
- 2.5 최종 모델 선정(P3·P4), α 민감도, 첫 경보 지연
- 2.6 **"다 맞았지만 의심했다"**: 의심 D1~D8 → 실험 → 결과, 그리고 검증한 것 / 검증하지 못한 것 2열 표(P5)

**3장 영향요인 및 오류분석 [15]**
- 3.1 주요 변수·상호작용
- 3.2 실패 조건 (출처 명시)
  - v2 FN: 기록 위치 0~1
  - v2 FP: 고부하에서 크기 성분 단독
  - 최종 모델 α 3·5% 오경보
  - V1b·V2에서 놓친 주입
  - B3k10의 valid→test 하락
- 3.3 규칙별 효과 분해 / 3.4 적용 조건

**4장 현장 활용 [10]**
- 2단계 경보·사건 알림·조치표
- R1 = 경보 래치·해제
- R2 = 크기 단독·파형 정상이면 **경보 보류(경보 없음, 기록만 남김)**. 채점한 동작과 같다
- 수집 개선 권고

**5장 창의성 [10]**: 결함 우선 진단, 구조 지식, 자기 의심 검증 체계(V1~V5), 잠금 해시 절차. 각각 2·3장 수치와 연결한다

**6장 코드·재현성 [10]**: 실행 명령, R=H 대응표, zip 구성, 새 환경 실행 결과

## 7. ADR
- **결정**: 최종 v2+R1+R2, test F1 1.000을 범위를 한정해 결론으로 둔다. 경위는 P1~P5로 공개한다. 의심 D1~D8을 사전 고정 기준으로 검증한다
- **동인**: 수상 가능성(사용자 판단), 반박 내성, 일정
- **대안**: 잠금 선택 v2+R1을 최종(검토자 권고, 비교표로 반영), 경위 생략(기각), SKAB 이식(기각: 다른 규칙이 됨)
- **이유**: 수치는 실제 값이고, 경위를 공개하니 사실과 다른 서술이 없다. 의심을 먼저 꺼내 검증해 반박을 흡수한다
- **결과**: "잠금 절차"는 창의성 근거로서 약해진다. 대신 "자기 의심 검증"이 그 자리를 채운다. V5·V1b 결과에 따라 적용 조건 문단이 길어질 수 있다
- **후속**: 팀장 검토(10/5), 발표자료(10/7), zip 동결
